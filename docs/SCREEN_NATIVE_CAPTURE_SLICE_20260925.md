# Screen 原生单次截图切片

日期：2026-09-25。范围：V2 `screen/` 领域的图片原件和一次显式截图请求；本切片没有改动现役 V1 或 Screen 提供方。

`ScreenCaptureService` 通过注入的 `ScreenDevicePort` 取得指定设备的一张图片。请求 ID、原 scope、设备、角色、可信主体和受众绑定同一持久操作；重复请求只能读取已发布的原件，不会再次触发设备。首次无权请求不预留操作；预留后设备 I/O 前再比较安装、角色、同意、身份绑定和授权版本，发布时重新复核。设备结果不明、取消或设备端口漏做调用前复核时保留未知结果，不自动补采。

原始 PNG/JPEG/WebP 字节保存于 V2 独立数据根的内容寻址目录，限制大小、尺寸及解码格式。发布记录将图片哈希、窗口标题、实际覆盖、缺口、采样时间和接收时间绑定 Source、Asset 与 Capture；读取时复核现行来源治理、受众和原始字节。相同图片内容不合并不同请求的逻辑截图。窗口标题和客户端时间只按其来源记录，不推断用户已阅读或屏幕外状态。

验证使用合成图片、临时 V2 数据根和替身设备，`python -X utf8 -m unittest tests.test_screen_capture tests.test_screen_originals tests.test_screen_pipeline -q` 共 32 项通过，覆盖重启/重放、初始拒绝、采集中撤权、设备回执异常、取消、原件损坏或撤权及后续解释链。没有真实设备、AstrBot 宿主、视觉模型或 QQ 调用。

下一步由 Screen 提供方提供明确的设备归属和单次采集端口，宿主把当前已安装提供方、可信账号/角色、设备绑定及请求来源装配到本服务；然后接 V2 模型网关和现有 `ScreenProcessingPipeline`，用受控设备完成“截图 -> 原件 -> 解释 -> 采用”验收。不能启动旧插件自带的自动观察、日记或发送循环，也不能把提供方的全局 latest 缓存当作 V2 用户原件。
