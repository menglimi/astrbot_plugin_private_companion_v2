# 已保存角色映射在启动时恢复

2026-10-06。

运行日志连续记录 `load_existing` 返回 `host_binding_changed`。只读对照 V2 插件配置和既有 V2 运行档发现：配置比已保存映射多了一个自动生成的 `legacy-*` 私聊目标；群目标与人格映射相同。

旧单目标兼容迁移每次启动都会读取 `target`，即使 `staging.enabled` 已关闭、共享映射已经建立，也重新添加旧目标。小屋保存映射会改回按账号管理的通配目标；下一次启动又添加旧目标，从而无法加载角色运行数据。问题不需要重建角色或记忆。

迁移现在仅在旧单目标仍启用或共享映射尚未建立时导入旧目标。已建立的共享映射以已保存配置为准，禁用的旧段只保留兼容信息。

对已经遭到重复迁移的配置，启动只恢复这一种情况：旧段已禁用；多出的目标 ID、平台、账号和参与者与旧段的自动生成规则一致；同一 Bot 已有覆盖它的私聊通配目标；移除这一个目标后，完整绑定契约与持久运行档完全一致。修复通过宿主配置保存接口持久化，并重建当前路由，不改写既有运行档、身份归属或授权。其他账号、人格、群目标或角色归属变化仍按真实配置冲突报告。
