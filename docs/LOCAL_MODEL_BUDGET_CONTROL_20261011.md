# 插件本地预算开关修复

## 原因

`model_budget_exhausted` 来自 V2 自己的每日准入账本，不表示 AstrBot 或模型服务商余额不足。旧实现无条件启用硬预算；全局软限额关闭后，角色上保存的旧开启值仍可覆盖关闭设置。配置继承还把“在当前角色显式保存”误当作“存在已保存的值”，导致全局值被宿主默认值替代，或部分覆盖时恢复不相关的默认值。

## 行为

- 新增宿主运行配置 `runtime.enable_daily_model_hard_limit`，默认 `false`。仅有旧 Token、费用上限不代表开启硬预算，必须显式打开开关。
- 硬预算关闭后不做 Token、费用准入拦截；继续记录调用、实际用量、待确认预留和账户归属。已有预算等待不再阻断新工作。
- 软限额默认关闭。有效开关是全局开启且角色允许；旧角色的开启值不能越过全局关闭。阈值和开关各自继承已保存值或宿主默认值。
- 陪伴小屋预算编辑器默认读写全局设置，避免在当前会话所属角色上保存一个无法开启全局预算的局部开关。
- 普通回复继续使用 AstrBot 主链，排除在插件硬预算和软限额之外。
- 诊断 API 明确返回 `hard_limit_enabled`；关闭时 `remaining_tokens` 为 `null`。页面显示本地限制已关闭，保留用量与预留详情，不按关闭的上限产生接近耗尽警告。
- 日账本和历史调用不清空。未知调用不释放为零、不自动重放；新工作使用新任务身份。
- 保存运行档能往返持久化关闭开关；旧运行档的文档形状和指纹保持兼容。开关不改变每日账户策略指纹，避免仅切换开关就要求迁移旧账本。

## 验证

从新构建交付包验证预算准入、全局关闭与角色覆盖、继承和部分覆盖、关闭后实际用量统计、历史未知调用保留、保存档指纹兼容及诊断页面。宿主检查使用 AstrBot 自带 Python、临时数据根，并覆盖加载、停机和路由注销。验收结果写入本次外部产物目录。
