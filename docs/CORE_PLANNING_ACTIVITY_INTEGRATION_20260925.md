# 原生规划与真实活动联动（2026-09-25）

本批把角色规划、实际活动经历和主动联系候选接入同一个 V2 宿主周期。规划写入日历；经历与主动候选只由原领域已经提交的活动或书写回执产生。三类记录保留各自的来源、版本和用途，不能互相代替。

## 已接通的运行链

- `agenda/planning.py` 在绑定的原角色窗口中按本地日期安排每日小步，按周检查长期节点，并在已接受日程临近时细化指定期次。启用需要 `planning_enabled`、`calendar_enabled`、日历写入权限和 `calendar.plan` 后台模型配置；默认关闭。输入来自当前可访问的日历、目标、记忆及已完成会话，按字符和来源数限制。模型只能提议条目与细节；身份、来源、操作编号和实际日历写入由宿主确定。重复或无效条目不会作为新计划保存。
- `memory/activity_ingestion.py` 从原活动与私人书写操作读取完成回执，按宿主绑定窗口分页写入经历记忆。阅读只记录实际已读范围；日记和梦境仅保存书写导航，正文仍由日记领域管理。经历在普通对话中可按相关性召回，并在读取时重验原回执、来源和权限。已计划、开始、暂停、取消或单纯过时均不等于完成。
- `proactive/events.py` 从原角色活动历史产生阅读完成和睡眠结束候选，继续通过原主动联系任务决定发送或跳过。阅读材料限定为实际已读片段及主观感想；睡眠只证明该段睡眠结束。候选遵守用途开关、联系额度、空闲/间隔及事件时效，同一已读区间和既有任务不会在重启后重复生成。
- `host/application.py` 在统一后台驱动中轮转以上生产者，停机和故障时关闭相应 worker 与来源 owner。主动活动来源保存原操作回执用于每次读取复核，但内部回执字段不进入模型材料；来源 owner 关闭或原回执变成未知后，旧来源不可继续读取。

规划建议、日历安排、实际执行与主动发送各有独立回执。来源撤回、角色或授权变化后，派生经历和待发内容沿现有来源治理重新核验；已发生的真实发送回执不会被伪造为未发送。

## 验证与边界

使用 AstrBot 自带 Python、临时 `ASTRBOT_ROOT`、独立 V2 数据库及合成模型/平台，联合运行 `test_calendar_planning`、`test_role_activity_history`、`test_memory_activity_ingestion`、`test_proactive_activity_events`，并覆盖多目标启动及单目标预览、热重载注销三项 SDK 宿主用例：**67 项通过**。其中活动历史迁移用例改为核对固定的 V22→V23 回执，不再把后续新增的当前 schema 版本误作该步迁移目标。

本批不代表全天自动活动执行已完成。自动成长/目标进度结算、天气预警与资讯生产、日记/梦境主动分享，以及其他生活事件的主动候选仍待原生接入。真实模型表达、QQ 投递及长期日常运行未在这组合成测试中验收；已有 V2.0 ZIP 未因本批源码增量更新。V1 用户数据没有被读取或迁移。

下一片优先让实际活动回执生成可审阅的成长/目标进展提案，再依据已采用的进展调整后续日程。后续接天气、资讯和更多生活事件时，沿本批的原来源与回执合同增加生产者。
