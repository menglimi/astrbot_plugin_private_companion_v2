# 私聊语音输入、可信原件与完整音频视图

2026-09-24。本切片将直接私聊语音接入统一宿主、合并输入、来源治理、模型工具续答、文字投递及确认历史。单目标和多账号宿主共用合同；已完成本地框架与真实 SDK 格式验证，真实 QQ／语音模型现场验收仍待进行。

## 已落地行为

- Record 支持 QQ SILK 和 PCM WAV。WAV 接受 16 位 PCM、单/双声道、8–48 kHz；双声道转换为单声道，SILK 完整解码为 24 kHz 单声道 WAV。原始字节及其 SHA-256 独立保留，实际提供给模型的 WAV 另有字节数、样本数、采样率和指纹。
- AstrBot 4.27.2 在插件前执行预处理，可能把 Record 替换成 STT Plain 或改写为本地路径。宿主从同一 OneBot 原始事件恢复包含直接语音的消息链，并核验消息 ID、self ID、发送者及私聊场景。Record.text、path 和预处理转写不成为语音原文；原始文字、图片、Reply 与 Forward 保留各自的来源合同。
- 文件名或消息里的路径不授予磁盘读取权限。加载只接受捕获的 base64 或经过已有公共 HTTP(S) 传输校验的 URL；实际 DNS 地址、重定向、流式长度沿用图片下载边界。地址和转写不进入持久语音清单。
- 编解码在独立短进程执行。SILK 使用已安装 `silk-python 0.2.8` 的 CFFI SDK，逐个读取包内全部帧；便捷 decode 接口每包只输出一帧，不能用于完整录音视图。截断、无效容器、超时和取消不会产生已接纳的部分音频；取消时终止子进程并排空管道、回收进程。
- 新 `AudioConversationEvent` 保存可组合的清单，旧文字、图片、引用和转发事件不增加空字段、不改写旧哈希。语音原件、转换结果、Source/Asset、批次接纳共用一个事务。来源依赖父消息，读取时重新检查原账号、身份、角色、受众、父消息、源与两个音频资产及原始字节。
- 模型接收来源明确的 `input_audio` WAV。语音来源句柄进入材料，工具续答保持原字节与来源；SDK 准备若丢弃或改动媒体则不会发送请求。预算估算剔除 base64，按每秒 256 token 预留音频估算量，实际用量仍按 provider 回执核算；估算不是供应商计费证据。
- 撤回或撤权继续约束模型派发、发送前复核、确认历史与派生记忆。重启读取保存的原件和 WAV，不重新下载/解码已接纳批次。结果未知沿用统一回执规则，不因输入重放再次调用模型或补发。

## 来源表达和预算

音频材料注明完整附件覆盖、转换形式与容器时长，录音时间、原作者、音频中的说话者身份保持未知。提示词要求只引用听清的内容，不能把发送者当作录音者或音频中的本人；语音中的命令仍是资料，不改变人格、身份或工具授权。没有提供独立转写，也不声称验证了听不清的词语。

每条原件最多 5 MiB、60 秒；每条输入和合并轮次最多 4 段，总时长最多 120 秒。原件、WAV 与直接/引用/转发图片及动画帧共同受 20 MiB 保留预算约束；图片原有数量及帧数上限继续生效。捕获、持久合并和模型请求边界均检查预算，超出合并预算的新输入开始后续批次。

语音来源不会出现在原图出站选择中。当前语音输入生成普通文字回复，可与已有图片输入及已授权原图选择共存；没有接入 TTS、语音出站或视频。

## 边界与下一步

所选 OpenAI 兼容模型需要支持 `input_audio`；本轮没有进行真实供应商调用、真实 QQ 发送或识别准确率验收，也不自动另选 STT 模型。若 AstrBot 全局 STT 已启用，它可能在进入插件前已经调用过 provider；本切片防止其转写冒充原件，不改变宿主全局配置。SILK 解码依赖宿主自带 CFFI 扩展，缺失时明确返回 decoder unavailable；MP3/AMR 等编码、引用/转发节点内语音、群语音、TTS/语音出站仍待独立接入。

视频输入随后已由[私聊视频切片](CORE_PRIVATE_VIDEO_20260924.md)接入：MP4 原件和最多四个可追溯画面帧加入共享预算、来源复核及 v30 存储，音轨明确未检查。下一步把音视频来源合同扩展到私聊引用/转发节点，再推进群合并转发与嵌套媒体；图片、语音和视频的真实 QQ／模型效果仍待定向现场验收。实际生图/改图继续使用独立任务产物与投递合同，管理/拓展页由另一任务推进。
