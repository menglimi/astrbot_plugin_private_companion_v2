# 角色状态总览与共享作息展示

日期：2026-09-25

## 目标与边界

把 V2 已实现的角色模拟状态和共享睡眠执行信息接入“陪伴小屋 → 管理与设置 → 角色状态”。页面是已认证 Dashboard 内的只读观察视图，复用既有页面目标目录、状态 API 和授权判断，不执行角色状态修改、QQ 动作或模型调用。

私人会话按页面目录给出的固定 `state_api` 读取当前授权的 target/role；角色或账号切换后重新从相应路径取数。群目标不提供私人角色状态 API，页面明确说明群聊不读取私聊状态。状态数据由宿主组合提供，包括饥饿、健康、心理能量、睡眠感受、生理期当前阶段与描述、有效临时影响、维护排程、角色共享睡眠计划、唯一执行窗口和实际睡眠回执。

日程、模拟值和真实平台执行分开展示：预约或自动睡眠时间不证明角色已完成现实活动，实际睡眠按执行回执呈现；健康值注明是角色模拟感受，不构成医疗判断。未知或不可读字段保留为空状态，不推断缺失值。

## 文件职责

- `pages/陪伴小屋/state-page.js`：页面桥接、授权目标/角色切换、只读状态渲染、短期刷新与撤权后的敏感状态清空。
- `pages/陪伴小屋/state-page.css`：桌面和窄屏布局及键盘焦点样式。
- `astrbot_host/page_api.py`：为页面目录暴露宿主已有的固定状态 API 路径，不接受目标覆盖。
- `companion_v2/role_work/state/management.py` 与 `role_work/life/management.py`：按当前受权上下文组合角色状态、共享睡眠计划及实际身体时钟。
- `tools/check_state_page.cjs`：仅使用合成的页面桥和状态记录进行浏览器验收。

当前小屋以 V2 `pages/陪伴小屋/` 为规范源，`tools/sync_framework_page.py` 构建嵌入工作区和资源清单，`--preview` 可选同步到 Content 插件 `pages/framework-preview-v1/`。状态页 JS/CSS 两处逐字节一致，构建清单检查通过。诊断和原请求追踪的实现与验证见[QQ 展示诊断记录](CORE_QQ_PRESENTATION_DIAGNOSTICS_20260925.md)。

## 验收

使用无头 Chrome 和合成页面 API 验收桌面、390px/320px 窄屏、饥饿/健康/能量/睡眠/生理期/临时状态、共享睡眠时间/时区/时长、执行窗口和回执、相同用户不同 Bot 账号与角色隔离、群聊不暴露私聊状态、XSS 转义、撤权后状态清空以及浏览器异常检查。场景通过；截图写入系统临时目录，不保存在源码树。

页面同时投影 `presentation` 回执：`accepted` 显示平台已受理，`unknown` 显示结果未知且不会自动重发，`failed`/`not_started`/`blocked` 显示未完成原因，`preview` 明确没有 QQ 展示端口。回执面板只反映平台请求结果，不把“已受理”解释成 QQ 客户端仍在显示，也不增加停止输入的猜测性调用。合成场景覆盖自定义短状态和正在输入各一条回执，以及预览目标和撤权清空。

V2 的 `typing_refresh_seconds` 新默认值为 4 秒，仍允许已授权配置在 1–10 秒内显式调整。输入提示由一个原账号/收件人连续任务持有，刷新只发送 `set_input_status(event_type=1)`；不在每次刷新间插入停止请求，未知回执后本轮停止刷新。这个调整只改变新配置的默认节奏，不覆盖已有窗口配置；请求频率降低不等于已经验证客户端闪烁改善。

首次总览交付使用 AstrBot 自带 Python、SDK 和临时导入数据根，运行 `tests.test_role_presence`、`tests.test_role_state_configuration`、`tests.test_role_state_api` 与 `tests.test_page_targets_api`，23 项全部通过。当时使用 `tools/sync_framework_page.py` 发布并检查页面清单，状态页资源与规范源逐字节一致。无数据库 schema 变化、在线重载、真实 QQ/模型调用或 V1 用户数据读取。

随后补齐[QQ 展示诊断与原请求追踪](CORE_QQ_PRESENTATION_DIAGNOSTICS_20260925.md)：显示当前开关/授权/刷新间隔、原会话任务、公开文案和阻塞原因；历史记录带原时间和请求标识，重启读取不重发、不伪造新时间。修复跨窗口身体忙碌误用于原收件人输入续持的问题；该批 35 项定向测试及新增浏览器场景通过。
