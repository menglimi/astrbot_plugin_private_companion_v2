# Reality 手机位置进入 V2 对话（2026-09-30）

## 已补齐的范围

Reality 已有 `reality.snapshot.read` 原生接口，V2 已有提供方发现、任务执行和结果采用。此前缺少公开的能力选择、Bot／人格启用和会话授权入口。Reality 的私聊指令可以直接读取手机上报，指令成功不能替代 V2 的这些授权记录。

当前在唯一公开页面「陪伴小屋」的现实设备台加入手机摘要读取管理。宿主提供所选目标和角色的固定 API；启用操作在一个 V2 事务中选择当前已加载的固定包、启用该 Bot／角色、保存当前参与者和完整私聊范围的 `reality.snapshot.read` 同意，并准备必要的工具调用权限。状态由实际对话工具目录核对。

该接口原有摘要还包括手机端已开启的设备、活动、健康数据；页面据实说明授权的是手机位置与终端摘要。设备控制、摄像头采集和声音播放使用各自的权限，本入口只开放 `reality.snapshot.read`。

## 归属

- `companion_v2/capabilities/reality_access.py`：事务、版本核对、当前身份／角色校验、同意与撤回、原请求回执。
- `astrbot_host/reality_access_api.py`：从真实 Dashboard 登录态及可信目标视图解析调用者；拒绝请求体或查询中的目标身份覆盖。
- `astrbot_host/multi_api.py`、`page_api.py`：按 Bot／人格／私聊目标下发固定地址，群目标不提供入口。
- `pages/陪伴小屋/reality-access.js`：展示真实可调用状态、明确启用／撤回、原请求核对、忽略已切换目标的迟到响应。

撤回只取消当前用户与完整会话范围的摘要同意，不取消其他窗口的同意。重试已完成的旧启用操作只读回当前状态；撤回后重放旧操作不会恢复授权。重新开启需要新的明确操作。

旧 `notify_mobile_location_update` 仍属于原通知路径。这不阻碍 V2 经原生工具主动读取位置；本次没有将旧通知广播到所有 Bot／人格，也没有迁移或读取 V1 用户数据。

## 验证与使用

`tests/test_reality_access_api.py` 验证启用后摘要进入 V2 模型上下文、独立 Bot／角色授权、撤回、原请求重试、停机重开、身份覆盖拒绝和路由注销。提供方、手机摘要、模型与平台均使用临时数据根和合成替身，预览不会发送真实平台消息。

`tools/check_reality_access_page.cjs` 验证桌面与手机宽度下的启用、撤回、超时后复用原请求和迟到响应隔离。验收还须从当前源码构建新交付包，在扫描目录外展开并验证宿主加载、生命周期与注册路由。构建及验收报告保存在本次交付目录；这些本地合成检查不替代用户手机的实际定位回包。

重载 V2 后，在小屋选择正确 Bot／人格／私聊目标，打开现实设备台并允许此会话读取。随后 V2 对话可调用已有原生工具读取手机摘要；手机定位来源和有效期继续由 Reality 提供方负责。
