# 插件禁用、启用与热重载恢复

## 故障来源

2026-10-07 16:11:32 的 `host_control_failed` 原始异常为
`ModuleNotFoundError`。固定运行档在装配 `ModelTaskProfile` 时无法导入核心
模块；异常与账号、人格映射或授权校验无关。

旧入口在停机时删除顶层 `companion_v2`、`astrbot_host` 缓存与自己插入的
导入路径，却保留 `data.plugins.astrbot_plugin_private_companion_v2.main`
及相对导入的宿主模块。AstrBot 禁用插件后不会解绑入口，再启用时可复用
旧入口、旧类与旧装饰器处理器。此时延迟导入找不到核心包，恢复失败。

## 修复边界

- `astrbot_host/import_lifecycle.py` 管理入口命名空间、宿主模块和核心别名。
- 确认存储已释放后一起清理完整模块图，同时移除父包中的旧模块属性。
- 新入口导入前替换自身旧装饰器处理器，避免禁用后启用重复接收消息。
- 保留仍在收尾的运行时所需模块，释放全局导入路径供下一入口接管。
  重复终止旧实例不会清理新入口。
- 仅清理本插件源码根拥有的模块；其他插件的同名前缀模块继续保留。
- 导入失败使用 `host_module_unavailable`，界面提示重载和核查安装包。
  日志保留异常类型与调用位置，继续省略异常值和凭证。
- 不修改 V1 数据，不重置 V2 运行档、角色归属、配置与历史记录。

## 定向验收

`tests/plugin_reload_process.py` 在临时 AstrBot 数据根下调用真实
`PluginManager.load/turn_off_plugin/turn_on_plugin/reload`，使用合成原生端口。
运行目录不作为插件核心导入路径，避免测试掩盖真实宿主的缓存问题。

覆盖三轮禁用再启用、禁用期间重载、活动插件热重载、延迟停机路径释放和旧实例重复终止，
以及已有运行档、角色归属与配置的恢复。检查每轮角色状态 API 可读，
处理器和路由无重复，停机注销路由，外部模块保留，模型调用和平台发送为零。

交付包需从当前源码重新构建，并在解包目录运行上述进程验收与异常提示检查。
