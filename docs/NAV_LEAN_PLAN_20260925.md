# 陪伴小屋侧边栏 · 精简版分类方案

日期：2026-09-25
基准：`V1_CONFIG_TAXONOMY_20260925.md`（1010 条 / 5 段 21 子类）
参考：V1「陪伴面板」导航栏（`pages/陪伴面板/index.html:261-277`）
现状：`SIDEBAR_NAV_AUDIT_20260925.md`（14 个入口逐项判定）

## 一、V1 导航给的两个可复用机制

V1 是 17 个平铺 tab，无分组，编号 01–17：

`总览 · 小屋 · 世界知识 · 用户 · 群聊 · 学习 · 观察 · 主动 · 创作(hidden) · 生图(hidden) · Token · 排障 · 配置 · 模型 · 实验 · 提示词 · 现实触及(hidden)`

真正值得 V2 继承的不是它的数量（17 个比 V2 还多），而是两点：

1. **默认页是「总览」而非某个功能页**。V1 的 dashboard 文案写的是「日程、状态、主动与记忆集中在这里；配置和诊断按需展开」——即默认页只做聚合，配置类不抢占首屏。V2 的小屋首页已承担这个角色，没问题。
2. **能力驱动显隐**。V1 用 `hidden` 属性让「创作 / 生图 / 现实触及」在能力未启用时完全不出现。这是"导航不长但功能不少"的正解，V2 完全没有用起来。

## 二、精简版方案

**默认可见 9 个**（分组保留），**按需显现 2 个**，**移出侧边栏 4 个**。

### 默认可见（9）

| 组 | 入口 | 承载 |
|---|---|---|
| 生活 | 日程与状态 | 计划/活动/进展 + 身体状态（吸收原「角色状态」） |
| 生活 | 日记与生活 | 日记、便签、梦境、睡眠与生活轨迹 |
| 生活 | 主动与联系 | 主动强度、联系间隔、免打扰（原「联系安排」更名；对应 B4 144 条，V1 也有独立「主动」tab） |
| 关系 | 人物与关系 | 人物、群、关系与权限入口 |
| 关系 | 记忆与经历 | 共同经历、原话与来源 |
| 表达 | 回复与表达 | 分段、注入、时机；语音与表情先作为页内分区 |
| 设置 | 感知能力 | 天气、新闻、识图、语音视频、群黑话、屏幕与现实来源（吸收「生活与环境」的天气/新闻） |
| 设置 | 身份与权限 | 角色、人格与三档权限 |
| 设置 | 模型与连接 | 公共模型与任务路由 |

### 按需显现（2）

| 入口 | 显现条件 |
|---|---|
| 创作与作品 | Content / Image 能力启用后。未启用时 `hidden` —— 与 V1 的「创作」「生图」同机制 |
| 目标与成长 | 存在成长提案后显示。V2 静态预览文案即为「暂无个人目标或成长提案」，无内容时不该占入口 |

### 移出侧边栏（4）

| 项 | 去向 |
|---|---|
| 角色状态 | 并入「日程与状态」，页内分区 |
| 生活与环境 | 拆解：天气/新闻→感知能力；日程→日程与状态；V2 试运行→维护工具区 |
| 宿主管理 + 资料与维护 | 合并为**维护工具区**（页脚工具位，非侧边栏项）：宿主探测、导出/重置、风控与用量、排障。位置参考 V1 的「配置引导」按钮，语义参考 V1 的「排障」tab |
| 语音与表情 | 先作为「回复与表达」的页内分区；TTS 真正接入后再考虑独立成入口 |

## 三、为什么这样收

- **默认 9 个是"每天都该看得见"的**，其余都是配置或按需。V1 把 Token/实验/提示词都列成 tab，那是历史包袱，不是好设计。
- **分组保留但不再平均分配**：生活 3 / 关系 2 / 表达 1 / 设置 3。表达组只有 1 个入口是因为 D 段里真正已实现只有文本分段，语音表情还没落地——不该给未实现的功能留空页。
- **「主动与联系」必须留在一级**。它对应 B4 决策与主动 144 条，是全部配置里最大的子类，也是 V1 单独开了 tab 的功能。砍它会让"她什么时候来找我"这件陪伴核心事没有入口。
- **维护类下沉为工具区**，而不是删掉。宿主探测、导出、排障这些是排障路径，不该和"生活"并列出现在主导航里。
