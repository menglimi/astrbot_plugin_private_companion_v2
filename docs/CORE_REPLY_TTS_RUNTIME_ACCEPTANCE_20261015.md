# TTS 实际回复链修复验收（2026-10-15）

## 现场

用户 01:23 的“在干嘛呢”收到文字和表情，没有语音。只读核对当轮核心观测：有效策略是始终语音，主模型失败后的备用模型仍带语音提示，未执行发送工具；原生会话保存的最终回答是纯中文，没有朗读标签。配置丢失或 FishAudio 合成失败均不能解释这次未触发。

旧流程依赖模型主动输出标签；遗漏时只在 DEBUG 记录并退回文字，没有补齐始终语音所需的朗读内容。此前模型探针未携带实际工具列表，不能用其成功率代表真实聊天。另检查到原生发送工具的文字参数会先做呈现清理，响应钩子也不会为工具参数保存语音；该路径一并补齐。

## 实现

- 在本轮 AstrBot Runner 的最终回复边界捕获语音，重复响应钩子不清除已经保存的朗读片段。分段发送与原生发送工具在文字替换和清理前分离语音与译文。
- 对已通过触发检查的始终语音或应请求语音，若模型完成正文却遗漏朗读标记，在同一 Runner 内整理该正文的朗读格式。使用当前实际成功的 Provider，不经过插件 ModelGateway，也不创建后台模型任务。原生发送工具的文字参数使用相同处理。
- 整理时只提供完成的正文和语音设置，不再次提交历史、记忆、图片、工具定义或工具结果。关闭这次呈现请求的工具，避免重放已执行操作；程序保留原正文，整理结果只提供朗读内容。保留自适应模式选择文字的空间，明确只用文字时不补写语音；整理失败或无适合朗读内容仍保留原文。
- 这次请求仍经过核心请求观测，用量计入 AstrBot 主链，并纳入 Runner 累计 token。定向回归确认两次核心请求共 220 个模拟 token，插件预算消耗和插件 model_rounds 均为零。
- TTS 生成、格式补全、无朗读内容的原因通过宿主 INFO 日志输出，只保留阶段、状态和计数，不记录用户正文、密钥或音频 Base64。取消、合成失败和未知发送结果继续沿用既有授权与不重放边界。

## 验证

使用 AstrBot 自带 Python、SDK 4.28.2 和临时数据根。从当轮保存的 offered_tools 对应源码重建 57 个工具的名称、说明和参数 schema。真实模型探针包含实际人格、近期历史和 Safe Mode，工具只作为模型输入，从不执行或对平台发送测试消息。

最终候选包三轮真实 Provider 验证均生成日语朗读，其中一轮复现标签遗漏并由主链呈现请求补齐，另两轮无需补全。FishAudio 本地合成得到有效 WAV，344108 字节、1843 毫秒。该结果验证真实生成与本地合成；不据此声称 QQ 已确认接收语音。

包内回归覆盖真实 SDK Runner、已有标签、遗漏标签、发送工具参数、中文正文不被替换、适应性文字、明确文字要求、失败、取消、主链统计、QQ 文字与 Record 分开发送及表情附件。另执行新包宿主加载、启停、路由注销与迁移验收。最终结果与构建哈希保存在 `D:/codex/artifacts/companion-v2-tts-runtime-20261015`，以最终交付包报告为准。

## 边界

没有向 QQ 或真人发测试消息。额外朗读呈现仅在本轮实际缺失时产生一次主链请求，会增加该轮主链延时和用量；成功产生朗读内容仍需当前 TTS Provider 与平台发送可用。后续实聊可用同一 event_ref 对照 authoring、response、TTS 合成和发送返回，区分格式、Provider 与投递问题。
