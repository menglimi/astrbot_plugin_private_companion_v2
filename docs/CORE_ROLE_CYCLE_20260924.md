同日后续[优化核查](ROLE_CYCLE_OPTIMIZATION_REVIEW_20260924.md)确认的 5 项问题现已修复，新增感受延续与自然初始化，详见[优化实施和验证](ROLE_CYCLE_OPTIMIZATION_20260924.md)。下文为更新后的当前合同；首批与本次测试证据分别记录。

后续已增加[可选的每轮阶段差异](ROLE_CYCLE_VARIATION_20260924.md)，最新相关回归 119 项通过。差异只调整阶段内天数，周期总长仍按配置；默认关闭。

2026-09-24。补齐上一批角色状态中仅有 `cycle` 文字槽的缺口。实现归 `companion_v2/role_work/state/` 内的周期模块，沿用状态正本、版本历史、派生来源、共享后台任务及已认证的 state 管理 API；不增加 SQL 表或 schema 迁移。

## 当前行为

- 基础三阶段为经期 → 恢复期 → 经前期；六阶段为月经期 → 卵泡期 → 排卵前 → 排卵期 → 黄体期 → PMS。默认长度分别为 5、7、2、2、9、3 天，总计 28 天；基础模式将中间四段合为恢复期。
- 保存模拟起始日期、采用的时区、各阶段长度及表达偏好。按当地日历日期计算当前第几天、阶段内第几天、周期次数和下一阶段日期；经过夏令时按当地日期推进，重启不重置，不要求离线时补跑模型。
- `applicability` 区分 `unknown`、`not_applicable` 与 `applicable`。自动模式由模型结合完整原人格设定判断；程序不使用姓名、性别词表或用户的经期自述推断。首次确认适用默认一次性选择自然位置并持久保存，也可保持阶段未知、明确从第 1 天开始或由 CORE 管理者定位。人工适用性保存为 `decision_origin=manual`，普通维护不能覆盖，需用 `auto` 显式恢复自动判断。
- 代码只推进模拟时间线。语气、注意力、精力感受和不适由原人格与提示词解释；没有固定扣分、必然痛经、情绪刻薄、自动亲密升级或生育预测。允许温和照顾、安慰和拥抱，结合自己的意愿表达身体负担与互动边界；无关话题不重复播报。
- 不适模拟独立关闭。关闭时新写入的 `kind=cycle` 临时症状会被移除，已有结构化状态的周期症状也不进入当前材料；开启后仍不要求每月或每轮产生症状。感受文字的语义依赖模型遵循提示词，不采用症状关键词拦截。
- 周期配置进入既有后台维护；当前时间线同时进入普通私聊。普通回复仅在有适用的周期材料时添加共用说明和当前阶段提示；关闭、未知适用性或不适用时不添加完整周期说明。`cycle_expression_prompt` 可描述各阶段的角色偏好，随状态版本保存并进入对话材料。QQ 仍只读取显式公开的 `presence`，不把周期字段映射为公开状态；提示词要求公开文案不包含身体细节。
- 可选的 `cycle_feeling` 保存同一次感受的标识、开始/观测/最近确认时间及延续、减轻、加重、结束或未确认状态。是否有不适、如何表达和是否提及由原人格、材料及提示词解释，不采用症状词表或数值惩罚。

本批的 owner 仍是当前私聊 scope、角色与用户，尚未实现跨窗口共享一个身体时钟或群内周期表达。这里只维护角色的模拟身体，不记录或推测用户现实经期。

## 配置与管理 API

仍使用 `GET /astrbot_plugin_private_companion_v2/state` 和 `POST /astrbot_plugin_private_companion_v2/state/command`，不增加另一套页面。配置及操作沿用原 CORE 身份、固定 profile 目标、版本检查和幂等回执。

`configure` 的 `changes` 新增以下字段；原有 `enabled` 和 `cycle_enabled` 默认仍为 false。

| 字段 | 默认值及含义 |
| --- | --- |
| `cycle_mode` | `basic`；可选 `six_phase`。 |
| `cycle_initialization` | `natural`；首次确认适用时一次性选择位置并保存。可选 `unknown` 保持阶段未知、`first_day` 从第 1 天开始。已有锚点不会因修改此配置重抽。 |
| `cycle_variation_enabled` | false；启用后每轮可保留基础方案或在两个阶段间移动一天，总周期长度保持配置值。本轮方案固定，开关变更从下一周期采用。 |
| `cycle_timezone` | `Asia/Shanghai`，有效 IANA 时区。已建立的起始日保留原时区，需用 `cycle.align` 显式重新定位才采用新时区。 |
| `cycle_menstrual_days` | 5；月经期天数。 |
| `cycle_follicular_days` | 7；卵泡期天数。 |
| `cycle_pre_ovulation_days` | 2；排卵前天数。 |
| `cycle_ovulation_days` | 2；排卵期天数。 |
| `cycle_luteal_days` | 9；黄体期天数。 |
| `cycle_pms_days` | 3；经前期天数。各阶段均为 1–30 的整数。 |
| `cycle_discomfort_enabled` | false；允许可选的周期临时不适模拟。 |
| `cycle_expression_prompt` | 空字符串；最多 2048 字符的附加表达偏好。 |

模式、阶段长度及阶段差异开关修改由下一次成功维护保存为 `pending_plan`，从当前周期结束后的当地日期生效；当前周期和过去的周期次数不重算。生成前提供当前阶段和待生效方案，模型失败不改写记录；需要立即改期时用 `cycle.align`。表达偏好及不适模拟的开启在下一次成功维护时采用。宿主已绑定时配置变更沿原排程请求尽快维护。关闭 `cycle_enabled` 或不适模拟立即停止相应投影；关闭期间保留起始日期，重新开启时按经过的当地日期继续。不会重复应用旧的手动偏移。旧回复保留当时采用的不适偏好，后续开启不适模拟不会改写它。

新增一次性命令：

```json
{
  "action": "cycle.align",
  "operation_key": "my-cycle-adjustment-1",
  "expected_revision": 3,
  "view_token": "使用 GET 返回的 state.view_token",
  "data": {"applicability": "applicable", "day": 15}
}
```

`day` 从 1 开始且不超过配置的总天数。设置 `unknown` 或 `not_applicable` 时 `day` 必须为 null，并清除锚点；这些人工决定持续生效。使用 `{"applicability":"auto","day":null}` 清除人工决定及旧锚点，下一次成功维护根据原人格和初始化设置重新判断。重新定位会清除旧周期描述、感受记录及周期临时症状，保留其他仍有效的状态；同操作重试只查原回执，旧版本的新操作被拒绝。自动维护不能指定锚点或当前日，日期参数由代码和显式管理命令负责。

普通 `state.write` 继续接受完整原字段。`cycle` 兼容文字/null，新增结构：

```json
{"applicability": "applicable", "description": "今天想放慢一点节奏"}
```

返回的 `state.values.cycle` 仍是文字或 null，已采用的结构化时间线位于 `state.cycle_timeline`，不会把原字段改成对象。时间线包含适用性、表达偏好、不适开关、决策来源与初始化方式，以及日期已知时的 `cycle_day`、`phase`、`phase_day`、`next_phase_date` 等。待生效方案位于 `pending_plan`。输入还可带可选的 `feeling={episode_id,trend}`，完整合同见优化记录。内部锚点和独立依据保存在版本记录的 `cycle_clock`、`cycle_sources`，不会另建无来源的全局状态。

本轮已开启阶段差异时，时间线增加 `variation_enabled=true` 和实际 `phase_plan`，所有阶段日期据该方案计算；待生效方案的 `phases` 仍为基础方案，`variation_enabled` 表明届时是否启用差异。内部种子和算法版本不进入模型材料，完整保存及恢复合同见每轮阶段差异记录。

## 历史与来源

旧文字数据保持可读，不从含糊描述猜出阶段。旧时钟和旧快照投影保持原合同，避免改变已经封存的历史哈希。新回复快照封存观测时间，未发送及已发送回复均使用当时的周期日，跨午夜自然推进不改变这一轮材料。未发送回复仍复核当前状态版本、临时条件到期及实际活动；关闭功能、撤权、来源撤回和人工改期仍按当前规则阻止旧材料消费。

周期日期/适用性的来源与之后的聊天感受分开保存。无关聊天撤回后旧状态感受仍不可读，维护可读取仍有效的独立周期依据，恢复时不重置日期。真正的周期依据撤回会使依赖它的后续时钟失效；旧记录没有独立来源时保守沿用整份旧记录依据，不扩大可见范围。同一次感受的续写继续依赖此前感受来源。坏 JSON、非法日期字段、维护中撤权和旧版本冲突不会覆盖旧状态。

## 验证与边界

使用 AstrBot 自带 Python、临时 V2 数据根、模拟模型和平台端口。新增测试在 `tests/test_role_cycle.py`，管理 API 用例追加到 `tests/test_role_state_api.py`。覆盖六阶段边界、三阶段合并、当地日期与 DST、重启、开关、一次性定位及 CAS/重放、适用性、不适到期、来源撤回、旧文字兼容、历史快照、原人格维护与普通对话、用户自述归属、配置校验和 API 固定目标。

首批新增 **17 项**用例（周期 16 项、管理 API 1 项），最后一批相关回归 **81/81 项通过（33.167 秒）**。本次优化新增 **22 项**回归，周期、状态、API、配置权限、QQ 展示、会话历史和工程隔离 **103/103 项同批通过（30.184 秒）**。这些批次有重叠，不累加为独立用例数。

这些测试验证材料归属、状态计算、提示词接线和执行边界；模型是否始终自然理解角色身体、不过度谈论周期，仍需实际对话验收。管理页面由原页面任务接入；本批没有在线重载、启用功能、读取 V1 用户数据或调用真实模型/QQ。
