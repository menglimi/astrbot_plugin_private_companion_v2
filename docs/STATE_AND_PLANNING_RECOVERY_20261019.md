# 状态与日程闭环修复（2026-10-19）

## 已确认的原因

- 角色的活动及睡眠执行记录为空，且自动作息未启用。空记录被模型沿旧描述解释成持续没睡、没吃，旧感冒、失眠和低精力因而不断续写；这不是新的执行证据。
- 定时状态维护原先只读取最近的用户输入，并以共享状态的更新时间截断。照顾发生在另一个授权私聊窗口时，或角色已回复药物开始起效时，维护任务可能没有读到这段连续互动。
- 状态模型曾返回普通聊天文本，结构协议拒绝后界面只显示 `model_usage_unknown`，保留的旧状态看起来像又一次成功更新。
- 当日日程的凌晨请求因模型等待超时失败；原日程时段的持久标记防止重复请求，但也使当天没有新的自动评估机会。页面把空日历显示为“今日暂无安排”，掩盖了生成失败。

## 实现

- 为授权窗口维护独立的对话消费游标，读取最近三天内有限量的用户输入和已发送助手回复。每次任务只使用自己窗口的私聊材料，成功写入后消费该次观察；无发送回执、撤回和已重置的材料仍被过滤。达到字数上限时优先保留最近消息，再按时间顺序提供给模型。
- 共享状态只承载角色自身的概括感受。补充旧状态历史、睡眠资料及其观测时间，明确没有记录不等于缺食、失眠，旧症状不应逐日滚动成新发病；照顾和角色的缓解反馈可合理影响感受。通过提示词恢复自然变化，不直接重置真实状态或按关键词增加精力。
- 状态维护、日程规划请求使用 JSON 对象响应，并在动态材料之后补充任务对应的输出协议。底层的协议拒绝、超时等错误码传递到状态诊断，失败仍保留上一有效状态。
- 保存日程任务结果。仅在原任务已终止、没有本地提交且本地操作并非未知时，在当地 06:00、12:00、18:00 开始的白天时段重新观察剩余一天；与前次失败至少间隔一小时，每时段最多一个新任务。新任务采用当前材料和新的持久标记，不重放旧请求，不补写已过时段。成功的空计划和已提交/未知的本地结果不自动重做。
- 首页区分规划失败、正在生成与确实没有安排，展示具体失败原因和后续评估时刻；日程材料标注状态记录的时效，低精力不自动意味着全天没有生活安排。

## 验证范围

使用 AstrBot 自带 Python，在临时测试数据根中检查状态维护、日程重新评估、模型 JSON 协议、对话字数截断、来源撤回及跨窗口隔离。页面检查覆盖失败提示和日程覆盖显示。交付包另行验证资源哈希、唯一公开页面、宿主启动停机和路由注销；结果保存在该次构建的验收目录。

检查实际运行数据使用只读 SQLite 连接。未改写 V1 数据，未清空 V2 状态，未触发真实聊天发送、服药记录或睡眠执行。模型如何描述主观恢复仍需重载后的实际维护回合验证，合成测试不等同于真实模型效果。
