# G6 跨能力前置审查

日期：2026-09-21。范围：对照其余能力的设计与独立 V2 当前实现，决定继续 G6 时哪些公共责任必须先补。本文是实施前置清单，不是新增公共 Schema，也不表示相关能力或验收已完成。

范围补充：用户随后明确本次关注的是 V1 已实现的非拓展本体功能，当前优先顺序以 [本体功能前置对照](V1_CORE_FEATURE_PREREQUISITES.md)为准。本文保留为之后继续 G6/G7 时使用的拓展配套审查，不代表当前先于本体补齐推进安装器。

结论：保留 Screen 首接入和 G7 三组接入顺序，但不能把 Screen 的一次观察流程直接推广成所有能力的运行方式。现在先补安装管理共用的状态、身份、操作恢复、依赖退出及设置归属；会话、媒体和资源的共同接口现在确定，真实适配随相应能力接入。无需为等待全部领域实现而停下 G6。

### 3.1 本批采用的实现边界

- 包的发布描述采用版本化配套记录；不把待定领域字段全部塞入 `ScopeRef` 或现有公共结果枚举。当前固定包记录通过显式数据库迁移演进，保留既有冲突保护和用户选择。
- 保留人类同意的语义，另建可信的角色任务执行上下文及许可关联。不能仅放开 `SubjectKind` 检查，就宣称角色具有系统或管理员权限。角色自有材料可留在自身范围；实际分享时按目标受众另行核验，不修改原件 scope 来规避检查。
- 同一 owner 的 Repository 写入、原操作与 outbox 通过明确事务单元组合；跨 owner 使用原引用、outbox/inbox 与采用回执。事务不包住网络、模型、媒体播放或用户动画等待，不承诺文件/远端与 SQLite 同时原子提交。
- 先用固定的本地描述符、隔离获取/装卸替身及临时数据根验证管理闭环。真实下载/解包再接固定资产与路径核验；包 hash 不代替来源信任，也不把原生插件描述成已经沙箱化。
- 只读目录、页面刷新和版本检查不触发生图、采集、通话或发送。只读状态查询可读取已有实际盘点结果；联网检查作为独立有界操作表达，离线不显示“已是最新版”。
- 未知在途效果可保留为待查账；暂停/丢弃不要求无限等待，但不能谎称外部已停止。需要重启才能排除旧 writer 时如实等待宿主交接，不启动冲突写入者。被卸载模块不为清理或恢复而偷偷重新启用。
- 已有授权覆盖时复用。角色是否看、说、接电话、继续写作、等待用户介入，由原模型结合材料与提示词决定；技术边界只处理权限、版本、资源、明确停止与实际效果，不增加固定剧情或每步确认。

### 3.2 延迟与互动的公共约束

普通主动保留“效果优先”；新闻的时效来自发布时间、有效范围和来源更新，不能由竞争权重刷新。Together、Live、Game 的当前会话接续不重新参加普通主动竞争。

前台优先利用已取得的有权材料，长检索/写作/生图可返回原任务后继续；不固定追加分类、策划、答复、复审多轮模型。后续语义分段仍按既定设计保留。可靠停止和授权变更不能被高频媒体队列堵塞；临时帧/进度允许有据合并，确认输入、最终回执和已接受事项不随缓存丢弃。

接真实链时记录排队、材料准备、模型首个有效输出、首个可发送语义单元、TTS、提交和端点实际开始等时间点，分别评估被动、实时与普通主动。不能以空泛占位话降低首句数字，也不在没有真实测量时承诺延迟指标。

## 4. 留到领域接入时完成

| 能力 | G7 对应交付，不扩大当前 G6 实现 | 最小联合验收情境 |
| --- | --- | --- |
| Reality | 真实设备目录/绑定、位置与手机状态查询、单帧采集、音响执行与逐层回执；健康等来源复用当前感知入口。 | 有“在家”依据和适用授权才考虑对应设备；外放前地点/受众变化重验；未知播放不换音响重播。健康累计数有统计窗口，不从后台状态推断用户未用手机。 |

| Live | AI 主播/助播分工、节目活动、现场输入视图、后台准备、逐端声音/字幕/形象关联。 | 生成插画时仍可接话与停止；私聊后台指示不进入公共口播；换节目后晚到结果不强行切回旧节目。 |

共同语义在隔离环境验证后，真实设备、媒体、后端、模型及平台再按各自关卡取证；不能把一条替身链的通过数复制成所有能力通过。

## 5. 暂缓与不能遗漏的范围

长期暂缓仍沿 `IDEA-20260916-001`：独立客户端移植、独立对话窗口、智能家居、跨端共同注意、可穿戴/实体互动和新增独立交互形象。保留接入端口即可，本轮不提前开发。这个口径不排除已承诺的 Reality 手机感知/现有移动入口、Together 通话及 Live/桌宠呈现。

Memory、基础日记、日程/提醒、群聊参与和角色生活是核心路线，不用附加家具取得。Calendar 已接受事项及 occurrence 的恢复不能被主动竞争取代；Memory 保留当前授权与有据采用。V2 当前局部核不等于这些核心能力已完整持久实现，领域整合和替换验收仍须逐项补齐。

第三方多功能包、复杂依赖选择、丰富家具款式与完整市场展示可逐步实现；当前目录必须如实声明支持范围，不能接受无法核验/退出的包并显示 ready。完整首装、自动迁移及回滚属于后续发行交付，配置值来源、稳定身份和迁移登记则从本批落库时保留。
