# QQ 展示诊断与原请求追踪

日期：2026-09-25

## 已实现

“陪伴小屋 → 管理与设置 → 角色状态”新增当前 QQ 展示条件：开关、有效授权、输入提示刷新间隔、原会话是否正在回复，以及自定义短状态的显式公开文案和来源。页面区分未启用、无展示端口、宿主未运行、授权不足、等待任务、正在刷新、本轮已停止、没有公开文案、日程重叠、账号存在多个展示窗口和相同文案去重。

状态 API 增加只读 `presentation_diagnostics`，保留原 `presentation` 结构并增加回执记录时间。自定义短状态同时返回原操作 ID、操作状态和请求的公开文案；输入提示关联原回复批次。页面默认展示用户可用的状态说明，原请求标识通过键盘可操作的折叠区查看。

自定义短状态读取已有 `platform_presence_operations`，即使宿主刚重建且尚未绑定窗口，也可按原完整 context 读取最新账号操作。重启、重复查询和命中相同文案均保留原 `updated_at`，不生成新的请求时间。旧记录无需迁移；`started` 明确表示只有开始记录、没有完成回执，其时间也只代表开始时间。不同角色或绑定修订不继承原回执；相同账号的其他角色只得到“相同文案已去重”的条件说明，不暴露前一角色的请求标识。

输入提示仅保留当前宿主运行中的最近记录；回执未知后本轮停止刷新，后续独立回复仍按原流程重新判断。平台已受理只代表请求结果，页面不会把历史 ACK 解释为客户端当前仍显示。

修复输入提示发送前的续持条件：按原会话 `origin_key` 检查 collecting / generating / delivering 回复，不再使用同一角色跨窗口共享的身体忙碌状态。另一窗口仍在回复时，已结束会话不能继续续持输入提示。

## 职责与边界

- `companion_v2/delivery/presence.py`：原请求记录、准确时间、账号去重及原会话输入续持。
- `companion_v2/delivery/presence_diagnostics.py`：组合只读条件，复用展示协调器的准入、公开文案选择和账号归属判断。
- `companion_v2/role_work/state/management.py`：经过既有 CORE 管理授权后输出配置、当前诊断及历史回执。
- V2 规范页面和 Content 预览的 `state-page.js` / `state-page.css`：现有页面内的诊断、回执和窄屏展示；页面入口的资源版本同步更新。

GET 不调用展示端口，不绑定目标，不排程，不写操作表，不调用模型。健康、周期感受和私人日程标题不用于公开文案。4 秒默认值只降低了请求频率；客户端提示持续时间及闪烁改善仍需实际 QQ / NapCat 版本验证。
