# 对话呈现提示与 V1 对照（2026-10-15）

## 现场与边界

截图中的「查看本次提示词」来自表达设置的离线呈现预览，由 `ReplyManagement.preview()` 返回分段、文字呈现和语音提示，不是某一轮实际请求的完整日志。旧预览把规则处理设置描述成模型提示，容易混淆两者。

对照本地 V1 的 `release-6.4.5` 源码：`main.py` 的模型分段入口只在 `enable_llm_controlled_segmenting` 开启时提供分段控制；`event_dispatch.py` 在回复返回后执行文字替换、分段与清理。V1 没有 V2 额外添加的「消息正文组织」段落，也没有把清理词、替换表作为 JSON 提示交给普通对话模型。

V2 原有 `SegmentationPolicy.instruction` 在规则模式下也生成长篇组织提示；`ReplyTextPolicy.instruction` 将清理和替换配置编码为「正文呈现偏好」。这些公共策略同时用于离线预览、领域回复生成和主动联系。原生 AstrBot 核心回复只提取显式表达偏好，不使用这份清理 JSON；但规则分段提示会经临时上下文进入核心请求。

## 修复

- 关闭分段或仅启用规则分段时，分段策略不生成模型提示。模型控制分段时只使用选中的协议和实际分隔标记。
- 删除「消息正文组织」常量及提示目录中的失效项目。用户主动开启的日常表达、自定义风格提示仍按原配置生效。
- 清理词、正则和替换表继续作为程序后处理设置，不进入文字策略的模型提示。既有替换、分段、清理顺序及保护范围保持原合同。
- AstrBot 核心私聊、群聊的模型分段协议仍位于本轮临时上下文中；不因规则设置改写人格或系统前缀。感知事实、历史和关系背景仍按既有入口提供。
- 语音标签在模型编写朗读内容或按语境选择语音时仍需要。普通全文转语音模式不提供标签协议；不将清理提示移除解释为关闭 TTS。
- 表达页将入口改为「查看呈现提示预览」，明确它不代表某一轮完整请求。
- 主动新闻自身的排版提示属于独立业务路径，本次未调整。

## 验证与交付

使用 AstrBot 自带 Python、临时数据根和模拟模型/发送端口验证；不访问 V1 用户数据，不进行真实消息投递。

最小源码验证已通过私聊/群聊分段注入、感知上下文和提示目录的 28 项测试。交付包从当前源码构建后，另在解包目录执行呈现、分段、语音、感知及预览的定向回归，并检查宿主启停及路由注销。最终结果、包哈希和日志统一保存在 `D:/codex/artifacts/companion-v2-chat-prompt-20261015`，以其中最终记录为准。
