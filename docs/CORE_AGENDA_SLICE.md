## 1. 当前实现

| 部分 | 行为与代码 | 已验证边界 |
| --- | --- | --- |
| 个人便签 | [AgendaService](../companion_v2/agenda/service.py)提供创建、读取、有限分页/搜索、字段修改、完成、恢复、置顶/取消置顶及明确删除提交。 | 真实创建者、所属角色、资料主体和精确范围持久保存；未知 ID 修改不变成创建。省略字段不重置，空正文有效。服务端先按置顶再按稳定 ID 排序，使用包含置顶状态的复合游标分页；翻页期间数据变化仍按当前视图读取，不是跨请求冻结快照。 |
| 独立提醒 | 提醒可以独立存在，也可以引用便签；便签有到期时间不等于自动设置提醒。 | 一条便签最多关联一个提醒记录，关闭后沿原记录明确重新安排。提醒接收者固定为当前个人对象；不遍历主要用户名单，也不猜最近窗口。 |
| 原操作与版本 | [AgendaRepository](../companion_v2/agenda/repository.py)在共同短事务中更新便签、提醒、期次及原操作结果。 | 回包丢失可查原结果；同参数重试不再次完成或覆盖新内容。两连接过期修改被拒绝；事务失败不留下半份事项、期次或已受理操作。 |
| 重复时间 | [Schedule](../companion_v2/agenda/models.py)支持一次、日、周、月、年及正整数间隔、可选总期数，保存绝对锚点和 IANA 时区。 | 每期由原锚点计算：1 月 31 日到 2 月末后可回到 3 月 31 日；闰日年度重复可回到闰年的 2 月 29 日。夏令时重复时刻按 fold，缺失时刻按明确策略拒绝或顺延；不会默猜时区。 |
| 完成与改期 | 重复便签完成本期后推进一次；独立重复提醒在本地准备完成后登记下一期。 | 便签恢复不会自动重新开启已取消提醒；改期/取消/完成使旧期次不可再用。正文修改重建同一期的未投递准备，不另建预约；回传未变的时间设置不倒退期次。 |
| 到期本地端口 | `due()`有限分页查询 ID，`accept_due()`核验并领取，`prepare_local()`保存当前个人受众的准备内容，`validate_preparation()`在本地交接前重验。 | 到期查询不代表已领取，领取不代表发送；撤权、账号换绑、角色换走又换回、内容修订都不能借旧回执继续。准备可跨进程恢复，两工作连接重复处理只保留一份准备和一个下一期。 |
| 删除与治理 | 明确删除保留对象墓碑和不含正文的原操作回执，清空便签标题/正文及关联期次准备正文。 | 停止后续本地准备；已删除对象不能由 reopen 复活。当前没有真实发送效果，不能以本地取消代证外部消息已撤回。 |

便签实际内容与排序属性分别计修订：置顶/取消置顶会更新对象版本，但不会使已领取内容失效。正文变更则使旧内容准备失效，同时保留预约标识。重复便签的完成计数只表示受理的完成操作，不将它写成用户已经做了某种现实行为的证据。

原操作回执分别包含对象保存状态、`not_requested / local_registered / local_cancelled` 和 `delivery=not_started`。本地准备另记 `local_prepared`；遇到下一期夏令时空缺，当前期仍可保存准备结果，并记录 `schedule_needs_resolution`。这些结果都不能表达“宿主已排程”或“用户已收到”。

## 2. 数据库升级与依赖

[schema](../companion_v2/storage/schema.py)新增内部 `storage.v3 -> v4` 事务迁移，建立便签、提醒、期次和原操作结果四张表及范围/到期索引。原 v1->v2、v2->v3 的 DDL 与指纹保持；版本常量显式保留 v3，避免旧迁移记录被当前版本号重新解释。

非空 v3 夹具含真实格式的绑定、授权、角色修订和 0/false/空文本配置。升级后保持原值与修订；故障注入证明新表、迁移记录和版本一起回滚；半升级、旧指纹变化、未知版本、缺失到期索引均不会被静默修复。这仍是 V2 内部格式升级，不是 V1 用户数据迁移。

时区使用 Python `zoneinfo`，Windows 在 [pyproject.toml](../pyproject.toml)声明 `tzdata` 依赖；本机现有环境已可解析上海/纽约时区。缺少数据库或不支持的时区明确失败，不退回系统本地时区。真实发行的全平台依赖安装仍需后续验证。

## 4. 尚未完成及接续顺序

- **公共对象权限仍需补齐。** 当前服务仅支持具有精确操作授权的本人对象，并绑定当前角色范围；跨窗口个人资料、共享对象、核心用户全安装管理和替他人安排尚未接入。重要/普通用户自动开放语义也未由这一局部服务完成。必须接公共对象策略，不能把本轮的本人限制当成最终产品规则或另建便签管理员。
- **入口与意图接续。** 尚无工具/页面/宿主适配；删除提交仅供已有明确对象和版本的意图调用，准备/取消删除意图、分享、旧来源治理未实现。自然语言由原角色模型理解；没有用词表自动替用户设置提醒或认定完成现实活动。
- **调度与投递仍是本地端口。** 尚无常驻 worker、持久扫描游标、宿主注册/取消回执、执行租约、外部未知结果查账或真实 Delivery。扫描者需沿分页游标前进，避免被无权事项挡住其他事项；停机后的过期提醒聚合/跳过策略及大量历史期次追赶，须在正式后台执行前接入 CORE-08，不自动补发全部错过消息。
- **本地准备不是外部执行资格。** 多连接可共享同一本地领取；其安全性来自无外部效果及同事务准备。接真实模型/发送前必须进入公共任务与 Delivery，不能把 `prepare_local()`外包一层 sender 就宣布完成；实际输出需再次复核版本、目标及当前授权。
- **时间范围仍有限。** 当前为固定频率和锚点规则；周内多日、自定义 Cron、例外日期、业务日、外部日历，以及 Bot 计划/用户自述候选/已接受约定/实际经历的完整 Calendar 领域尚未加入。
- **归属与配置仍沿公共服务。** 本切片不新增一套参数文件；时间是具体事项的显式业务字段，未默用全局默认值。完整设置页、全量 V1 转换器、直接替换资格不因本轮升级而完成。

下一步先接本切片所缺的公共对象权限与原角色操作入口，再沿 CORE-08/CORE-02 建立有界任务执行、模型路由和消息公共链；到期执行及真实回执在相应适配阶段接入。CORE-03/05、Calendar 其余部分及 G6-G10 仍按本体路线推进。
