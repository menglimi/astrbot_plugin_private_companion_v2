# 手机终端与 V2 原生连接

手机仍使用原来的网关地址和配对令牌。连接参数保存在 V2 当前运行数据根的 `extensions/reality/config.json`，从原插件复制配置不等于读取其运行态或用户数据。原独立网关必须先停止，才能由 V2 内置 Reality 监听同一端口；两个网关不能同时占用 6322。

`GET /health` 保留移动端原有协议字段，并返回 `owner=astrbot_plugin_private_companion_v2`、`execution_path=v2_native` 及当前产品版本。旧手机会话保存在原网关内存中，切换后手机需要重新配对；支持自动恢复的终端会自行重连。

`GET /status` 返回配对、手机上报和房间能力状态。同一用户的 `connections.devices` 只返回设备名称、配对时间和最近通信时间，不返回令牌。屏幕状态的 `available` 只代表共享功能可用；`online`、`last_report_at` 和 `age_seconds` 才反映是否有最近心跳。配对成功不代表已开启位置、活动或身体数据共享。一起房间和游戏需要各自的启用和使用授权。多目标宿主也注册原生设置接口，连接参数可在「陪伴小屋」配置。

`GET /snapshot` 是显式的原生摘要读取入口，不调用模型或设备，不触发通知、相机、声音、建房及消息发送。它要求有效手机会话、当前 V2 私聊身份、当前人格，以及独立的 `reality.snapshot.read` 授权；通过 V2 原生注册表执行该能力，返回原生回执和本用户的摘要。支持 V2 移动前缀别名，未配对返回 401，摘要读取未获授权返回 409，撤销会话或改变人格后不得继续返回旧摘要。

2026-10-11 的真实环境检查复用了旧网关的连接参数，停止旧网关后重载 V2。手机终端于 14:09:23、14:15:23 在 V2 日志中重新配对。人格接口返回「星缘-私聊」和 `v2_persona`；原生摘要调用于 14:19:52 返回 HTTP 200、`state=succeeded`、`effect=none` 和 `reality.native.operation:` 回执。检测使用的本地检查会话均已关闭，没有上传合成手机数据。

这次检查还发现历史摘要读取授权只绑定 `staging-role` 和迁移前会话。按用户本次原生能力检查请求，为同一用户、同一账号及同一原生私聊的当前「星缘」角色接通摘要读取权限；历史授权保留。相机、音频和设备控制权限未纳入这次调整。

初次检查显示屏幕功能可用，但没有最近屏幕心跳，`streaming=false`；位置、设备电量和活动摘要为空。身体数据共享关闭，一起房间和游戏未启用或授权。后续发现诊断会话会清空手机缓存，因此初次空快照不能证明手机没有上传。以上项目不算真实功能验收通过。

手机显示「已上报」后的排查发现，`MobileSnapshotOwner.session_changed()` 在同一用户建立、关闭或过期任意会话时，会删除该用户所有上报缓存。检查程序本身的临时配对与关闭就足以产生空快照；原先的保留期限还取该用户所有会话到期时间的最小值，短时检查会话会错误缩短手机数据的引用期限。

修复后，每条缓存记录带内部上传来源会话引用。配对、关闭或过期检查会话仍让旧读取票据失效，但会保留来源会话仍有效的数据，并保持原始保留期限。关闭上传来源会话、切换私聊身份或人格、停止插件仍撤下对应缓存。身体数据合并包含多个来源时，任何贡献会话撤销都会撤下合并缓存，避免残留已撤销数据。屏幕心跳也记录来源会话，并在读取请求后再次核验授权。

`GET /status` 的 `connections.devices[].reports` 返回本会话实际接收的各项上报时间，不返回令牌、内部会话引用、位置坐标或身体数据。独立网关记录固定上报操作、HTTP 状态及成功标志，便于定位手机旧状态、请求拒绝和真正接收之间的差异。

`tools/check_mobile_native_connection.py` 从 V2 的 Reality 配置读取既有配对参数，通过本机网关观察真实上传并执行原生摘要读取，最后建立并关闭第二个检查会话验证缓存保留；所有诊断会话在退出时关闭。脚本不上传合成数据，证据仅保存状态、时间和原生回执。可执行 `python tools/check_mobile_native_connection.py --config <V2 Reality config.json> --output <扫描目录之外的证据路径> --duration 120`。无真实上报时，`validation.real_uploads_seen=false`，不能将摘要接口的成功回执算成手机数据验收通过。

定向用例覆盖手机的五项上报在检查会话增删及过期后的保留、来源会话的撤销、多人来源身体数据的撤下、新私聊上下文隔离、HTTP 接收和拒绝记录、屏幕上报等待期间的授权撤销，以及原生读取权限和宿主路由注销。详细无令牌实时记录保存在本地 `D:/codex/artifacts/companion-v2-mobile-native-20261011/`。

修复加载后的真实手机于 14:52:55 自动重新配对，V2 在 14:53:41、14:54:08 接收到位置上报。14:55:11 的原生摘要读取返回成功回执且 `location.available=true`；14:55:12 建立并关闭第二个诊断会话后，同一位置仍可读取，原手机配对及接收时间均保留。退出时第一个诊断会话也成功关闭。证据为 `phone-upload-followup.after.json`。这些上报由真实手机发起，检查脚本没有上传数据。电量、应用活动及屏幕心跳当次没有接收记录，身体数据共享有效关闭，仍不能视为这些项目的真实验收通过。

## 手机建房接通

手机提示「V2 拓展未运行或此目标尚未获得建房授权」时，实际缺少内置 Together 的启用配置、安装状态、角色选择和当前私聊的建房授权。旧独立 Together 占用 6321；本次将 V2 的房间服务配置为 `127.0.0.1:6324`，手机仍通过原 6322 网关及统一房间代理访问。配置和授权经正式 V2 设置与能力仓库保存，仅为当前用户、账号、私聊会话和「星缘」角色启用 `together.room.create`。

启用后真实请求又暴露了 `host_persona_ambiguous`：当前「星缘-私聊」「星缘-群聊」合法地映射到同一 V2 角色，旧 `verified_persona()` 却通过角色反向查找并要求人格唯一。现在按当前 AstrBot 会话实际选中的人格查找，复核原账号、角色、会话、提示词和原生客户端；多人格共享角色不再被误拒。多目标的角色会话编号维持原格式，群聊由对应群适配器读取。

手机 `/status` 与 `/room/create` 区分功能未启用、当前目标缺少授权及服务启动失败。建房错误返回可诊断的 `code`；未知结果保留 `uncertain`，不得换新请求编号重放。失败日志仅记录错误码及异常类型。成功响应保留原手机客户端字段，并增加 `execution_path=v2_native`、能力、执行状态和原生操作回执。

2026-10-11 15:42:56 的本机检查通过配对后的手机网关真实调用 `/room/create`，得到 HTTP 200、`together.room.create`、`state=succeeded`、`effect=committed` 和 `together.native.operation:` 回执。由 6322 代理读取房间页面返回 HTTP 200、HTML；使用相同 `request_id` 再请求，URL 与操作编号均保持一致。检查沿用了 15:35 首次失败的请求编号，未改变身份重复创建。两个临时诊断会话均成功关闭。证据保存在 `D:/codex/artifacts/companion-v2-mobile-together-20261011/native-room-live-check.final.json`，不包含配对令牌、会话令牌或房间票据 URL。

检查工具默认仍只观察上传和读取摘要。显式增加 `--create-room call|watch|novel` 才会创建本用户的短期房间，`--request-id <原编号>` 用于继续核查同一个未确认请求。工具只从本机网关读取 HTML，不执行页面脚本或连接 WebSocket；本轮未验证进入房间后的媒体通话。15:35 的真实手机连接已收到活动摘要，重载后的建房检查尚未等到手机再次上报，因此本轮建房成功不能替代手机各类数据共享及音视频的现场验收。

## 旧手机建房协议兼容

16:04–16:05 的真实手机请求因 `mobile_request_id_required` 被拒。核对手机客户端 `GatewayClient.createRoom()`，实际请求只有 `mode` 与 `client=android_native`；此前带编号的诊断检查遗漏了这个协议差异。

V2 现在允许 `/room/create` 省略 `request_id`，由原生桥接在通过身份、当前人格及建房授权检查后保存一次稳定请求。相同用户和模式的连续点击、网络重试及重新配对复用原请求；已确认成功且票据仍可用的房间复用，确认过期、关闭、重载后内存票据丢失，或确认失败且未产生效果后才允许下一次创建。票据检查要求原生操作已确认成功，历史缺失不能触发替换。未知结果、异常和取消不替换请求编号；原上下文变化时拒绝将仍有效或未确认的请求转交新人格。状态保存于 V2 数据库，不保存手机令牌或房间链接。

成功和未确认回执均返回服务端选定的编号；手机提示改为可直接理解的“再点一次会继续检查这次请求”。新客户端仍可显式提供稳定编号；邀请与加入保持独立授权和原编号要求。检查工具增加 `--legacy-room-request`，按实际 Android 请求省略编号，同时核验返回的编号、操作和房间链接在重试时保持一致。

移动协议状态属于 `companion_v2/together/mobile/`。本次不修改原生房间提供方的行为、清单和指纹，保留已有操作身份及授权；兼容辅助文件不参与该未修改提供方的实现指纹，避免重载时误触发固定版本冲突。
