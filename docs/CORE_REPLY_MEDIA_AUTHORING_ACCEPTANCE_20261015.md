# 主链媒体生成修复验收（2026-10-15）

本记录对应此前的提示词、表情与索引修复。01:23 实聊随后仍出现纯文字，证明只验证无工具请求不足以覆盖实际现场；后续 2.1.24 的主链朗读格式补全与完整工具验证见 [TTS 运行链验收](CORE_REPLY_TTS_RUNTIME_ACCEPTANCE_20261015.md)。以下“不追加模型调用”是此前实现边界，已由新记录中的主链呈现补全取代。

## 真实故障

截图对应 `2026-10-15 00:05:57` 入站。平台返回了五条文字，没有启动 TTS 合成或表情检索。只读核对当轮生效配置：始终语音、模型标签、日语、中文译文、概率 1；角色图库启用且原件存在。原生会话保存的模型输出没有语音标签或表情意图。

原语音提示将始终语音仍表述为“可选”“没有合适内容就不用标签”，与旧人格的仅文字、需另行请求语音规则冲突。旧人格使用的 `<tts>` 也未被新解析器识别。上一包的消费与发送测试预先提供媒体标签，不能证明真实模型会生成协议。

修正提示后，真实模型可以生成语音片段，但多个试验仍遗漏表情意图。因此自动表情不能只依赖隐藏标签。另核对到当前角色有 119 张表情、116 张已有描述，向量却为零；真实 Embedding 返回 400，明确要求每批不得超过 10 条，原先批量 24 条导致索引建立失败。

## 修复

- 始终语音和应请求语音明确生成口语回应；语境选择仍可不用语音。尊重当轮明确只用文字的请求，不强制每轮发图，不通过追加对话模型调用补写格式。
- 人格决定身份、性格与措辞，本轮配置决定呈现。内部语音、表情格式由程序消费，与不向用户展示内部 JSON 的背景指令协调。
- 在所有请求 hook 完成后的 Agent 消息中统一落实本轮媒体指令，保留人格、其他插件资料、历史和工具。直接验证 SDK 实际主模型、备用模型与工具续答的请求；重复执行不增加协议块或内容部件。
- 兼容原始及 HTML 转义的 V1 `<tts>`；外语朗读与中文译文继续在分段前分离，禁用语音时也清理包装而保留文字。
- 非空表情意图继续按模型描述检索；明确空意图不附图；遗漏协议时，以本轮完整可见回复和用户原话作为语义材料检索角色图库，按配置进行语境视觉审核。外语朗读和内部标签不进入中文检索材料，不新增补写正文的模型请求。
- Embedding 遇到明确的批量上限拒绝后按确认上限拆批，保持原始顺序及全局索引；同一模型绑定后续复用该上限，模型改变后重新判断。鉴权、额度、普通参数错误不自动拆分重试，单项失败或不完整结果不返回部分向量。
- INFO 媒体诊断记录最终请求是否有指令、模型是否生成朗读片段或表情意图，区分明确不附图与协议缺失；保留合成与检索后续原因。实际请求的模式与布尔状态可持久保存，拒绝记录提示词、正文、API Key 或音频 Base64。
