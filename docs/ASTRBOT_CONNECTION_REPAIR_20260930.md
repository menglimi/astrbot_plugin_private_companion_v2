# AstrBot 接入流程修复

当前单目标 OneBot 运行档有有效的身份、配置读取和模型回复权限，但历史发送授权已撤销。普通启动正确返回 `authorization_revoked`；页面管理接口连通不能代表正在接管消息。

## 原因

- 设置向导先要求启动并查看草稿，原 OneBot 会话却在启动、接收时先要求发送授权，导致向导无法走到授权步骤。
- 草稿读取没有等待异步宿主接口，且把字典传给要求 `Outcome` 的呈现函数。
- 完成设置只签发授权，没有切换并启动实际发送会话。
- 设置进度把有效授权直接视为已连接，遗漏运行与入站接管状态。
- 在真实 Dashboard 启动草稿会话时，发现运行时的另一份旧版收据仍按完整装配和旧字段格式计算摘要。新版只校验身份，并补入新默认字段，导致同一运行档返回 `staging_profile_conflict`。按实际运行档的原字段格式复算后，与保留的旧收据完全一致。
- 向导启动失败时没有清空忙碌状态，导致「开始连接」一直禁用，无法重试。
- 继续真实启动时，发现可选提供方沿用相同包版本修改了能力声明，触发 `capability_descriptor_conflict` 并阻断整个本体启动。

## 实现

向导启动使用本地草稿会话，保持原运行档身份、指纹、发送绑定与撤销记录。该会话从装配时便使用本地 sender，并关闭平台在线状态端口；发放授权也不会把它变为平台 sender。普通启动的授权检查保持不变。

确认发送前，重新读取当前会话中已经查看的草稿；等待草稿会话完全停止，再通过原授权入口签发新授权，最后装配并启动实际发送会话。草稿保留未发送回执，连接后仅新入站消息产生真实发送。接入状态同时要求运行、接管、有效授权和实际发送模式。选择不发送会撤销已有发送授权，并继续本地运行。

预览运行档不能被向导静默改为发送运行档。页面及配置提示说明真实发送需在初始化前选择 OneBot 模式；已有 OneBot 运行档继续使用原 ID，不改记忆归属。

运行时收据兼容读取旧版完整装配摘要：使用当前已验证运行档的原字段集合恢复旧格式，只接受精确相符的摘要，并继续核对作用域、所属服务及完成状态。既有收据不重写，任意未知摘要仍拒绝。启动失败后恢复按钮，使同一向导可以重试。

可选提供方的目录声明冲突只阻止该拓展在本体中的调用。注册器保留原不可变声明和安装、启用、同意记录，并让当前声明与工具调用检查同时拒绝该提供方；其余目录和本体继续启动。小屋展示冲突原因，需提供方以新的包版本发布后再确认启用，不会自动续权或替换已批准的内容。

小屋管理目录和提供方状态不代表消息接管或模型工具可调用。页面分别显示「管理接口可用」与「提供方状态已读取」，不再把状态读取成功归为「可用」。六类能力的安装选择、角色启用和会话同意入口缺口仍见 `EXTENSION_CAPABILITY_AUDIT_20260930.md`，本修复未补齐这些入口。

## 验证范围

新增宿主回归覆盖：撤销后的草稿与重新连接、未查看不授权、有效授权下仍只预览、选择不发送、旧会话查看凭据失效、停止后不显示连接、API key 不能使用管理员向导。平台和模型使用本地替身，临时数据目录与 AstrBot 自带 Python；未读取 V1 数据，也没有重新授权实际运行档。

交付包构建后应从新包核对上述回归、普通启动/撤销/恢复合同和宿主入口加载、停机及路由注销，再在实际 Dashboard 核对管理接口、连接探测与向导状态。实际 QQ 回复需要由操作者完成一条输入及发送授权。
