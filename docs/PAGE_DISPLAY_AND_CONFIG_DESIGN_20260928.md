## 二、设计规则

- **R1 一个配置组只有一个「可写归属页」。** 其它页面最多放一张状态卡 + 跳转按钮；同一份设置不允许在两处各有控件（现状 `life`／`recall`／`screen` 等曾在两页并存，靠约定维持，不能再靠约定）。
- **R2 每页三段式。** ①**展示**：只读合同（状态、证据、回执、来源），说清数据从哪个 API 来；②**可配置**：组 → 字段 → 作用域 → 生效方式 → 路由；③**边界**：没有合同的部分按 `boundaryCard`（由谁保存 / 现在能做什么 / 下一步），不放假控件。
- **R3 作用域决定前置上下文。** `window` 级必须先选定「对象 + 角色」；`role` 级只需角色；`installation` 级不需要。缺上下文时整页一条引导（`pageNeedsTarget`），不让每个挂载点各渲染一遍空态。
- **R4 状态由合同推导，不手写。** 「已接入 / 部分接入 / 待接入」按后端是否真有读写路由与字段判定；页面不因为"看起来该有"就标注已接入。
- **R5 分区编号唯一且不跨页复用。** 编号表示**概念分区**（A 感知接入 / B 角色内核 / C 产出 / D 投递 / E 治理 / L 学习与反思）。一个分区只有一个「持有控件的主页面」，引用页只显示状态卡并注明「控件在 X 页」。
- **R6 生效方式要写在控件旁。** 立即生效（`immediate`）与下一轮生效（`next_task`）不能混在一句说明里；窗口级设置在切换对象时不携带草稿。

## 三、逐页设计

> 每页给：职责 / 展示什么 / 可配置什么 / 待接 / 边界。**「可配置」列为设计目标**，标注 `已接`＝今天就有控件。

### 3.1 小屋（`life/home`）

- **职责**：只读总览。回答「她现在怎么样、今天发生了什么、有哪些能力在用」。
- **展示**：体素小屋与家具目录（14 项）；当前生活快照（心情、心理能量、身体、睡眠、饥饿、位置）；今日日程；今日记录四视图（日记梦境 / 生活轨迹 / 状态变化 / 交互影响）；便签与提醒计数；记忆概况（经历数、计划数、最近来源）；能力接入状态。
- **数据来源**：`/page/targets`（对象、角色、模式）、`/state`（状态与日历）、`/life`（日记与执行记录）、`/memory`（事实与经历）、`/integration`（能力目录）、脱敏配置快照（能力开关）。
- **可配置**：无。唯一可写项是「布置房间」——按角色保存在浏览器的显示偏好，明确标注它不写业务配置。
- **边界**：没有查询合同的（主动候选池、用量与余额、见闻记录）只给空态与跳转，不推算。

### 3.2 日程（`life/schedule`）

- **职责**：看时间线上"已定下的事"与"实际进展"。
- **展示**：Calendar 计划、已接受约定、独立提醒、进行中活动；计划与进展分开呈现；每条带状态与来源。
- **可配置**：无独立配置组；新增/改期/取消走日历编辑器（`calendar-editor.js`），提醒不被普通联系暂停吞掉。
- **待接**：完整 Calendar 的重复规则与改期回执（合同未定，页面只说明）。

### 3.3 日记（`life/diary`）

- **职责**：日记、梦境、阅读、睡眠、执行记录的工作台。
- **展示**：四个视图（日记与梦境 / 阅读书架 / 睡眠记录 / 执行记录）、原文与来源范围、已知失败的显式重试。
- **可配置（设计变更）**：`role.life` **23 项**应在这一页：写作偏好（风格、梦境题材、混合与余韵）、作息（日记时刻、时区、睡眠开关/时刻/时长——四个 `sleep_*` 为角色共享）、阅读与衍生、休息时段回复判定、补看材料。当前挂在「自我 B3」，按 R1 迁到这里（自我只保留状态与身体）。
- **边界**：梦境不等于现实事实；执行记录来自任务账本，不做推算。

### 3.4 人物与关系（`people`）

- **职责**：按人看「她认得谁、关系怎样、最近有哪些理解被采用」。
- **展示**：关系工作区（`pages/关系与记忆`）——待审阅的关系理解、采用、更正、撤回；相识目录（跨群与私聊同一人）；群与私聊分开。
- **可配置**：`person` 2 项（熟人卡开关、卡片字数上限）落在记忆与经历 B1；本页只读。
- **边界**：身份归并、成员目录筛选等未接部分只说明。

### 3.5 记忆与经历 · 浏览（`memories`）

- **职责**：事实、经历、原文与来源、修订与遗忘的治理工作台（六个视图，8 秒自动刷新）。
- **展示**：事实列表与修订、钉选/取消、纠正与遗忘、范围清理预览、来源检索与原文复核、冷归档与迁移、反思失败恢复。
- **可配置**：不在本页；策略在「记忆与经历 · 设置」（B1）。
- **边界**：不同主体、Bot、角色之间不共享；来源与授权逐次复核。

### 3.6 感知（`manage/perception`，A 段）

- **职责**：角色**能得到**什么信息。
- **展示**：A1 身边环境（地点/时区/天气/年度日历）、A2 对话里的信息（消息、引用、转发、语音、图片视频；语义与黑话）、A3 屏幕与设备（识屏解读、提供方接入状态）、A4 外部资讯（新闻与检索）。
- **可配置**：`conversation.perception` 9 项（已接，A1/A4）、`knowledge` 14 项（已接，A1）、`screen` 3 项（已接，A3）、语义与黑话（`/semantic`）、天气时效（A1）。
- **待接**：`context_image_caption*`（上下文图片描述，2 项）应从表达页移到这里（A2）——它决定"图片变成文字材料"这件事，属感知；对应模型档 `model.conversation.context_image_caption` 留在模型页。
- **边界**：识屏与设备观察是否进入对话以能力目录的接入状态为准；识图用哪个模型在模型与连接指派。

### 3.7 决策（`manage/decision`，B 段）

- **职责**：角色**怎么判断**——记什么、在意谁、什么时候开口。
- **展示**：B1 认知与记忆（统一记忆策略工作台）、B2 关系与情感（关系理解审阅，跳转工作区）、B3 角色自我（状态工作区）、B4 决策与主动（行为规划与沉默）、B5 群聊参与。
- **可配置**：
  - B1：`memory` 30 项（已接）、`person` 2 项（已接）；
  - B3：`role.state` 61 项（已接 51 + 10 有意不接）；
  - B4：**只放引用卡**（控件在主动与联系页）——同一个 contact 段今天在决策页与主动与联系页各挂一次，按 R1 收敛为一处；
  - B5：`conversation.group_participation` 20 项（已接）。
- **待接（B5，共 31 项，都在 `conversation.presentation` 组里）**：群唤醒一整套 `group_wakeup_*` **24 项**（触发关键词、兴趣与图片权重、冷却与疲劳、冷群判定、主要成员、日志上限……）、群冷场守卫 `group_air_guard_*` 4 项、三条群安全闸 `enable_group_{injection,privacy,reality_promise}_guard` 3 项。它们决定"在群里怎么判断"，与 `conversation.group_participation` 同页。
- **边界**：主动候选池、群内反馈统计没有查询合同，不展示推算值。

### 3.8 行动（`manage/action`，C 段）

- **职责**：除回复以外的行为——共处、游玩、现实设备、社交发布。
- **展示**：能力提供方接入状态（Together / Game / Reality / Live）、执行是否可用的原因、提供方页面入口。
- **可配置**：无自有组（各能力提供方自持配置）。
- **边界**：C4 社交发布没有写入合同，只给说明；不因没有控件的页面缺少内容而放假开关。

### 3.9 产出（`manage/output`，C 段）

- **职责**：角色**产出**的东西——画面与作品。
- **展示**：C1 图像生成（生成与参考素材的提供方状态、已有相册）、C2 创作与作品（原稿、版本、封面、提供方状态）。
- **可配置**：`conversation.media_quota` 4 项、`conversation.image_review` 11 项、`photo.reference` 3 项、`wardrobe` 6 项（均已接）。
- **待接（C2）**：`content.authoring` 5 项（创作总闸、方向提示、正文上限、候选数、封面张数）+ 封面相关字段；需要先补一条 `/config` 分区（编辑器与页面声明都还没有）。
- **边界**：生图参数（尺寸、步数、并发）归提供方，不在本页放假控件。

### 3.10 表达（`manage/expression`，D 段）

- **职责**：角色**怎么说话**——文字形态、语音、表情、投递方式。
- **展示**：D1 文本形态与注入（分段预演，不调用模型）、D2 语音（与分段共用设置）、D3 表情与配图（检索与视觉复核状态）、D4 撤回与平台动作、D5 时机与编排（跳转主动与联系）。
- **可配置**：`conversation.presentation` 已接的 32 项、`expression.reaction` 9 项、`conversation.recall` 4 项。
- **待接（本页 21 项，都在 `conversation.presentation` 组里）**：
  - D1 文本形态与注入：`content_cleanup_*` 5 + `content_replacements` / `content_replacement_enabled`（内容清理与替换，共 7）、`framework_error_guard_enabled`、禁用词召回 `enable_forbidden_word_recall` + `recall_forbidden_*` 3、`component_order`（组件顺序）、引用呈现 `reply_quote_*` 4 + `reply_mention_speaker_enabled`、分段规则 `split_words` / `match_width_variants` / `rule_regex`。
  - D2 语音：`voice_*` 10 项已有控件（在回复页的语音分区），本页只做归位与说明。
  - D4 撤回：`conversation.recall` 4 项已接，无待接。
- **边界**：戳一戳与群投递由宿主执行，没有动作开关；语音音色归 TTS 提供方。

### 3.11 自我（`manage/governance`，E 段）

- **职责**：角色自己的设定与世界知识。
- **展示**：E1 关系与权限（跳转）、E2 模型分配（跳转）、E3 内容风控（现状说明）、E4 资源与预算、E5 存储与部署（跳转）。

### 3.12 关系与权限（`manage/identity`）

- **职责**：身份、人格绑定、三档权限、相识目录。
- **展示**：身份工作区（`pages/关系与权限`）——角色与人格绑定（只读）、授权对象、相识目录按人沉淀。
- **可配置**：无自有组（授权写入由宿主与对象访问策略承担，页面只读）。
- **边界**：旧身份归并需要单独协议，本页不提供。

### 3.13 主动与联系（`manage/contact`）

- **职责**：**她什么时候来找我**——主动联系与开口时机设置。当前 `proactive.contact` 有 160 项，另有 `conversation.busy_gate` 7 项。
- **展示**：节律盘、消息测试、契机矩阵、开口闸门、额度与去重、外部触发源六个工作视图；显示当前配置与服务实际返回的状态，不推算下一次联系内容。
- **可配置**：160 项 `proactive.contact` 通过唯一配置合同编辑；忙碌回复延迟与恢复通过 `conversation.busy_gate` 编辑；休息时回复判定及醒后补看跳转到日记与生活工作区的对应设置。字段有安装、角色、关系和窗口层级，关系预算不能在窗口层修改。
- **边界**：候选池与完整执行历史没有查询合同，不展示虚构的下一条联系、候选队列或发送状态。

### 3.14 记忆与经历 · 设置（`manage/memory`，B1）

- **职责**：统一记忆策略（启停、注入上限、定时整理、经历与习惯阈值、反思）。
- **展示**：策略工作台（`memory-settings-section.js`）；反思调度状态；跳转到治理工作台。
- **可配置**：**不在本页**。策略控件唯一归「决策 B1」，本页只放一张引用卡（避免同一份设置两处各有一份）。
- **边界**：事实正文与来源不在本页编辑（在治理工作台），避免两处各有一份。

### 3.15 学习与反思（`manage/learning`，L 段）

- **可配置**：`expression.learning` 10 项、`library` 12 项、`role.growth` 2 项（均已接）；成长提案工作区（原 `growth` 页签）并入 L1 作为「目标与成长」子区。
- **待接**：表达候选的审阅列表控件（当前只有入口）；反思调度节奏与窗口（可配置化）；私聊片段与"到期才刷新"游标。
- **边界**：黑话没有采纳/排除词表；梦境压实仍是设计稿，不标注为可用。

### 3.16 模型与连接（`manage/models`）

- **职责**：任务 × Provider 路由矩阵、语音与画面后端、测试。
- **展示**：15 个任务档（对话、判官、反思、整理、日记、阅读、创作、审稿、识屏、配图描述、图像审核……）各自的主/备 Provider、输出上限、超时、替换规则；Provider 测试结果（测试与保存分开，查看不自动调用模型）。
- **可配置**：`model.*` 全部（已接）、`model.budget` 2 项（已接，随模型页读）。
- **边界**：凭据、Cookie、Provider ID 不回显。

### 3.17 治理与维护（`manage/maintenance`）

- **职责**：预算、用量、排障、运行状态入口。
- **展示**：E4 资源与预算（每日软限额）、宿主运行状态入口、用量与余额（**没有聚合接口 → 只说明**）、诊断与修复建议（未接）。
- **可配置**：`model.budget` 2 项（已接）。
- **待接**：用量聚合与成本（后端合同）；诊断工作台（问题 → 检查项 → 证据 → 建议 → 执行结果）。
- **边界**：不展示编造的费用曲线。

### 3.18 开始使用（`manage/setup`）

- **职责**：首次使用引导：探测 → 选对象 → 初始化 → 收一条真实消息 → 读草稿 → 决定是否允许真实发送。
- **展示**：每一步的当前状态与阻断原因；review 步骤展示真实草稿（只读预览，不额外调用模型）。
- **可配置**：无配置组；它写的是授权与生命周期（`/setup/*` 6 条路由 + `/initialize`、`/authorize-delivery`）。
- **边界**：没有"看过一条回复"就不允许开启真实发送；连接与断开都要留回执。

### 3.19 外观与设置（`manage/appearance`）

- **职责**：拓展页自身的显示方式（主题、显示维度、房间布置）。
- **展示**：外观面板；说明它只影响本浏览器。
- **可配置**：无业务配置组（浏览器本地）。
- **边界**：不写角色资料、不影响消息发送。

### 3.20 宿主管理（`manage/host`）

- **职责**：宿主生命周期——探测、初始化、启停、投递授权、备份入口。
- **展示**：运行状态、会话与投递授权、最近失败（含脱敏后的模型失败分类）、路由注册状态。
- **可配置**：无配置组；写的是 `staging/*` 11 条控制路由（或 `host/*` 多目标路由）。
- **边界**：启停会真实改变入站消息的处理方，属于管理员操作，不与日常按钮混排。

### 3.21 资料与维护（`manage/data`）

- **职责**：入口汇集与安装级操作：备份与还原、导出、重置、宿主跳转。
- **展示**：备份（预览 → 确认 → 回执）、多目标模式下明确说明备份接口未注册。
- **可配置**：无配置组。
- **边界**：备份是安装级合同，不针对单个关系。

## 六、验收口径（每页通用）

- **可达**：控件在页面上真实渲染，且不在两个页面各有一份（R1/R5）。
- **准确**：`scope` 与 `layers` 由后端下发，页面不写死范围；窗口级设置在切换对象后不携带旧草稿与迟到响应。
- **可写**：保存走 `ConfigurationService.patch`，有回执、有幂等、有版本冲突提示。
- **可读**：保存后立即回读一致；只读展示必须来自真实合同，没有合同就明说。
- **无裸码**：失败一律翻译成人话；确有原因句时原样保留。
- **可复核**：`audit_page_config_coverage.py`（声明覆盖）、`build_v2_inventory.py`（注册面）、`build/tmp/audit_config_consumers.py`（消费端交叉核对）、页面契约 cjs 测试。
