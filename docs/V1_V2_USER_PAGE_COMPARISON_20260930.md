# V1 的「用户」页 vs V2 关系页下的「用户」（2026-09-30 基线，2026-10-01 复核）

对象：**V1 陪伴面板 → 04 用户（`panel-private`）** 与 **V2 关系与权限工作区里的用户/相识**。
只比用户能看见、能改的东西。方法：读两侧源码（V1 `pages/陪伴面板/{index.html,app.js}`、
V2 `pages/关系与权限/*` ＋ `astrbot_host/acquaintance_api.py` ＋ `companion_v2/memory/person/*`），
按同一口径分类。

## 2026-10-01 复核更新

本文主体保留 2026-09-30 的只读页面基线。此后 V2 已增加两类按人写入，因此“只有 GET 路由”“0 项写操作”“整页只读”和“约 9%”不再是当前结论：

- **管理员称呼**：关系页可设置或清除管理员称呼，覆盖显示名但不改平台资料。服务校验当前 Bot/角色目录、主体、原生账号、卡片 revision 和操作账本。
- **按人授权**：关系页可查看并调整 `conversation.reply`、`message.delivery`、`proactive.contact` 三类页面管理能力；不可编辑的运行档授权会显示真实状态和管理位置。
- 当前用户工作区因此有两个写入面、四个可编辑值（一个管理员称呼和三类能力授权）。它们不等同于 V1 的关系档案字段；语气、主要/次要关系角色、好感度、身份合并、画像模式及诊断仍有差距。

实现记录见 [管理员称呼切片](CORE_PERSON_ADMIN_NICKNAME_20261001.md)；授权路由与权限页面位于 `astrbot_host/acquaintance_api.py` 和 `pages/关系与权限/`。

## 三、量化的差

| 指标 | V1 | V2 |
| --- | --- | --- |
| 每个用户的字段/标签 | **约 176**（六页签区域内的中文字段与文案，实测去重） | **约 15** |
| 用户级写操作 | **≥ 10**（`/user/update` 十余字段 ＋ 身份关联/解绑/审核三条 ＋ 列表级新增与归并） | **2 类入口 / 4 个可编辑值**（管理员称呼 + 3 类页面管理授权；不与 V1 写操作逐项等价） |
| 每用户页签 | 6 | 1 |
| 用户级配置字段 | 多组（称呼/语气/画像/主动/关系/好感度） | **2**（相识开关、印象卡字数） |

原“15 / 176”与“0 / ≥10”是 2026-09-30 页面基线，本次不沿用作当前覆盖率。V2 新增写入仍只覆盖称呼与能力授权，不代表 V1 关系管理字段已迁移。

## 四、别误判成"缺失"的部分（V2 换了位置或机制）

| V1 在那个页面做的事 | V2 现在在哪 |
| --- | --- |
| 主动权限（per-user 开关） | 投递授权（grant，按作用域/受众）＋ `proactive.contact` 的四层配置（安装/角色/关系/窗口） |
| 关系记忆的编辑 | 角色工具 `relationship.memory.read/propose/revise/review/adopt/retract`——由角色在对话里走审阅流程，而不是管理员在页面上填 |
| 群内风控（黑屋、审核） | `group_member_safety`（群成员风控，另有字段），不在这张页上 |
| 身份别名 | V2 用 `ScopeRef`/`SubjectRef` 派生身份；**没有**人工归并入口（真实差异，不是"换了位置"） |

## 五、结论与建议

- **结论**：V2 关系页下的用户现在是**相识档案加有限管理入口**——可维护管理员称呼和三类页面管理授权，也能查看计数、时间、阶段与窗口分布；V1 用户页仍提供更宽的关系、记忆、诊断与身份操作面。
- 值得补的（按用户价值）：
  1. **语气与关系角色**（主要/次要用户）仍无按人编辑入口；
  2. **画像/记忆模式**（关闭 / 仅用已有 / 持续学习）与 Memory 连接状态；
  3. **关系与诊断细节**（当前互动、回复温度、最近错误、路线来源）；
  4. **身份归并**：两个平台账号属于同一个人时，V2 仍没有人工合并入口，需要独立定义归属与撤销规则。
- 不建议照搬的：黑屋/人工审核（V2 有群成员风控，位置不同）、P4 安全回复保护（V2 的对应机制在表达/审核组里）。
