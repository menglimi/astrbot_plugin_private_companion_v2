## 1. 权限与对象归属

[ObjectAccessPolicy](../companion_v2/identity_policy/object_access.py)提供安装级身份等级、对象登记、精确动作共享、撤回/过期及当前身份复核。身份等级独立持久保存，旧能力授权携带的 tier 不会自动提升安装级身份。

| 身份 | 功能开放 | 对象范围 |
| --- | --- | --- |
| 核心 | 当前注册的管理动作 | 同一安装内的已登记对象；代办保留原对象归属和实际操作者。 |
| 重要 | 当前注册的非核心动作 | 本人对象，或明确共享了该动作的对象。 |
| 普通 | 仍需精确功能授权 | 在功能已开放的前提下，访问本人对象或明确共享的对象。 |

当前动作目录覆盖便签、提醒、原操作查询和权限管理动作声明。未知动作拒绝执行；该目录不表示所有领域已经接入此策略。身份等级和对象分享的写接口供可信控制层使用，尚不是经过身份认证的页面/API 管理入口。

[AgendaService](../companion_v2/agenda/service.py)沿共同事务登记便签、提醒及操作对象。创建者、资料主体、所属角色、提醒接收者和本次操作者分别保留；共享编辑不会夺取归属，操作回执归实际操作者。核心用户可管理原角色留下的对象，但到期执行仍复核原目标角色绑定和原请求者当前权限。

列表先检查功能开放，再按 read 动作确定可见对象，在搜索、排序和分页前过滤。共享只读不等于允许修改；群窗口不会自动向全群共享个人对象。当前共享面向既有对象，尚无共享容器内创建和完整跨窗口个人资料查询。可见对象键仍先枚举再参与 SQL 过滤，尚无海量对象查询性能证据。

## 2. 原角色工具续答

[AgendaRoleSession](../companion_v2/conversation/agenda_tools.py)固定宿主提供的原事件、调用者、角色绑定、目标和受众。模型只填写业务参数，不能通过工具参数替换身份、归属、角色或收件人。时间使用显式日期/时区结构，不用关键词代替模型理解用户意图。

- 暴露便签创建、读取、列表、编辑、完成/恢复、置顶，以及提醒创建、读取、列表、取消/改期和原操作查询。删除意图流程尚未接入，因此没有暴露 `delete.commit`；也不暴露内部到期执行或权限管理写接口。
- 工具调用使用稳定操作标识，同一调用重试恢复原结果；复用标识但改变参数会报冲突。新建本地会话后也可从持久操作结果恢复已完成的业务操作。
- 续答沿原事件、角色指令和上下文，追加真实工具结果及表达说明，调用所提供模型端口一次。没有额外分类器或办事人格，也没有独立发送器。
- 续答前后使用当前时钟重新核验账号、角色、原来源和工具材料。读取结果发生修订、撤权或过期时，不把新正文悄悄顶替原材料；生成期间失效则不返回草稿。
- 保存回执保留该次操作的历史事实，因此同轮创建后再编辑可以正常续答；提示明确较早回执不代表对象当前状态。完成操作也不证明用户真的做过对应现实活动。
- 私密正文只交给调用者本人私聊受众。群聊或多收件人只得到需要私密入口的结构化结果，不向模型提供私密正文，也不声称已经另发私信。实际私密路由仍待接入。

提示分别说明 `saved`、`local_registered`、`local_prepared` 和 `delivery=not_started`；失败可继续自然聊天，但不能编造成功。这里仅证明本地端口保留原角色输入并传递真实结果，没有真实模型的表达质量或语义效果测量。

## 3. 存储升级与恢复

内部数据库增加 `storage.v4 -> v5` 显式迁移，保存权限版本、主体等级、对象登记和动作分享；历史迁移 DDL/指纹保持原值。非空 v4 夹具升级后，便签归属、修订、重复期次及已领取提醒保持原值，并能继续准备原提醒。

首次组装 AgendaService 时，从原领域记录和原操作作者登记已有对象，在同一事务写入完成标记；不根据当前调用者或新绑定角色重新认领。以后组装只检查标记，不每轮全表扫描。新建对象在业务事务内同步登记。

这些是 V2 自身格式升级，不是 V1 用户数据自动迁移。身份等级、共享和提醒准备已验证重开数据库恢复；本地会话及模型执行任务的恢复仍待公共任务层。
