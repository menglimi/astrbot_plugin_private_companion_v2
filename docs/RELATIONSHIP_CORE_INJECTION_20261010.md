# 关系网迁移与普通回复描述注入修复

2026-10-10。修复范围为迁移资料到 AstrBot 普通回复请求的连接，保留同轮关系页先显示本地数据、后台补全目录的修改。

## 实际数据与故障位置

只读检查当前使用的 V2 profile 数据库。三个历史群均有关系网导入记录，当前合计 713 个成员节点、386 条互动边；这些当前总量包含后续观察形成的记录。知识目录另保存 167 份带账号和正文的群成员描述（88、74、5 份），以及群知识和通用知识。三个群的资料绑定均包括角色、群号及平台／Bot／登录账号路径。

`knowledge.member_recognition_enabled` 已启用。最近群回复的原生观测包含 `group_network` 和 `person_card`，却没有知识或成员描述材料：新版 `build_core_reply_prompt()` 没有调用已经装配好的 knowledge owner。关系图只包含名称、次数和互动边，因此迁移后的描述虽已保存，普通回复仍看不到它们。旧成员提示还将描述限为称呼线索，未指导模型参考相处内容。

用修复后的领域选择 API 对最近 30 个群回复上下文做只读核对，不发布生产来源：其中 17 个上下文按当前认证账号可选出成员描述，13 个没有可匹配描述。该核对只证明已有资料可被选出，实际运行中的请求注入需在重载后观察。

## 修改行为

- 普通私聊和群聊分别选择本地知识与成员描述，复用 knowledge owner 的有效配置、归属过滤、预算和来源发布；使用本轮原话，不以当前用户名或人格提示冒充成员匹配依据。
- 两种材料独立降级，并分别记录 `knowledge_reference`、`knowledge_member_clue` 的状态、字数与耗时。AstrBot 请求确实包含补充背景后，原生观测才将它们标为已注入。
- 本地知识读取不再次调用 AstrBot 官方知识库候选读取器；官方知识库继续沿宿主普通回复流程使用。
- 按认证账号归属的描述可用于自然延续偏好、相处方式和已记录经历；仅在原话中提及的唯一名称归属被提及者。歧义名称和重复账号不猜对象。描述不提供认证或权限，也不替代当前发言。
- 补齐成员条目的群类型和逐条群号过滤，避免群限定描述进入私聊或其他群。已有按角色、平台、Bot、登录账号的过滤继续生效，撤回来源不再进入下一轮。
- 唯一「陪伴小屋」继续使用原 knowledge 配置合同，更新成员资料的说明和本轮总字数标签。没有增加页面、注册实体或配置字段。
