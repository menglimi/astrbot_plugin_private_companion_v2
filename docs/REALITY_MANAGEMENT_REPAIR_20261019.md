# 现实设备管理页修复（2026-10-19）

## 已核实的问题

- 摄像头独立授权和策略已经持久保存，但管理快照的用户筛选只考虑私聊路由、音频与叫醒字段，遗漏仅有摄像头记录的用户，页面因此显示未确认并退回默认策略。
- 管理接口错误响应将机器码只放在 `data.code`。AstrBot 页面桥拒绝请求时只转发 `message`，具体错误丢失后被页面显示为“数据不完整”。
- 米家 SDK `mijiaAPI` 未列入依赖，重装后运行时无法初始化；页面仍误报为尚未登录。此问题与摄像头授权独立。
- 刷新管理状态时自动保存默认摄像头草稿，会遮挡后端新读到的已保存策略。

## 修复

- 管理快照包含摄像头独立授权和策略记录，沿用原有授权校验及撤销行为。
- 接口在 `message` 和 `data.code` 同时返回稳定错误码；页面明确解释缺少授权、用户无权限和米家运行时不可用等原因。
- 米家运行时不可用时返回明确状态和原因；页面区分未读取、不可用和未登录状态。
- 只有真正改动的摄像头策略保留为草稿，普通刷新显示后端最新保存值。
- 声明 `mijiaAPI==4.1.3`、`fastmcp==3.4.2` 和 `mcp>=1.26,<2`，兼容当前 AstrBot 的 MCP v1 环境。

## 验证范围

- `test_native_extension_api` 覆盖独立摄像头记录、保存、磁盘重载、撤销、身份拒绝及米家不可用。
- `native_management_contract_process` 在临时 AstrBot 数据根生成真实接口回执；`test_native_extension_management_bridge.cjs` 通过安装的 AstrBot 页面 SDK 与真实产品请求层验证回执、错误和刷新，未用成功结果替换产品请求实现。
- `test_native_extension_panel` 覆盖管理控件和草稿；摄像头目录断言限定为设备列表，避免与测试按钮同名冲突。
- 宿主路由测试采用统一注册名 `astrbot_plugin_private_companion`，包含停机和路由注销。
- 最终交付包的哈希、测试结果与重载验证见发布目录的验收记录。设备验证使用模拟实现，未执行真实拍摄、音频播放或米家登录。
