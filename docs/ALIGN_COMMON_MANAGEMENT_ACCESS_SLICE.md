# ALIGN-02：配置与能力管理共用权限

日期：2026-09-21。接续[人格解析与旧范围映射](ALIGN_PERSONA_RESOLUTION_AND_LEGACY_MAPPING_SLICE.md)。本轮将已有安装级身份策略接到配置与能力管理服务，完成可供页面、命令、工具复用的本地调用合同；尚未注册真实管理页面或 AstrBot 命令。

## 1. 配置采用当前安装身份

[公共权限](../companion_v2/identity_policy/object_access.py)新增有明确动作定义的配置/能力权限，以及受限定范围的 `scope_access`。身份等级来自当前持久 `subject_access_tiers`；旧功能 grant 的 `tier=CORE` 仍不提升安装身份。

| 操作者 | 配置与范围权限 |
| --- | --- |
| CORE | 在本安装内管理明确选择的配置目标，包括窗口当前已切到别的人格时的历史人格配置；仍核验真实账号绑定和目标安装。 |
| IMPORTANT | 可管理可信路由登记给自己的私聊偏好；其他私聊、群聊、角色全局或安装配置需明确的动作/范围授权。 |
| STANDARD | 每个动作都需精确范围的功能授权；不会因返回了字段定义或看见家具而获得写权限。 |
| 任意非 CORE | 不能凭普通 grant 进入声明为 `core_only` 的配置组。 |

字段注册新增 `core_only`；一个组必须具有一致的权限分类，防止一起读取时带出核心设置。实际本体字段注册时须逐组标明核心管理/普通偏好，本轮不把所有配置统一硬锁成管理员专用。

[配置服务](../companion_v2/configuration/service.py)的读取、差异保存、变更游标、操作查账和消费者采用回执都经过相同策略。编辑 token 同时包含身份策略与对象策略 revision；降级、撤权或换绑后，旧页面及迟到采用报告不能继续生效。保存权限仍不等于消费者已采用。

窗口角色复核使用 PersonaDirectory。核心用户按明确目标管理其他人格不意味着模型可以换角色续答：对话与工具仍受原事件人格快照约束。私聊 owner 来自已登记 `ConversationRoute`，不从调用参数或“最近聊天用户”猜测；没有可信 owner 的旧范围仍需明确授权。

## 2. 能力管理共用一个服务

[CapabilityManagementService](../companion_v2/capabilities/management.py)提供固定包选择、版本换新、暂停/恢复、请求丢弃、指定 Bot/角色启用、个人范围同意及授权投影。

- 获取/换新/全局暂停/恢复/丢弃请求和角色全局启用属于 CORE 管理动作。
- 个人同意检查本人身份或 CORE 明确管理；IMPORTANT 不能给别人代签，STANDARD 仍需该动作的精确开放。
- 同意、角色启用、资料读权限和包选择分别核验，任何一项不会顺带建立另一项。
- 包选择绑定目录里的 package/version/artifact hash；请求参数改变不能套用同一操作号。
- 权限检查、原操作预留、Repository 变更和完成回执在同一个本地事务内。失败全部回滚；重试只恢复原操作，暂停后重试“获取”不会重新启用。
- 回执仅标记 `local_record_saved`。请求丢弃只记录 `discard_requested`；没有实际卸载证据的调用不能确认已经删除家具对应的运行资源。

Screen 的主动开关与竞争权重仍通过 `CapabilityConfigurationOwner` 调用公共配置服务，沿用原 `capability_settings` 正本；没有增添第二份开关或另建一条写设置入口。权重仍只供可行念头竞争，不参与能力准入或来源读权限。
