# QQ 展示设置与日程公开文案编辑

日期：2026-09-25

## 已实现

“陪伴小屋 → 管理与设置 → 角色状态”可以编辑正在输入提示开关、1–10 秒刷新间隔及 QQ 自定义短状态开关，并修改已有角色计划的公开文案。保存后重新读取现有诊断区，显示实际配置、授权条件、待展示文案与历史平台回执。配置保存成功不等于平台已受理，更不等于客户端持续显示。

配置表单仅提交用户改动的字段，并携带开始编辑时的配置版本。并发修改会保留草稿；用户显式读取当前版本后，已编辑字段继续保留，未编辑字段采用当前值，再由用户核对保存。日程文案同样使用原 revision / view_token，不自动覆盖并发更新。读取版本遇到网络失败时保留内存草稿，刷新成功后可以继续；授权失效或切换目标会清空当前编辑视图。

公开文案使用新增的 `calendar.presence` 窄命令，仅接受现有、未取消的 `role_plan` 和 `data: {presence: string}`。沿用最多 8 字的合同，可留空；不修改标题、详情、时间、时长、接受状态、日程例外、来源和原提醒。更新仍记录管理操作者、版本及幂等回执，写入前复核原来源权限。留空表示该日程不提供公开文案，角色模拟仍可能提供后备文案，也不承诺清除无法确认归属的手工 QQ 状态。

页面支持日程分页。所有保存请求固定原安装、管理者、目标 API 路径和完整请求体；选择其他对象或角色后，旧响应不能覆盖新页面。页面内选择与小屋公共对象/角色选择保持同步。

请求结果不明时，原请求保存在当前标签页的 `sessionStorage`，并有内存后备；不保存私人日程标题或详情。重新挂载或刷新页面不会自动 POST，只显示待核对项。用户可显式使用相同 operation key、版本和请求体核对回执，或结束核对；结束核对不会撤销已经完成的保存。正常未提交草稿只在当前挂载的编辑器内保存，不承诺关闭页面后的草稿恢复。

## 目录与边界

- `companion_v2/agenda/calendar.py`：公开文案专用命令，保留原提醒与来源。
- `astrbot_host/state_api.py`：认证入口的命令字段白名单，拒绝目标、操作者和来源覆盖。
- `pages/陪伴小屋/state-editor.js`：表单、版本冲突、原请求核对与作用域隔离。
- `pages/陪伴小屋/state-page.js` / `state-page.css`：现有状态页集成、分页、轮询暂停和响应式布局。
- `tools/check_state_editor.cjs`：由 `check_state_page.cjs` 调用的编辑验收场景。

页面修改配置和领域记录，不直接调用 QQ 展示端口。运行中的宿主继续根据原授权、日程和去重规则决定平台动作。未增加数据表或 schema 迁移，未读取、迁移或修改 V1 用户数据。

V2 `pages/陪伴小屋/` 为规范页面源，构建工具生成嵌入工作区与资源清单；Content 页面仅为可选预览。本批不发布 Content 镜像，也不使用旧 Content 外壳覆盖 V2。
