# V2 真实环境验收任务表

日期：2026-09-26。对象仅为 `astrbot_plugin_private_companion_v2` 及其七个可选 V2 原生提供方。此表用于**功能和交付包完成后**逐项现场验收；目前表中没有一项因 SDK、模型替身、本地 OneBot ACK、浏览器夹具或单次离线截图而标为通过。早期记录见[整合验收](INTEGRATION_ACCEPTANCE_V2_0.md)、[多目标现场清单](CORE_MULTI_TARGET_LIVE_ACCEPTANCE_20260924.md)和[构建状态](BUILD_STATUS.md)。

## 执行约定

1. 使用最终待交付 ZIP、AstrBot 4.27.2、实际 OneBot/NapCat、真实模型和所测能力对应的真实服务。先核对安装包与源码版本，再在测试账号运行。V2 使用独立数据根；不读取、迁移或修改 V1 用户数据。同一 QQ 目标在测试期间只由一个版本接管。
2. 备好测试 Bot A、测试用户 A，必要时增加 Bot B、用户 B、两个角色、一个至少两名成员的测试群。先在未启动的正式配置下完成探测、初始化和绑定核对，再只连接当前测试目标；真实投递固定为 `onebot_private`，不设置长时或“十年”授权。提供方权限按当前角色、会话和动作分别开通；设备控制、直播发布等外部副作用只用可控测试对象。
3. 表中「已接线」只指截至本日文档/源码已有生产链，**不是实机已通过**；「待补齐」须先实现并更新交付包才进入现场验收；「依赖事件」须等真实外部事件；「受控注入」只在可隔离的测试环境模拟传输故障，不靠反复真实发送碰运气。功能范围后续变化时先更新本表的准入栏。
4. 每行初始结果为「待测」。执行后改为「通过」「失败」「阻塞」或「不适用」，在最后一栏填日期、脱敏证据链接/操作 ID、问题编号和必要的提供方/客户端版本。失败保留原回执，修复后用新轮次复测；未知操作只查询原 ID，不擅自换 ID 重发。截图、日志和表格都不写账号明文、令牌、私人正文或设备凭据。
5. 可在同一次实机对话内完成多行组合验收，按行分别记录结果即可。推荐先完成 S、C 的私聊主链，再测 QQ/生活/主动联系、群聊和可选提供方，最后做故障与长时运行。需要受控注入或真实天气预警的行可留到相应条件具备时。

## 收口规则

本表中的「待补齐」行是实现任务的现场出口，不能因为能力目录可见、页面有入口、合成测试通过就划为「通过」。可选硬件/服务未部署时记「不适用」并注明交付范围；本体核心、已承诺的功能和权限隔离不能用「不适用」跳过。真实预警等客观事件暂缺时记「阻塞」，保留到事件出现后完成。

每轮实机执行结束，按编号记录脱敏证据、失败原因和修复版本；复测通过后再更新[构建状态](BUILD_STATUS.md)与发行说明。最终交付至少应完成安装隔离、私聊/流式分段、QQ 回执与媒体、状态生活、授权/撤回、已纳入发行的可选提供方及长时运行行；新增能力同时追加相应真实验收行。
