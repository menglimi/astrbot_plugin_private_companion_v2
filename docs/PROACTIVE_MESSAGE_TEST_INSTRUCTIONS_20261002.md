# 主动消息类型测试指令设计

## 测试边界

主动联系配置目前登记 15 个目的。测试不能把「目的开关可读」当成「触发器已实现」，也不能用一条通用的 `chat` 文案声称覆盖所有类型。

每个目的测试分成两层：

1. **触发器测试**：使用该类型原有的生产器和可信来源，在隔离 V2 数据根中构造合成事件；验证来源、资格窗口、偏好开关和去重。
2. **主动联系链路测试**：将生产器实际生成的 `ContactIntent` 交给 `ProactiveContacts.contact`，检查 `proactive.compose`、人格复核、投递和 `observe` 回执。合成数据仅用于隔离验收，不写入用户数据。

模型指令用于约束自然表达，不预置回复正文。`send` 与 `skip` 都是有效结果；除首次连接的管理员私聊测试外，自动化使用模型和平台替身，不向真实用户发送。真实发送结果为 `unknown` 时不得重放。

### 统一模型约束

每条类型指令都附在通用主动联系指令之后，不替代角色设定、授权检查、来源复核或 JSON 输出合同：

> 这是一条「{类型}」主动联系候选。只使用本次提供的已核验素材，不把候选摘要当事实，不推断对方情绪、行程或需要。先判断现在是否有自然且值得发送的内容；没有就返回 `skip`。若发送，保持当前角色口吻，正文简短、不索取回复、不提测试或内部流程。严格遵守通用 JSON 合同，并给出 `decision_confidence`。

## 类型指令

### 关系类

| 目的 | 测试素材与触发指令 | 通过条件 |
|---|---|---|
| `affection` 想念与亲近 | 合成一段双方近期有来有回、明确表达亲近的私聊。测试指令：只根据双方真实表达的亲近感，判断是否适合留一句自然、不索取回应的话；不能凭沉默声称想念。 | 可发送时锚定原对话；只有单向旧消息或没有亲近证据时 `skip`。 |
| `care` 情绪关怀 | 合成对方明确说出疲惫、难过等感受的私聊。测试指令：回应对方实际说出的感受，不诊断原因，不提供未经请求的方案，也不把普通沉默解释成低落。 | 不夸大情绪，不连续追问；缺少明确感受时 `skip`。 |
| `play` 轻松互动 | 合成双方接受过的玩笑、共同梗或轻松话题。测试指令：只有原语境确实轻松且双方都参与时，才延续一个低压力的小互动；不编造共同梗。 | 互动可自然结束；紧张、严肃或单方玩笑素材必须 `skip`。 |
| `repair` 关系修复 | 合成角色之前一条可核验的失误和对方明确指出的不适。测试指令：准确承认自己做错的具体部分，简短表达理解；不辩解、不要求原谅、不把修复责任推给对方。 | 只回应证据支持的失误；没有具体失误或对方边界要求停止联系时 `skip`。 |
| `chat` 日常话题 | 使用一轮已完成的私聊和真实消息来源，推进到配置的空闲窗口。测试指令：从最近实际谈过的话题承接一点内容；避免「在吗」、空泛问候和复述刚发过的话。 | 空闲、授权、额度、活动曲线和去重均按真实配置判断；不合适时 `skip`。 |

**覆盖说明**：自动会话调度器创建 `chat` 契机；私聊关系事件生产器也会依据明确的原文线索分别创建 `affection`、`care`、`play`、`repair` 契机。四类均有生产器与主动联系链路验收，分类线索只生成候选，不代表情绪事实，正文和是否发送仍由统一主动联系模型决定。

### 时间与约定类

| 目的 | 测试素材与触发指令 | 通过条件 |
|---|---|---|
| `greeting` 问候与纪念 | 分别构造早/午/晚窗口、夜间窗口和管理员配置的重要日期样例。测试指令：把日期或时段只当作开口机会；优先承接当前语境，不假设对方刚醒、吃饭、休息或正在等待。 | 只在有效窗口、静默和冷却规则允许时进入链路；无话题可 `skip`，不得机械套固定问候。 |
| `followup` 接回旧话题 | 构造一条已确认投递、之后无人类新输入、超过跟进等待时间的记录；再构造有新输入、已发屏幕观察或冷却未结束的对照组。测试指令：只承接原记录中仍有意义且未被新输入取代的话题，不暗示已读或催回复。 | 等待期未到不触发；等待后只使用仍有效的原话，无新输入且冷却允许时进入统一主动联系链路。新输入、来源失效或冷却中不触发。 |
| `invitation` 共同活动邀请 | 合成含有明确共同活动邀请的私聊；另测只有共同兴趣、没有明确邀请、空闲未知及已拒绝的情况。测试指令：把活动说成可商量的邀请，不伪造双方空闲、预约或承诺，不要求接受。 | 私聊事件生产器只为明确邀请建立候选；只有共同兴趣或已拒绝时不发送，最终正文和是否发送仍由统一主动联系模型决定。 |
| `reminder` 约定与提醒 | 创建一条已接受、即将开始的日历约定；对照待确认、已取消、已过期和时间修订样例。测试指令：只根据当前有效的已接受约定简短提醒，不说成已发生，也不声称对方已收到或记得。 | 来源回执、版本、发生时间及配置窗口全部匹配才进入模型；其他情况不发送。 |
| `meal` 饭点问候 | 使用关系时区构造午餐与晚餐窗口，并验证窗口边界、暂停和重复候选。测试指令：当地饭点只提供时间语境，不推断对方没吃饭、正在吃饭或需要提醒；没有自然话头就 `skip`。 | 使用配置时区和原始窗口；正文不以盘问饮食或要求报平安作为默认模板。 |

### 素材分享类

| 目的 | 测试素材与触发指令 | 通过条件 |
|---|---|---|
| `life` 分享自己的生活 | 构造一条真实的角色活动完成回执或允许分享的角色日记记录；分别撤回素材和更改修订版本。测试指令：只分享已完成且当前仍有效的具体片段；日记/梦境保持主观语境，不扩写成客观事实或对方经历。 | 原操作、修订、来源授权和受众复核通过才生成；撤回或版本变化后丢弃旧候选。 |
| `creation` 作品与阅读 | 构造完成阅读回执，包含可引用的阅读范围；对照只打开、未完成、范围已变更的记录。测试指令：只说回执覆盖的阅读片段；个人感想明确是角色感受，不声称读完整本或把书中内容说成现实。 | 仅完成且回执有效时触发；不补写未提供的书名、章节或情节。 |
| `news` 外部资讯 | 使用隔离资讯源返回带标题、原链接、发布时间的当前条目；另测过期、重复、抓取失败及来源配置变化。测试指令：仅根据给定条目判断是否与关系语境相关；保留原发布时间，不声称亲历、看完全文或独立核实。 | 缺标题/原链接/发布时间或来源失效时不触发；归因由程序追加一次，模型正文不重写归因。 |
| `environment` 环境与状态变化 | 分四个子例：当前天气观测、两次观测形成的天气变化、官方预警、Bot 服务余额。测试指令按素材区分：观测不等于预报；变化不等于灾害；预警只按官方原文及覆盖范围；余额不是用户欠款，不催充值。管理页的环境诊断另外支持 `external_news` 来源探测，但实际主动资讯仍登记为 `news` 目的。 | 只使用对应来源的地点、时效、范围和金额；预警覆盖不明、余额缺失或观测过期时 `skip`。不得把四种来源混成同一类事实；资讯探测必须保留新闻来源校验和归因。 |
| `screen` 已授权屏幕观察 | 以同一私聊、有效授权、仍可读取的屏幕分析回执构造候选；再测撤权、来源撤回和冷却。测试指令：只提及分析明确支持、且适合主动分享的一点观察；不暴露无关屏幕内容，不推断用户意图或身份。 | 授权、来源、窗口和每日上限复核通过才进入模型；撤权或来源变化立即失效。 |

## 覆盖矩阵与验收记录

当前源码中 15 个登记目的均有明确 `ContactIntent` 生产器：`affection`、`care`、`play`、`repair`、`chat`、`greeting`、`followup`、`invitation`、`reminder`、`meal`、`life`、`creation`、`news`、`environment`、`screen`。`environment` 有天气观测、天气变化、官方预警及余额多个来源分支；环境诊断还可选择 `external_news` 变体核对同一条真实资讯来源。关系事件生产器依据原文线索筛选关系候选；`followup` 根据确认投递历史、等待期、冷却和后续新输入生成或取消候选。生产器接通只表示类型候选可进入相应链路，不替代授权、来源复核、模型判断或投递验收。对应触发器和链路证据见 `PROACTIVE_MESSAGE_TEST_ACCEPTANCE_20261003.md`。

验收结果须分别记录：

- 类型指令与模型 JSON 合同通过；这项检查本身不能代替生产器和投递链路验收。
- 真实生产器是否构造了该类型的 `ContactIntent`。
- 来源失效、撤权、关闭目的开关、静默及重复等负例是否阻止模型或投递。
- `proactive.compose`、启用时的 `proactive.judge`、投递回执和 `observe` 是否属于同一个 attempt。
- 对明确 `skip`、失败、已接受但未确认、`unknown` 分别记录结果；`unknown` 不重试。

只完成类型指令和 JSON 合同时，报告为「类型指令测试」，不要报告为「该类型端到端主动消息已完成」。
