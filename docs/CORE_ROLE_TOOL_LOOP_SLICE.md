# CORE-02/08 原角色工具多轮续答切片

更新时间：2026-09-22。本文记录 Companion V2 在隔离数据根中的本地实现，不代表 AstrBot 宿主、真实模型或平台发送已经接通。

## 目标

当原角色需要读取资料、保存便签、查询配置或解释一次本地检查时，模型可以在同一条原始消息任务中分轮调用受宿主声明的工具，再沿用原人格、原受众、原提示词和同一份模型配置继续回答。工具调用本身不是新的对话、人格或主动消息，也不自动产生平台发送。

本切片解决四个边界：

1. 模型只可以调用本轮宿主预先注册的工具和来源句柄；身份、角色、scope、受众和权限不由模型参数决定。
2. 每个调用都有持久的开始屏障、实际结果、效果状态和 owner 回执；同一调用编号只返回原结果，换参数会终止本轮。
3. 本地便签/提醒等有限同步操作与工具结果在同一 SQLite 事务内提交。进程中断时业务写入和结果一起回滚，屏障保留 `unknown`，不会自动重做。
4. 每一轮续答都重新读取和复核原材料、人格绑定、受众、工具结果和来源有效期；资料撤权、过期、换绑或诊断依据变化时，草稿丢弃而实际模型用量仍结算。

## 运行路径

```text
入站事件
  -> 持久输入批次与来源正本
  -> seal 原角色生成任务
  -> open_session（一次解析配置与工具目录）
  -> 模型轮次 0..8
       -> final draft
       或 -> 有序 tool calls
                -> 本地 owner ledger
                -> 原角色带 ToolExchange 续答
  -> 不可变分段清单
  -> 已有 Delivery 队列与逐段回执
```

`ModelSession` 在第一次打开时固定原角色、原事件、原提示词、配置采用回执和 provider 计划。后续轮次不重新解析配置，也不接受改人格、换受众或替换输入。每轮最多 8 个工具调用，最多 9 轮；最后一轮不再向模型提供工具目录，并要求依据已取得的实际结果收束回答。

## 工具与资料

当前本地 owner 提供：

- 便签和提醒的读取、创建、修改、完成、重开、置顶、取消、改期及原操作查询；
- `source.read`，只能读取宿主在批次封存前以不可变 `handle -> SourceRef + capability` 注册的原件；
- `diagnostics.explain` 与 `diagnostics.inspect`，分别用于设计说明和有界本地检查。

模型不能创建、重绑或猜测来源句柄，过期原件不会被另一份新资料替代。成功的来源读取会以原 `SourceRef` 进入证据材料，交付和已发历史再次读取时仍复核权限、版本、撤权和有效期。

工具结果中的 `delivery=not_started` 只表示本地操作尚未发送；`local_registered`/`local_prepared` 也不等于平台已发送或用户已收到。提示词明确要求模型区分这些状态，并对 `unknown` 保持不确定。

## 持久化与迁移

内部 schema 已从 v11 升至 v12：

- `model_rounds`：任务、轮次、请求摘要、调用状态和工具调用清单；
- `conversation_tool_sources`：批次内不可变来源句柄；
- `conversation_tool_calls`：调用编号、参数、序号、owner 操作、效果、结果和完成时间。

v11→v12 在事务中同时重建 `model_calls` 与 `model_call_accounts`，把 provider 位置约束从 `0..1` 扩展到 `0..17`，保留所有历史账本行和外键关系。迁移指纹、版本链、半迁移表和失败回滚均在打开数据根时校验。旧版本根若提前出现 v12 表会被拒绝，避免把未来结构当成已完成升级。

## 重启、取消与未知

`model_requests` 仍是生成屏障：任务重启后不能重新打开模型会话或重新生成。已经成功保存的便签通过 owner 回执复核后可继续进入交付；未知的模型用量保留预算占额；取消或换绑会丢弃未发送草稿，但不抹掉已提交的本地操作和真实用量。

同步内置 owner 只覆盖共享同一 SQLite 的有限本地操作。外部插件、设备、网络和不可回滚副作用必须实现独立的受监督 adapter，不能直接复用这个事务假设。

后续已完成[外部工具独立监督与宿主目录映射](CORE_EXTERNAL_TOOL_SUPERVISION_SLICE.md)，新增 v13 调用账本并沿用本切片的原角色续答和交付复核。本页保留 v12 切片当时的验证范围。

## 证据与观察

诊断和 `observe` 只输出轮次、调用序号、固定动作名、状态、效果和是否存在 owner 回执，不输出原提示词、参数、私密正文、报告 token 或模型草稿。未注册的模型动作在观察中统一显示为 `unregistered`。诊断报告在重启后没有内存缓存也不能被无条件复用，必须重新验证原依据和有效期。

## 验证

本切片包含：

- 创建→读取→原角色续答、同配置多轮、重复调用幂等和调用编号冲突；
- 资料读取、过期、撤权、重启、诊断报告过期和换绑；
- 读→同轮修改→继续的历史观察复核；
- 取消、未知模型用量、owner 崩溃回滚、最后一轮禁止工具和结果总量上限；
- v11→v12 非空账本迁移、高轮次位置、失败回滚、半迁移及未来表拒绝；
- 历史 v6/v9/v10 迁移夹具兼容。

测试只使用临时 SQLite、合成身份、合成 provider/sender 和本地时钟，不加载 AstrBot，不读取 V1 数据，不连接真实模型或平台。真实宿主注册、工具目录映射、插件副作用监督、自动防抖、群聊路由和 V1 数据迁移仍属于后续交付。

本切片的工具循环测试共 **21 项**；连同所有既有隔离模块，最后一次全量回归为 **405 项通过（52.874 秒）**，`compileall` 通过。历史迁移测试仍从对应旧版本构造真实非空数据库后打开升级，并非只检查建表文本。
