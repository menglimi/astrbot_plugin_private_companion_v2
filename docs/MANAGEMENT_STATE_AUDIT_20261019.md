# 管理状态同类问题排查与修复（2026-10-19）

本轮接续现实设备管理页修复，检查错误经过 Dashboard 页面桥后的表现、独立记录的快照筛选，以及刷新和保存之间的状态一致性。

## 确认并修复的问题

- 感知设置和家具清单接口仅在 `data.code` 返回错误码，AstrBot 页面桥拒绝请求时只转发 `message`，导致具体原因丢失。两处改用统一的 `outcome_response`；设备管理接口继承相同实现，页面补充对应说明，保留身份与权限检查。
- 音频输出、主动语音与叫醒表单在刷新前保存整份默认草稿，遮挡后台的新配置。现在只保留实际改动的字段，未改字段采用最新快照；保存仍提交完整有效表单。摄像头草稿也改为字段级差异。
- 仅有独立提醒或待确认授权记录的用户会被管理快照遗漏。现在纳入这两类记录，沿用原授权状态，不把待确认记录当成已授权。
- 公共请求层把带有 `data` 字段的业务对象误当成匿名包装，可能丢掉其他业务字段。现在只拆解形状确切的响应信封或仅有 `data` 一个字段的包装。
- 较早开始的刷新请求可能晚于保存返回，覆盖新保存状态。管理操作变更请求代次，忽略旧刷新回执；操作期间不再接受重复管理操作，也不重放结果未知的外部调用。

## 回归与交付验证

- `test_native_extension_api` 与 `test_perception_host_api` 验证接口错误、身份拒绝、记录筛选、磁盘重载及宿主停机。
- `native_management_contract_process` 从临时 AstrBot 数据根导出真实接口回执；`test_native_extension_management_bridge.cjs` 使用安装的 AstrBot 页面 SDK 和真实产品请求层验证错误码、音频刷新、字段级草稿、完整保存、旧刷新回执与业务包装。
- `test_native_extension_panel.cjs` 验证配置表单、设备管理和手机宽度。
- 当前源码构建后的交付包另行验证哈希、语法、唯一注册、唯一公开页面、迁移合同、宿主启动停机及路由注销；具体结果保存在发布目录验收记录。
- 设备与授权测试使用临时合成数据，未执行真实摄像头拍摄、音频播放、米家登录或聊天发送。
