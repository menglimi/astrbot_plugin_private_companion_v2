# 普通被动回复的文字清理接线

## 原因

主动消息经 V2 的 `ReplyTextPolicy` 执行文字替换、分段及清理。普通私聊、群聊改为 AstrBot 核心生成和发送后，准入快照只带群聊分段配置，没有携带文字清理或替换配置，最终发送包装也没有执行这些规则。因此同一套页面设置只影响主动消息等 V2 独立任务。

## 当前实现

- 准入时按实际私聊或群聊上下文读取同一 `conversation.presentation` 配置快照，只提取文字清理和替换字段；不启动旧回复任务，也不选择 V2 模型。
- `astrbot_host/core_reply_presentation.py` 复用既有 `ReplyTextPolicy`。普通文字在实际发送前处理；群聊由 V2 补充分段时先替换再拆分，并对每个完整气泡清理一次。宿主已拆出的气泡保留其发送边界。
- 清理支持词条、正则、整段及仅句尾；继承原有代码、Markdown 段落、括号、引用、链接和媒体标签保护。不修改原消息链或会话历史，图片等非文字组件保留顺序。
- QQ 私聊原生流式回退以及群聊缓冲、增量流式，在实际气泡发送时清理。SDK 分块不会单独触发句尾清理。
- 直接原生流式的平台需要完整文字才能正确执行跨分块替换、任意正则及引用保护，因此启用清理或替换时合并连续文字到媒体、控制消息边界或生成结束，再交原生流式发送器。这会延迟这类平台的首段文字；关闭两项规则时维持原流程。
- 原生发送工具使用相同规则，并保留原文与实际呈现文本的宿主去重记录。完全清空的正文不发送空气泡或单独的引用、@；混合消息保留图片等内容。
- 群复读仍走专用跟读／打断路径。真实发送继续逐次复核权限；拒绝或结果未知时不续发、不重放。

本次处理范围是最终的 Plain 文字组件，未对宿主已合成的音频或已渲染的图片进行重制。清理配置仍沿用现有配置继承及窗口覆盖规则；本次没有迁移配置作用域。

清理及替换的默认开关保持关闭，不自动开启任何窗口的规则。页面以实际保存的清理范围和词表为准，去掉了“默认开启句尾标点清理”的过时说明；测试同时验证默认原文保留及显式启用句尾清理的行为。
