# 陪伴小屋配置归属重排

日期：2026-10-01。本文是当前唯一公开页面「陪伴小屋」的现行配置归属表；旧版页面展示设计见 `PAGE_DISPLAY_AND_CONFIG_DESIGN_20260929.md`。

## 分配原则

- 按操作者要解决的问题分组：塑造角色、理解输入、安排回应、管理联系、连接运行。
- 同一读写合同可以按职责在多个工作区提供可写入口；各入口必须复用同一字段合同、编辑令牌和生效层级，不能各自维护一份影子值。状态页、家具和其他说明仍以状态与跳转为主，不凭空复制一套合同。
- 角色本人设定与 AstrBot 知识来源放在「自我」；关系权限、模型路由、资源预算、宿主运行和数据维护各归其主责页。
- V1 能力对照用于命名和内容边界，不把 V1 的字段组名直接当 V2 页面名。

## 跨页视图

`conversation.presentation` 仍是一份读写合同：分段、语气、投递与群聊判断按字段分别出现在「表达」「感知」「决策」，三个视图过滤同一份字段清单，每个字段只出现一次。群聊图片补述归「感知」，因为它生成的是输入材料；群聊判断视图不再携带表达控制。

`group_participation` 也保留一份群级合同。「决策」只展示氛围观察、插话与复读；`enable_group_persona_denoise` 单独在「表达」展示，因为它只调整群聊说话腔调。`enable_group_roleplay_strength` 仍在「决策」：运行时先依据群聊氛围计算强度参考，再将其作为本轮判断材料，不是直接的风格开关。

`knowledge` 仍是一份合同：「自我」展示世界知识的导入与引用；「关系与权限」展示 `member_*` 群聊成员线索，并放在关系网中维护，因为它们描述已登记成员，不代表自动确认身份或授予权限。

`busy_gate` 同时控制忙碌时的私聊回复顺延与普通主动联系暂停，统一挂在「主动联系」的「开口闸门」设置。`role.life` 的休息时回复判定与醒后补看也在同一处集中调整；日记与生活页只保留生活例程、睡眠和写作偏好，避免“什么时候写日记”和“什么时候回复消息”混在一起。

## 自我工作区

「自我」有三个工作区：角色档案、人格底稿、世界知识。角色档案按角色共享，细分姓名/种族/生日/性别/身份经历、外貌识别、性格与日常、第一人称/口吻示例/典型反应、价值与目标、边界、世界规则/场景/人物网络和平台称呼；字段仍保留旧版七个综合档案键，历史内容继续进入提示词。角色档案会在新对话封存时进入该轮提示；口吻示例只作为表达参考，不会被当成当前场景内容或事实。

人格底稿工作区读取 AstrBot 当前人格，允许修改、留版本和复制；宿主人格保持只读，需复制回 AstrBot 才会影响主回复。世界知识工作区管理世界书/知识库的导入和引用边界。当前还没有把 V1 的模型抽取预览接到角色档案字段，不能把读取人格原文等同于自动完成角色资料。

`knowledge` 的导入与引用控件留在「自我」；群聊成员线索在「关系与权限」的关系网内编辑。两处按字段过滤同一配置组，保存仍走原 owner 和 edit token，不复制配置数据。语义理解与学习素材在「学习与成长」，表情素材与检索在「表达」。`role.state` 的周期/状态区与联系区分别位于「状态」和「主动联系」，页面只挂载各自字段区，不重复一组控件。

## 校验口径

- 搜索配置编辑器挂载点，确认 `knowledge` 在「自我」与「关系与权限」按 sectionId 分工且字段不重复，`library` 只在「日记与生活」、`budget` 只在「模型与连接」挂载；状态 API 的主区与联系区分别只有一个入口。
- 旧的 `#manage/persona` 与 `#manage/knowledge` 深链接分别落到自我问卷和世界知识标签。
- 保存、恢复和复制人格稿继续经过已有版本服务；AstrBot 人格文本没有新增写入路径。

## 插件级配置 Schema 归属（2026-10-03）

本节补齐 `_conf_schema.json` 的 11 个顶层组。这里区分三种入口：小屋中的实际编辑器、引导流程对配置的间接管理、AstrBot 插件配置表单。只有前两者算小屋可达；字段名相近、状态可见或行为可被覆盖，不等于能编辑 schema 原值。

| Schema 组 | 唯一归属位置 | 当前状态与处理 |
|---|---|---|
| `staging` | 账号与会话；首次配置只负责首次连接 | `enabled` 由启动/停止生命周期管理，`profile_id` 是内部运行档身份；保留隐藏，不新增原始字段控件。旧 `delivery_mode` 已固定为原生发送，不应继续承诺可选预览模式；清理其 schema 字段及读取兼容时须先确认旧运行档兼容策略。 |
| `target` | 首次连接 → 绑定对象 | 新流程通过账号与会话目录选对象和人格。旧 `platform_id`、`account_id`、`participant_id`、`bot_id`、`role_id`、`persona_id` 仅兼容旧单目标配置，保持隐藏；不要再加第二组手填表单。 |
| `multi_host` | 账号与会话 | `targets`、`personas`、`group_targets`、`enabled` 由宿主管理工作区读写。`installation_id` 是稳定安装身份，显示只读。`capabilities` 应通过有含义的授权项管理，不暴露字符串清单。旧私聊 `delivery_mode` 与群 `group_delivery_mode` 都不控制投递，隐藏并只保留旧配置读取兼容；群消息固定走已配置的原生渠道，逐轮预览由操作级草稿流程决定。 |
| `model` | 模型与连接；首次配置提供初始值 | `provider_id`、`task_prompt`、`fallback_provider_id`、`fallback_on_refusal`、`replacement_rules`、`max_output_tokens`、`streaming`、`maximum_input_estimate`、`output_parameter` 与三个费率字段是运行档默认值；小屋任务模型编辑器设置的是任务/范围级有效配置，不能替代全局默认。`additional_providers` 是 AstrBot Provider 的额外运行元数据，目前由可见插件配置表单保存；Provider 实例本身仍由 AstrBot 管理，小屋 Provider 目录只读展示，不声称可在其中改写全局插件默认。 |
| `segmentation` | 表达 → 文字形态与风格 → 分段回复 | 小屋回复工作台已提供对应的分段字段。入口属于窗口/角色回复设置；schema 值只作为未设置覆盖值时的运行默认。不得再在第二处复制一套字段控件。 |
| `voice_reply` | 表达 → 语音与朗读 | 回复工作台管理当前对象的语音生成与投递策略；宿主默认开关、基础概率及私聊/群聊覆盖由表达页宿主默认区通过宿主配置保存接口维护。两层职责不同，不相互冒充；四个已迁入字段在 AstrBot 配置表单隐藏，其余宿主默认保留原生入口。语音默认修改当前会话策略并提示重启宿主后完整生效。 |
| `poke` | 表达 → 平台组件与动作 → 收到戳一戳 | `enabled`、`trigger_probability`、`replies`、`back_probability` 是收到戳一戳后的回应策略，由表达页宿主默认区维护；保存后立即更新当前策略并写入插件配置，整个原生表单组隐藏。主动联系页的 `poke_action_*` 是主动发起动作，语义不同。 |
| `runtime` | AstrBot 插件配置表单；部分同义分层设置另有小屋入口 | Token/费用默认和每日软限额另见模型与治理页；回复工作台和转发感知页上的分层设置不是对全局运行上限的写入。前后台容量、排队保留量和合并转发结构上限确实由宿主读取，暂由原生配置表单作为全局唯一入口；不要把局部覆盖字段宣传成等价配置。 |
| `news` | 感知 → 外部资讯与检索 → 来源设置 | 宿主级 `source_kind`、`bilibili_uid`、`feed_url`、`hot_sources`、`search_url`、`hot_result_count` 与主动联系的角色级资讯开关分开：前者只配置来源及默认读取参数，后者只配置该角色是否采用资讯。当前角色级来源设置不能写回宿主级 schema。`search_url` 等尚无小屋读写合同的值继续保留在 AstrBot 配置表单，接入后再隐藏原生重复入口。 |
| `solar_terms` | AstrBot 插件配置表单 | 宿主节气表仅支持将默认的 1901–2099 范围收窄；无需改动时保持默认即可。页面的自动节气开关是按窗口启用消费，不等于宿主范围编辑。 |
| `legacy` | 首次配置 → 从 V1 迁移 | `v1_root` 已在迁移卡片提供可选绝对路径输入；检查和试算通过查询参数使用它，执行请求也携带同一路径并重新核对试算指纹。留空仍自动定位。迁移仍需人工检查、试算和确认；V1 只读，禁止增加启动自动执行迁移项。 |

### 收口顺序

1. 保留现有分层配置 API 与新增的宿主默认配置 API：页面标明保存层级，不能把全局默认值与目标/角色/窗口覆盖值混写。
2. `legacy.v1_root`、`poke` 与语音私聊/群聊概率覆盖现已接入；验证 Dashboard 身份、编辑令牌、字段白名单、保存回执与实际生效层级，并隐藏重复原生表单入口。
3. `multi_host.group_delivery_mode` 已确认是无效兼容字段，隐藏并保留读取以兼容旧配置；有效但暂未迁移的 `model.additional_providers`、`runtime` 容量/结构上限、`news.search_url` 与节气表范围继续由 AstrBot 原生配置表单承担，不在小屋呈现假控件。
4. 只有页面具备等价读写合同后才隐藏原生入口。语音默认与戳一戳回应已迁入小屋的字段按此规则隐藏；仍由原生表单独占的值继续保留。

验证按字段读写合同进行：页面控件、实际 endpoint、保存层级和生效读取必须一致。仅有导航、只读状态、同名标签或可被另一层覆盖，不计为该 schema 字段已接入。
