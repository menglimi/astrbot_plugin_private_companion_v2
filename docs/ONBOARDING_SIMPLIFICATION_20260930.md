# 上手门槛：界面里的内部运行信息盘点（2026-09-30）

用户反馈："存在很多内部运行的东西，提高了插件的上手门槛。"
本文只做盘点与分级，给出改法与代价；所有数字都是本轮实测。

口径：**内部运行信息**指三类东西——
1. **内部术语**：实现概念直接当标签用（运行档、入站接管、投递模式、作用域、提供方、端点、路由、合同、批次、生成代次…）；
2. **原始标识与码**：id、哈希、字段名、错误码原样显示；
3. **运行仪式**：用户必须先理解再操作的一串状态机（选择运行规模 → 核心管理员窗口绑定 → 模型配置 → 初始资料 → 主动消息测试）。正式投递固定为 `onebot_private`；旧 `preview` 只用于兼容读取。

---

## 一、一个好消息：向导本身已经是人话

`setup-guide.js` 现在是六步「单/多账号 / 单/多人格 / 核心管理员窗口 / 插件模型 / 世界知识 / 关系教学与主动消息测试」，
出现的内部词极少（运行档 3、投递 4、授权 4、回执 3、初始化 3，且都在解释性句子里）。
**门槛不来自首次引导，而来自引导之后的界面**——用户一旦离开向导，就掉进下面这些东西里。

## 二、实测：术语密度（页面全域，`pages/**/*.js|html`）

| 术语 | 出现次数 | 说明 |
| --- | --- | --- |
| 宿主 | 507 | 一部分是合理的（"宿主管理"页名），一部分是"宿主状态/宿主目录/宿主装配"这类实现说法 |
| 角色 / 目标 | 1099 / 222 | 用户词，但"目标"同时被用于"接管对象"与"任务目标"，两义混用 |
| 授权 | 253 | 安全边界，必须留；但"授权/回执/账本"三件套同时出现时用户读不懂区别 |
| 路由 / 端点 | 153 / 55 | 纯实现词，出现在错误说明与边界卡里 |
| 快照 | 128 | 备份页的正当用词 |
| 运行档 | 115 | 见上一轮讨论：概念该留，词与粒度该改 |
| 回执 | 110 | "已收到的回执"这类句子；对用户等价于"确认信号" |
| 批次 / 生成代次 | 37 / （generation 164 含无关命中） | 纯实现词 |
| 作用域 | 39 | 配置生效范围，该改成人话 |
| 合同 | 21 | 实现词（"读写合同"），页面上仍然出现 |

| 固定档 / 指纹 / 收据 | 3 / 12 / — | 排障词，不该在一级界面 |

## 三、实测：原始标识与错误码

| 项 | 现状 |
| --- | --- |
| **错误码翻译** | 宿主侧可达码 **198** 个，页面有翻译 **71** 个，**缺 127 个**——缺的那些会以原文形式出现在提示里，例如 `content_provider_unavailable`、`host_audio_decode_timeout`、`group_reply_target_required` |
| 原始 id | 宿主管理状态卡「运行档 → `qq-v2-stream-20260926`」、关系与权限工作区同款一行 |
| 哈希 | 备份还原预览里的「确认摘要 `59cd09ee…`」 |
| 字段名 | 配置编辑器与边界卡里出现 `conversation.perception.calendar_timezone` 这类完全限定名 |
| 能力 id | 能力目录里出现 `astrbot_plugin_image_companion`、`private_core_legacy` |
| 版本 | `companion-v2.storage.v45`、`schema v41 与 v44 不一致` 这类信息在页面上出现过 |

## 四、哪些**必须**留着（不能藏）

安全边界与不可逆动作：**接管谁**、**能不能真的发消息**、**怎么撤回授权**、**备份与还原**。
这四件是产品价值本身；它们的措辞可以人话，但不能只在详情里。

## 五、三层改法（按性价比排序）

### 第一层：低风险、当天见效

1. **补齐错误码翻译**：给 127 个缺翻译的码加人话（或统一兜底："这一步没有成功，请重试"+ 一句原因），并按模块分表放（宿主管理、配置、备份、迁移各有自己的表）。
2. **统一术语表**（一处定义，页面全域引用）：

   | 内部词 | 用户词 |
   | --- | --- |
   | 运行档 / 运行实例 | 接管的会话（或"运行实例"，二选一，全域一致） |
   | 投递模式（onebot_private） | 正式消息通过已绑定的真实 OneBot 私聊通道发送；旧 `preview` 只兼容读取 |
   | 入站接管 | 现在是否接收消息 |
   | 作用域（安装/角色/关系/窗口） | 生效范围（整个插件 / 这个角色 / 这段关系 / 这个对话） |
   | 提供方 / 能力提供方 | 扩展 |
   | 合同 / 端点 / 路由 | 删除（改成"这一块现在没有可写设置"） |
   | 回执 | 确认信号 |
   | 批次 / 生成代次 | 删除（只留在排障详情里） |

3. **id / 哈希 / 字段名收进"详情"**：一级界面显示摘要（"QQ · 账号 100 → 对方 200 · 真发"），
   原始值放进可复制的 `<details>`，排障时再用。

### 第二层：结构（一到两天）

4. **首次上手只露六件事**：单/多账号、单/多人格、核心管理员窗口、插件模型、世界知识、关系教学与主动消息测试——其余（多目标映射、拓扑、批次、账本）默认折叠成「进阶」。
5. **状态卡改成两句人话 + 一个详情**：现在四行是 `运行档 / 投递模式 / 运行状态 / 入站接管`，可压成
   「正在接管：QQ 账号 100 → 对方 200（正式投递）」＋「状态：运行中，上次活动 3 分钟前」＋「详情」。模型参数变化不会被显示成连接冲突。

### 第三层：可选

6. **进阶模式开关**（默认关）：关掉后隐藏引擎级信息（批次、代次、账本、路由、端点、合同、schema 版本），
   打开才出现。适合"给家人用"的场景。

## 六、验收口径（可测量）

- 首次上手路径（开始使用 + 首页 + 状态卡）里出现的内部术语 = **≤ 5 个**，且每个都有一句解释；
- 宿主侧可达错误码的翻译覆盖率 = **100%**（含兜底）；
- 一级界面上不再出现：原始 id、哈希、字段全限定名、能力 id、schema 版本；
- 「进阶」折叠之外看不到：批次、代次、账本、路由、端点、合同。

## 七、可复跑
