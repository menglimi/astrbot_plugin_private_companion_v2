# AstrBot 全部会话 Token 统计

2.1.26 修复治理与维护中的全局来源占位项。原页面固定显示「未接入」，未读取 AstrBot 已持久化的核心回复统计。

## 数据与边界

- `astrbot_host/host_token_usage.py` 通过 `Context.get_db()` 读取宿主 `ProviderStat`，与 AstrBot Dashboard 的内部 Agent 统计使用相同记录来源和输入／缓存输入／输出计数，不重复观测或写入宿主。
- 累计读取已保存的全部内部 Agent 回复轮次；趋势保留最近 366 个本地日期，小时保留最近 72 个有记录的桶，最近回复保留 80 条。按 Provider 和核心回复类型提供周期分项，读取历史记录无需重新对话。
- 宿主统计按完整核心回复轮次汇总，包括工具续轮；不等同于逐次网络请求次数。只选择计数、状态、Provider／模型和时间列，不读取或返回会话标识、用户 ID、对话正文或凭据。
- 宿主默认零用量无法证明 Provider 确实返回零，保留为未知。正缓存输入计数可展示，宿主没有保存完整缓存回执覆盖和缓存写入，不推导总体命中率或缓存破坏事件。费用保持未知。
- 此全局账本只用于管理员查看，不写入 V2 角色预算、后台任务预算或角色总量。管理员身份在读取前和异步读取后均复核。

## 页面

来源按钮显示实际连接状态；读取失败显示可重新读取的原因。「今日／7 日／30 日／累计／日期」、趋势、Provider、最近回复和 CSV 使用全局来源数据，切换角色不改变全局账本。

## 验证

`tests/test_host_token_usage.py` 使用 AstrBot SDK 的真实 `ProviderStat` 和临时异步 SQLite，覆盖本地日期边界、历史累计、全会话聚合、排除外部 Agent 与未来记录、未知计数、缓存缺失、空账本和最近记录排序。查询记录验证只执行 SELECT，不输出会话标识。

`tests/test_model_provider_api.py` 验证管理员授权前不读取全局来源，宿主全局总量与角色总量分别投影。`tests/test_maintenance_page.cjs` 验证连接状态、来源切换、未知缓存和费用、周期导出及读取失败。最终交付包的宿主加载、自动启动、停机和路由注销沿用 `tools/verify_v2_release.py --host-check`。
