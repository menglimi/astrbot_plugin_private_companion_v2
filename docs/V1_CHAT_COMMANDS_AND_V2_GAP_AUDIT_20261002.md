# V1 聊天指令清单与 V2 差距

核对日期：2026-10-02。核对对象是 V1 核心插件当前源码与 V2 当前工作树；只核对源码入口，不读写 V1 用户资料，也不以旧 ZIP 作为当前实现证据。

## 结论

V1 核心插件注册了 6 个聊天命令处理器，包含别名后共接受 11 个命令名：`HDSI`、3 个图片命令、`陪伴`/`私聊陪伴`/`主动陪伴`、`陪伴群`/`群陪伴`/`群聊陪伴`。其中 `陪伴` 的实际分支远多于帮助文本列出的内容；`陪伴群` 帮助文本也只列常用入口。

V2 当前没有 V1 前缀命令的兼容处理器。私聊前置接入监听只识别三类接入词：`companion_bind [人格名]` 创建待确认目标，`companion_confirm [确认]` 只核对当前私聊来源，最终确认必须回到「开始使用」页完成；`companion_unbind` 只清除待确认目标，不能解除已确认的目标。这些命令不会像 V1 控制命令一样在聊天中执行管理动作，也不会向聊天发送回复。其他管理操作由唯一公开 Dashboard 页「陪伴小屋」及其工作区承接；部分对话任务通过当前私聊角色已注册且授权的工具执行。V1 旧格式不会触发旧副作用。判断时要分开看能力是否承接，以及用户能否继续输入旧语法：前者不少已承接，后者整体缺失。

特别注意：V1 的「绑定主动消息/会话」用于选择主动消息的投递 UMO；V2 的 `companion_bind` 是首次固定平台、Bot、参与者和人格的接入流程。名称相近，但对象和效果不同，不能视作等价命令。

### V2 可照做指令

| 目标 | 输入或入口 | V2 中实际会发生什么 |
| --- | --- | --- |
| 首次绑定私聊窗口 | 在核心管理员的目标私聊中发送 `companion_bind`；指定人格时发送 `companion_bind 人格名`。AstrBot 命令前缀 `/` 可选。 | 记录平台、Bot、参与者和人格，建立待确认窗口；不在聊天中回复角色消息。未指定人格时沿用当前会话解析的人格。 |

| 选择日程模式 | 在「陪伴小屋 → 状态维护 → 日程模式」选择「连续日程（HDSI）」或「日程编排」。 | 连续模式在已接受计划背景下回复；编排模式根据已有日历及近期材料生成/补全后续计划。模式配置不授予日历权限，日历读写仍按当前私聊授权检查。 |
| 回看角色历史 | 在当前私聊提出范围明确的请求，例如「回顾一下当前角色最近记录的活动和日记」。 | 角色时间线工具仅在可用时提供只读查询；历史可能不完整。日记/梦境工具提供的元数据不等于旧正文，也不能据日期补写经历。 |
| 查询或维护记忆 | 在当前私聊说清检索线索，例如「找一下我以前明确说过的关于咖啡的偏好」；需要保存或遗忘时，明确指出目标，例如「请记住我刚才说的这个偏好」「忘掉关于咖啡的这条记忆」。 | 仅在记忆工具与权限可用时处理；保存/纠正/遗忘要基于真实来源，结果可能是待整理或失败，按回执说明。遗忘会停止记忆使用，不代表平台消息、日志或备份被物理删除。 |
| 提出角色成长目标 | 明确说「把这个作为角色自己的成长目标提议」，并给出目标内容。 | 成长工具只记录角色自身的技能或长期目标；生成的是待人审阅的提案，不代表已确认、生效、完成或现实能力提升。 |
| 群配置与治理 | 打开「陪伴小屋」中对应的宿主管理、群回复或群记忆工作区。 | 当前没有 `陪伴群 ...` 的 V2 聊天命令树；各项分别按目标范围和登录授权管理。 |

自然语言例句是任务表达，不是快捷命令；上表列出的日程生成指令是严格匹配的私聊入口。日历、时间线、记忆、成长及扩展工具会按当前角色、私聊/群聊范围、授权和实际注册的提供方动态提供；目录里没有的动作不会因为换一种说法就变成可执行能力。对话中描述清楚要查或修改的内容及时间范围，并以实际工具回执为准；涉及配置、权限、角色或目标切换时回到「陪伴小屋」。

## 差距清单与建议

1. **确定存在的差距：聊天入口兼容。** 除三条首次绑定命令外，V2 没有 V1 命令名的控制路由；旧语法不会执行旧命令副作用，业务能力在其他表面可用也不代表旧聊天语法可用。
2. **部分能力仍有语义差异。** 重点是主动消息目标绑定、统一状态摘要、日程/重要日期、全量遗忘、群级临时 LLM 封锁、撤回内容/媒体转述、每日穿搭图、聊天语种切换、新闻日报及本机闹钟。
3. **明确不应原样迁移的操作。** HDSI 窗口实验控制命令与统计、V1 插件一键重置、资料柜口令输出、直接改写 V1 用户记录均没有安全的一对一命令映射。V2 的模式选择、恢复、授权和记录应走自身范围与回执合同；不读取或迁移 V1 用户数据。
4. **建议保持 V2 的入口边界。** 现阶段把三条接入命令限于建立、核验或清除待确认窗口；把设置类操作放进「陪伴小屋」，把已注册的对话能力交给自然语言表达和角色工具。只有产品明确要求新增聊天命令时，再从只读高频项开始；每条命令先定义目标 scope、授权、参数、回执和失败行为，再复用 V2 正式服务，不复制 V1 大分支 dispatcher，也不为兼容旧别名另造无权限检查的快捷入口。

本清单是当前工作树的源码盘点，未进行打包或宿主集成验收；新交付包仍应按工程约定统一验收。
