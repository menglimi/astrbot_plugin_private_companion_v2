Token 构成条带 · 四种样式对比

同一套数据（本期合计 4,899,078,312 Token）的四种条带编码。现状 v1 的问题：上下两层各说各话、L2 末尾有一段斜纹「输出不计入」空占位、绿/青两色偏近。以下方案全部消除空占位；落码时配色换成主题 token（绿=命中、青=写入、紫=普通输入、琥珀=输出、蓝=输入总量，映射不变）。

方案 A

单条全量带 · 一屏一真相

一层编码，括注补语义

放弃「输入/输出 + 下钻」两层结构，一根带子按占总量比例分四段，所见即所得。输入范围用底部括注表达；「命中占输入 47.7%」这类口径换算交给括注与派生行。

缓存命中42.7% 缓存写入18.3% 普通输入28.6% 输出10.4%
输入 89.6% · 其中缓存覆盖 68.1% · 命中 : 写入 2.34 : 1
结构最诚实：四段同口径（占总量），无嵌套歧义 少一层，省 30px 高度 「47.7% 命中率」不能直接从带上看，要读括注
方案 B

下钻放大镜 · 漏斗连接

保留两层，修掉空占位

保留 v1 的两层语义，但把「缩窄的 L2 + 斜纹空位」改成全宽放大镜：L2 是输入段的等比放大，两条斜边交代「这里被放大了」，L2 各段宽度 = 占输入比例，语义严格。

输入89.6% · 4,387,135,640 输出10.4%
↓ 下钻 · 输入内部构成 宽度口径：占输入 100%
缓存命中47.7% 缓存写入20.4% 普通输入31.9%
输出 10.4% 不参与缓存口径，仅在上层出现
命中率口径（占输入）直接可读，保留下钻叙事 L2 全宽，窄段有更多空间放标签 两条带口径不同（上=占总量 / 下=占输入），依赖漏斗提示
方案 C

层积纵带 · 核心样本

纵向层积，标签内嵌

换一个编码方向：四段纵向堆叠，层高 = 占总量比例，按体量降序，像一管岩芯样本。每层内嵌名称 + 数值 + 百分比，可以完全去掉下方图例卡，卡片反而更矮。

缓存命中2,091,245,66342.7%
普通输入1,401,337,66028.6%
缓存写入894,552,31718.3%
输出511,942,67210.4%
层序按体量降序 · 层高严格等比（1% ≈ 1.8px） 输入 89.6% = 上三层之和
标签永远放得下，天然响应式（窄屏也不挤） 免图例，卡片总高最低 纵向占地高（约 190px）；与页内其他横向条形语言不一致
方案 D

光谱细带 · 省墨模式

细带 + 外浮标签 + 范围缎带

最克制的一版：16px 细带零缝隙，段间只用发丝分隔；名称与百分比浮在带上方用刻度线对位，数值全部交给图例卡；输入/输出范围用底部两条缎带收束。

缓存命中 42.7% 写入 18.3% 普通输入 28.6% 输出 10.4%
输入 89.6% · 缓存覆盖 68.1% 输出 10.4%
最轻量，与页内 KPI 卡、Provider 表的气质最搭 外浮标签不挤占段内空间，段再窄也不糊 带内无数值，读数必须落一行图例；信息密度最低
