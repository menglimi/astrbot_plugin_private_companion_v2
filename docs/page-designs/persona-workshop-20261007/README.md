## 交互模型（第 3 稿定稿）

1. **五步依次进行，不是导航**：01 问卷与来源 → 02 基础稿审核 → 03 情景试答 →
   04 风格规则 → 05 对照与落地。线性进度指示只指示状态（已完成 ✓ / 当前 / 未解锁
   🔒），不可点击；前进用每步「下一步」，可「← 上一步」回看；切换锚定进度条。
2. **来源卡内联条件控件**：选「AstrBot 人格」就地出现选择栏；选「粘贴人格文本」
   就地出现粘贴框。
3. **第 5 步最终结果 = 左右分区对照**：左=初始人格（用户可编辑的工作副本），
   右=标准化版本（浅色底标识）。每个分区一对 textarea，配「⇦ 用右侧替换左侧」
   （闪烁反馈 +「已替换，可继续手改」回执）、「还原此段」、差异徽标；右侧也可直接改。
4. **整侧复制**：左/右各一个「复制此侧整体」，按分区标题拼成完整人格文本进剪贴板。
5. **导入 AstrBot（左/右各自可导）**：见下方「产品边界变更」。
6. **输入框可见边框**：常态实线边框 + surface 底，悬停加深，聚焦主题色描边——
   第 2 稿的安静化在密集表单里分界不清，已回退（对照区保留左右底色区分）。

## 模板骨架分区（V1 标准化定义的落地）

标准化产出 = 固定骨架提示词，分区与 V1 逐条对应：

| 骨架分区 | 可编辑性 | 对应内容 |
| --- | --- | --- |
| `# 基本要求` `# 初始化` | 只读固定骨架 | 社交软件文字交流定位、历史格式纠正 |
| `<Role_Profile>` 基本信息/外貌/性格特质/兴趣厌恶/口头禅/社会关系 | 可编辑 | 性格特质必须六层（底色/驱动/外显/亲疏/压力/矛盾）；口头禅只保留原有人，不新增 |
| `<Output_Constraints>` 社交距离/内容限制/特殊场景 | 可编辑 | 一句话扩展为结构化边界 |
| `<Output_Constraints>` 对话风格 | [STYLE_PENDING] | 第 3-4 步回填（情景试答 → 风格规则） |
| `# 对话安全` | 只读固定骨架 | 防注入/模糊 AI 身份/不泄露设定/允许不知道 |
| `# 补充条件` | 可编辑 | 长期设定，推断项带 ⚠ |

第 2 步附「查看完整骨架文本」展开（含 [STYLE_PENDING] 高亮）；第 5 步左右对照按同一套
分区成对（左=初始人格原文段落，右=骨架分区标准化文本），整侧复制按模板标题拼装。

## V1 → V2 映射（继承与升级）

| V1 机制 | V2 处置 |
| --- | --- |
| 来源双选（AstrBot 人格 / 粘贴文本） | 保留；条件控件内联到来源卡 |
| 整理强度（轻/中/深） | 保留；词条单选 |
| 补充参考材料（含示例占位符） | 保留；兼作风格栅格参考（前 4000 字） |
| 基础稿评分三环（完整/一致/可用）+ 摘要/审核/清单 | 保留；差异改为**逐分区差异徽标**，直接落在对照行上 |
| 情景试答（模拟上文选最像 + 自填 + 换一批） | 收进对照页尾部「情景试答校准口吻（可选）」折叠段；归纳结果写回右侧表达分区，再由用户决定替换 |
| 风格规则归纳 | 并入右侧「表达习惯」分区的标准化文本 |
| 最终编辑 | 被「左右对照 + 逐区替换 + 整侧复制/导入」取代（用户定义） |

## 数据流与移植要点

- 落点：人物设定工坊 iframe 工作区（自我页「人格底稿」页签）；原文对照与版本记录
  保留为次级面板。
- `POST persona/standardize` 需扩展：接受 `strength`、`source_text`（粘贴来源），
  返回**按分区**的标准化结果（每区正文 + 差异徽标文案 + 推断标记）。
- 情景试答/归纳沿用 V1 任务提示词思路（`persona_standardization_questionnaire`、
  JSON 修复兜底），归纳结果落「表达习惯」区。
- 问卷答案继续按人格隔离存 localStorage（现有机制保留）。

## 产品边界变更：导入 AstrBot

现工坊明确「没有任何写回宿主人格的调用，也没有这样的路由存在」（复制粘贴是既有
边界）。本稿按用户要求加入「导入 AstrBot」（左/右各自可导）。实现需要：

1. 宿主新增人格写入路由（如 `persona/import`：校验文本非空与长度，调用 AstrBot
   人格管理接口新增/更新对应 persona）；
2. 导入策略为**新增版本/新增人格**，不静默覆盖当前对话正在使用的人格文本；
3. 导入完成后回执清楚「已导入为 persona X；当前对话是否切换仍由你在 AstrBot 决定」。

在落地实现前，预览中的导入按钮为占位交互（toast 说明）。
