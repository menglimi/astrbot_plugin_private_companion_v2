# 15 · 治理与维护（`manage/maintenance`）

公开入口仍位于唯一 Dashboard Page「陪伴小屋」。页面采用「上方运行态势、下方运行配置」的纵向布局，维护面板由 `pages/陪伴小屋/maintenance-page.js` 和 `maintenance-page.css` 渲染，配置区继续复用现有工作区。

## 一、运行态势

| 分区 | 内容 | 交互 |
| --- | --- | --- |
| Token 统计管理 | 当前角色账本的今日、7/30 日、全历史总计与指定日期；每日趋势、近 48 小时/所选日期小时分布、输入/输出、平均 Token 与延迟、失败/未确认、硬/软预算、本地计价、余额接入状态；已加载的记忆插件/一起房间通过公开摘要桥显示独立账本 | 日期柱条和每日明细可钻取；Provider 与任务排行联动筛选最近调用；来源切换、周期对比、CSV 导出；各来源独立标明账本与预算边界，主链及未接入来源展示说明和空态 |
| Provider / 任务明细 | 按所选时间范围显示消耗排行和调用、失败、缓存命中、延迟及本地计价 | 可展开表格核对维度明细；不暴露提示词和模型正文 |
| 排障与测试 | V1 问题分类、错误/警告/信息筛选、优先处理信号、真实回执时间线、REQ-041 管理身份与角色隔离状态、任务路由、当前角色 SQLite、消息收口与防抖等待窗、上下文来源和主动触达证据；TTS/图片运行快照与按分类变化的 FAQ | 文本 Provider 固定探测、TTS 短音频合成、原生图片工具注册检查、SQLite `quick_check` 与外键一致性检查；从分类工作区跳转到相应测试或证据。检查只读，前两种 Provider 测试可能产生费用，图片检查不生成图片。测试结果只保留在当前页面，支持手动清除并在 15 分钟后自动清除；运行账本、投递回执和未知结果继续保留 |
| 缓存诊断 | Provider 缓存读写回执、请求前缀结构变化事件、前后上下文统计，以及 system / 工具 / 参考材料的 Token 估算 | 对照模型、system、工具定义、材料前缀/顺序/重置/尾缩；估算单独标注，不把结构变化或低命中等同于已确认缓存失效 |
| 最近调用 | 最多读取 80 条角色账本回执，显示任务、Provider、用量、延迟、失败码与缓存字段 | 按失败、未确认、低缓存命中筛选；从 Provider/任务排行联动筛选；折叠查看详情 |

数据来自角色级 `/model/maintenance` 接口和当前 V2 调用账本。成本以微美元存储，页面明确标为本地计价，不代表服务商账单。缓存命中率仅统计同时回报 `input_tokens` 与 `cached_input_tokens` 的调用；缓存写入量独立汇总。没有调用记录与有调用但没有缓存明细使用不同空态。

V2 每日账本按每日角色账户键查询全历史汇总、逐日/小时、Provider 和任务维度，不读取 V1 历史或其他角色。记忆插件与一起房间仅在自身已加载且公开统计桥可用时展示汇总、排行、逐日/小时与最近回执；它们不计入 V2 角色预算，也不提供服务端余额时不显示余额。AstrBot 主链仍显示为未接入。成本以微美元存储，页面标为本地计价，不代表服务商账单。缓存签名只保存哈希、材料体量与启发式 Token 估算，不保存提示词或上下文正文；结构变化事件提供前后规模和 Provider 命中回执，作为排查证据，不宣称能单独确认缓存失效。

运行证据按已选身份与角色的 V2 数据根聚合：这次请求通过的 Dashboard 身份/核心访问/角色账本范围、SQLite PRAGMA 与手动完整性检查、最近防抖策略窗口与消息收口回执、上下文材料来源/状态/次数、主动触达总数和最近时间。防抖证据不含 batch、route、merge 或 session 标识。页面不返回用户/账号/角色标识、消息正文、提示词、数据库路径或主动消息正文；候选拦截原因和完整评分链尚未接入。

页面行为覆盖连接/未连接来源切换与独立统计、今日/7/30 日/总计/指定日期、排行筛选、严重度与问题分类、REQ-041/防抖证据、SQLite 检查和文本/TTS/图片测试入口；由 `tests/test_maintenance_page.cjs`、`tests/test_token_sources.py` 与 `tests/test_model_management.py` 定向验证。

## 二、运行配置

- 每日软限额（`model.budget`）在这里设置。达到后暂停启动新的可选后台任务；已经运行的任务继续完成，交互回复不受影响。
- 账号与会话复用 [18-host.md](18-host.md) 的宿主管理工作区。
- 资料与备份复用 [19-data.md](19-data.md) 的备份与还原工作区。

## 三、验证

- 角色范围、缓存字段解析及统计汇总：`tests/test_model_management.py`。
- 全新数据根必须通过 V46 用量字段迁移：`tests/test_agenda_storage.py`。
- 修改公开页源文件后运行 `tools/sync_framework_page.py`，构建交付包前以 `--check` 确认生成文件一致。
