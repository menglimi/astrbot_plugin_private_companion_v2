# 16 · 开始使用（`manage/setup`）

代码位置：`pages/陪伴小屋/app.js` 的 `renderSetupPage` 挂载 `CompanionSetup`（`setup-guide.js`）；后端为 `astrbot_host/setup_api.py`。

## 首次配置顺序

| 步骤 | 操作 | 完成条件 |
| --- | --- | --- |
| 1. 核心管理员窗口 | 在指定私聊发送 `companion_bind`；多人格时可附加 `companion_bind <AstrBot 人格名>`。核对平台账号、私聊对象和人格后，由 Dashboard 管理员确认。 | V2 本地绑定记录已确认，账号与人格映射已登记 |
| 2. 插件模型 | 选择 AstrBot 已加载且 V2 可适配的文本 Provider。 | Provider 已保存 |
| 3. 世界知识 | 打开知识库与世界书，填写或选择来源。 | 用户标记完成或暂时跳过 |
| 4. 关系教学 | 打开关系与权限，补充核心管理员及重要对象。 | 用户标记完成或暂时跳过 |
| 5. 主动消息测试 | 用户点击按钮后，V2 向已确认私聊发送一次固定 OneBot 消息。 | 收到平台送达确认；未知结果不会重放 |

设置进度存于 V2 自己的数据根，刷新和插件重载后保留。保存账号与人格绑定候选不会发送消息；步骤顺序也不会要求用户每次启动插件都重新配置。账号数、人格数和平台数由映射自然决定，不要求用户选择运行规模。

## 进阶配置

运行实例准备好后，「开始使用」提供按 V2 领域组织的回复与分段、人物与资料、日程与作息、主动联系、群聊参与、模型路由六个分区。参考 V1 的引导层，配置按板块逐项完成，用户留在「开始使用」内；现有配置工作台在对应分区直接挂载，沿用原来的读取、校验和保存逻辑。

分区先提供常用配置：回复表达及分段预览、角色与关系资料、角色状态和日程、主动联系节奏、群聊氛围与插话、主动联系/日程/状态/反思的任务模型路由。由其他管理页专属的工作流不在这里放跨页跳转入口；用户仍可通过小屋导航进入完整工作台。V1 的字段与行为不直接复制为 V2 设置。

日常对话回复继续跟随 AstrBot 当前人格与主链。首次设置步骤中可选择陪伴通用模型；完成设置后，此处显示当前通用模型并允许编辑可即时应用的任务路由，避免使用只接受首次初始化的接口提交 Provider 修改。

合并转发阅读开关在「理解 → 图片与合并转发理解」中按角色封存到回复设置；同页的摄取上限由宿主设置接口保存，限制之后进入的新消息，单次处理中固定使用进入时的值。数量、节点数和深度不能超过转发结构合同；已保存的转发内容仍可读取。该设置属于安装级配置，不按账号或人格数量重复暴露入口。

## 账号绑定诊断

启动时会校验已确认的平台账号、会话与人格映射。出现 `host_binding_changed`（兼容旧状态的 `staging_profile_conflict`）时，状态会点名发生变化的绑定类别；模型/provider、预算、投递模式或其他运行参数差异只作为环境变化，不阻止原绑定重新连接。人格提示词内容变化也不等于更换人格。

首次设置不提供十年授权或预览选项。主动测试只由用户明确点击触发；插件其余投递规则由正式运行设置决定。

完成向导后，状态会写入 V2 独立数据根。宿主重启时会通过 `POST /astrbot_plugin_private_companion_v2/setup/host/start` 按已确认的账号、私聊对象、群目标和人格重新连接；首次启动自动准备运行数据，不需要单独执行初始化。模型或运行参数变化不会把用户退回向导；绑定关系发生变化时在「账号与会话」中核对并重新确认。

## V1 数据迁移入口

V1 配置与运行数据迁移不属于首次设置流程，入口在「资料与维护 → V1 数据迁移」（`#manage/data/migration`）。该页独立挂载迁移工作区，不读取首次设置状态；用户仍须显式检查、试算、再执行。侦察只读；执行只写入当前 V2 目标，不删除或改写 V1。

当前转换器只覆盖 V1 宿主配置中的天气设置；其他来源会按 catalog 标记为只读保留、由外部插件负责、归属待定或暂缺转换器，不应误称为已迁移。V1 配置来源未被宿主传入时，天气转换还依赖 V1 数据根中的受支持配置转储。

## 路由

- `GET /setup/status`、`GET /setup/targets`
- `POST /setup/mode`（旧客户端兼容）、`POST /setup/binding/confirm`、`POST /setup/model`
- `POST /setup/complete`、`POST /setup/proactive-test`
- V1 迁移接口见 [19-data.md](19-data.md)

连接和绑定问题只在 AstrBot Dashboard 管理员会话下操作；状态端点不发送模型请求或平台消息。
