# CORE-02/08 宿主装配、生命周期与自动输入合并

更新时间：2026-09-22。独立 V2 工程已能通过模拟宿主自动完成“可信入站 → 连续消息合并 → 原角色生成及工具续答 → 分段投递 → 确认历史”。本切片提供可装配的端口与生命周期，没有注册真实 AstrBot 插件，也没有读取生产 V1 数据。

2026-09-23 更新：[公共后台协调与提醒投递](CORE_BACKGROUND_AND_AGENDA_DELIVERY_SLICE.md)及[日记每日/睡眠触发](CORE_JOURNAL_TRIGGER_AND_SELECTION_SLICE.md)已进入统一宿主生命周期；本文保留最初对话装配的验收范围。

## 装配入口

- [CompanionApplication](../companion_v2/host/application.py)：共用 V2 runtime、配置服务、任务监督器、模型网关、便签/来源/诊断工具、可选外部工具和 sender，持有所有自动调度及执行句柄。
- [AstrBotCompanionHost](../companion_v2/adapters/astrbot/application.py)：组合可信事件、认证身份、原人格提示词、运行身份和可选工具目录端口。入站原件发布与批次接受位于同一事务；接受失败不会留下半份入站资料。
- [ConversationFlow](../companion_v2/conversation/flow.py)：只管理本入口接受的批次、计时及分段进度。旧的手动测试批次不会因升级被自动加入执行队列。

宿主先提供独立 V2 runtime、共享字段注册表、模型任务/provider、预算、sender 及经认证的事件/人格端口，再显式启动。`application.start(expected_task_generation=..., expected_model_generation=...)` 必须取得两项原版本；`host.receive(event)` 返回持久批次标识，不等待模型或发送。运行中可以通过 `flow.observe(context, batch_id)` 查看脱敏状态，通过既有诊断工具查看原任务、配置和实际回执。

装配保留原人格、Bot、登录账号、完整窗口、受众和当前授权。工具端口沿用固定能力包/provider 及独立子任务；主动开关和多念头权重不影响用户请求工具。存在外部工具时，每个并行父任务预留一个子任务名额；普通调度只精确领取回复/发送任务，不抢走工具子任务。

## 合并和顺序

只合并同一完整上下文、人格版本及原人格提示词的开放批次。默认静默窗口为 0.6 秒，最长收集 2 秒，每批最多 32 条输入；重放同一事件不会刷新时间。新输入在静默期到期后才到达，或原批次已开始生成时，会形成后续批次。同一窗口按批次顺序执行，不同窗口可以在受控名额内独立推进。

合并参数与整轮截止时间在首条输入接受时持久化。重启及运行配置更换不会重新开始旧计时；旧运行代也不能改写计时。宿主重启后重放完全相同的事件时，复用首份记录的运行实例编号，其他身份、内容、来源、时间和人格字段仍要求一致。

本轮没有通过新消息取消并重启已发生的模型或工具调用，也没有实现语义打断、生成中追加上下文或已说片段重写。后续输入走独立批次，避免抹掉已发生的动作。撤回在封存前移除相应输入；封存后沿用整批依赖失效，停止尚未发出的部分。

默认分段间隔为 1.5 秒。首段生成成功后立即进入投递，后续段按上一段的真实送达时间计算间隔；已创建的投递任务保留原定时间。只有确认送达才进入历史；accepted、unknown、失败和缺失停止证据都不会触发自动重发。

上述数值是可信装配参数，尚未接管理页。整轮默认截止为 180 秒；过期的未完成批次停止推进。没有测量真实模型、平台或手机 p95，不能把此处计时视为实际回复延迟结果。

## 启动、恢复与停机

任务监督器与模型配置消费者的运行代在一个 SQLite 事务中取得；任一 CAS 冲突都会回滚，避免半启动。恢复按有限页处理：未派发的持久工作仍由原任务领取；已经开始而无法确定结果的任务保持 uncertain，原 worker 未证明停止前继续占有物理名额。旧运行代的输入、调度和计时写入都会被拒绝。

调度等待输入、任务完成、明确的宿主变更通知或最近截止时间。空闲时没有固定轮询；名额不足时保留原批次，以 0.25 秒有界重查等待资源，不重新接受消息。恢复只处理任务和原回执，不读取新资料冒充旧原件。

`application.close(grace_seconds=...)` 先关入站与自动调度，再对已在执行的工作做有界等待/取消，同时关闭外部工具 runner。尚未执行的批次和分段保留在数据库，下一次装配仍按原期限检查。任何不配合取消的实际句柄都会使结果保持 `draining`；它们继续占有名额，V2 数据库继续开放用于实际用量/回执落账。宿主应在实际句柄停止后再次调用 `close` 完成收尾。仅当装配明确拥有 runtime 且所有句柄已停止时才关闭数据库；共享 runtime 由宿主管理。

迟到回执可以记账，但不会自行恢复阻塞的发送。可信宿主显式调用 `reconcile_delivery(context, part_id)`，且原任务已停止、回执有效，才可能继续原批次。若用户已经产生后续批次，只补记事实并关闭旧批次剩余发送；取消、撤回、过期的批次不会因迟到回执重新启动。

## 存储与验证

内部 schema v13→v14 新增 `conversation_flows`，记录原批次、完整路由、合并键、阶段、原时间边界、参数快照和脱敏原因。没有复制消息正文、人格提示词或工具原件；它们仍由既有 owner 保存。保留 v13 及所有旧版本的固定指纹，验证非空升级、失败回滚、半迁移拒绝、旧原件/工具回执/已发历史保留。该升级不是生产 V1 用户数据迁移。

本轮新增 32 项测试：

- [自动宿主链](../tests/test_host_application.py)：真实事件计时、最大合并窗口/条数、重复消息、提示词变化、原角色便签工具、双 Bot/角色隔离、撤权/换人格、入站失败回滚、撤回/取消、空闲等待和启动 CAS。
- [恢复与停机](../tests/test_host_recovery.py)：运行实例变化、旧计时保留、重启分段、unknown/accepted、派发中丢失、迟到回执、后续输入、过期、容量等待及不配合取消的 provider。
- [外部工具装配](../tests/test_host_external_tools.py)：同时两组父/子任务保留独立名额，映射原会话及原人格，主动开关/权重不干扰工具，以及停机取消父子任务。
- [v14 迁移](../tests/test_host_storage.py)：非空 v13 数据、不可自动接管旧手动批次、迁移回滚、未来表和原指纹校验。

当前全量隔离回归为 **497 项通过（84.020 秒）**。其中宿主装配、生命周期和 v14 迁移的 32 项，以及容量重查不得重新开放合并窗口的补充断言均通过。另有 7 项 AstrBot 4.27.2 原生契约在独立临时数据根通过，网络尝试为 0；它们使用真实 SDK 类型、`httpx.MockTransport` 和内存 WebSocket peer，不代表生产模型或平台已经接通。`compileall`、静态隔离扫描、UTF-8 与本地 Markdown 链接检查通过。
