# 同一角色共享自动睡眠排程

日期：2026-09-24

本批把生活页里的自动睡眠设置从窗口局部值提升为同一 installation、逻辑 Bot 和 V2 role 的共享值，并保留日记时区、日记时间、阅读/写作权限的窗口范围。共享字段包括 `sleep_enabled`、`sleep_time`、`sleep_timezone`、`sleep_variation_minutes`、`sleep_window_minutes` 和 `sleep_minutes`；同一角色的任一有效窗口读取到同一份设置，修改后下一次入睡与计划唤醒时间一起重算。

`RoleSharedSettingsOwner` 先读取窗口层，再覆盖已有的角色层。角色层第一次写入时会接管当前窗口原有的睡眠字段，因此升级不会把旧窗口的计划静默改成默认值；旧配置缺少独立睡眠时区时，先沿用该窗口的日记时区。角色层已经有显式值后，其他窗口只能通过同一角色共享值读取和修改，不能再次覆盖首个接管值。

排程仍由一个实际窗口执行。协调器从同一角色的已绑定、未退休、已授权窗口中按稳定 context key 选择唯一执行者；管理状态现在同时返回共享 owner、执行窗口的平台/账号/会话标识、下一次入睡、计划唤醒和当前实际睡眠唤醒时间。窗口没有有效授权时只展示未安排，不会把排程偷偷交给另一角色或无绑定窗口。

生活页的作息区域标明 `installation / Bot / role` 共享范围，直接显示实际执行窗口和下一次入睡/唤醒时间。入睡观察窗口与压力阈值共同决定到点后何时入睡，窗口结束仍未困倦时按计划开始；生活页可编辑观察窗口，并显示睡眠压力、欠睡、近 24 小时负荷和推荐睡眠时长。睡眠记录保留睡眠时长、质量范围、打断次数、早期打断和赖床延长。页面继续使用原来的授权、操作回执和重试协议；旧 owner 为 `configuration` 的已持久配置操作可以按原 operation identity 重放，新的操作统一使用 `role.life.settings`，不会因为 owner 分区而产生 idempotency 冲突。

验证范围：

- `tests.test_role_sleep_configuration`：共享读写、旧窗口一次性接管、唯一执行者、旧 owner 回执重放、重启恢复及共享设置变更后的排程重算，共 5 项通过；
- `tools/check_life_page.cjs`：桌面、390px/320px 布局、实际执行窗口与睡眠生理指标展示、入睡观察窗口保存、丢回执幂等、删除/恢复、阅读、醒来、设置、键盘焦点、XSS 文本和撤权清空，共 1 个隔离页面场景；使用 AstrBot 外的本地合成桥接，不访问模型或 QQ；
- 无 schema 迁移、在线重载、真实模型/QQ 调用和 V1 数据访问，所有新增文本保持 UTF-8、无 BOM、LF。

当前负荷估值只使用角色近 24 小时私聊输入量与已记录阅读时长。其他工作/活动没有可信完成时长时不参与计算；接入新的劳累来源需要先定义可核验的角色活动回执，再扩展估值。状态维护页保留睡眠节律摘要，完整压力、欠睡与负荷指标在生活页展示。真实 QQ 自定义状态和正在输入回执仍需单独现场验收。

## 2026-10-14 页面收尾

生活页补入 `sleep_window_minutes` 配置，并将后端返回的睡眠压力、欠睡、近 24 小时负荷和推荐时长呈现出来。编辑位置为 `pages/日记与生活`；「陪伴小屋」工作区由 `tools/sync_framework_page.py` 生成。

当前源码的角色共享配置、生理规则和生活 API 定向测试 **17/17** 通过；页面 JS 语法、模拟数据字段合同、`sync_framework_page.py --check` 与 `git diff --check` 通过。更新后的 `tools/check_life_page.cjs` 完整浏览器流程暂未运行，当前 Node 环境缺少 `playwright` 模块。
