# 同一角色共享自动睡眠排程

日期：2026-09-24

本批把生活页里的自动睡眠设置从窗口局部值提升为同一 installation、逻辑 Bot 和 V2 role 的共享值，并保留日记时区、日记时间、阅读/写作权限的窗口范围。共享字段是 `sleep_enabled`、`sleep_time`、`sleep_timezone` 和 `sleep_minutes`；同一角色的任一有效窗口读取到同一份设置，修改后下一次入睡与计划唤醒时间一起重算。

`RoleSharedSettingsOwner` 先读取窗口层，再覆盖已有的角色层。角色层第一次写入时会接管当前窗口原有的睡眠字段，因此升级不会把旧窗口的计划静默改成默认值；旧配置缺少独立睡眠时区时，先沿用该窗口的日记时区。角色层已经有显式值后，其他窗口只能通过同一角色共享值读取和修改，不能再次覆盖首个接管值。

排程仍由一个实际窗口执行。协调器从同一角色的已绑定、未退休、已授权窗口中按稳定 context key 选择唯一执行者；管理状态现在同时返回共享 owner、执行窗口的平台/账号/会话标识、下一次入睡、计划唤醒和当前实际睡眠唤醒时间。窗口没有有效授权时只展示未安排，不会把排程偷偷交给另一角色或无绑定窗口。

生活页的作息区域标明 `installation / Bot / role` 共享范围，直接显示实际执行窗口和下一次入睡/唤醒时间。页面继续使用原来的授权、操作回执和重试协议；旧 owner 为 `configuration` 的已持久配置操作可以按原 operation identity 重放，新的操作统一使用 `role.life.settings`，不会因为 owner 分区而产生 idempotency 冲突。

验证范围：

- `tests.test_role_sleep_configuration`：共享读写、旧窗口一次性接管、唯一执行者、旧 owner 回执重放、重启恢复及共享设置变更后的排程重算，共 5 项通过；
- `tools/check_life_page.cjs`：桌面、390px/320px 布局、实际执行窗口展示、丢回执幂等、删除/恢复、阅读、醒来、设置、键盘焦点、XSS 文本和撤权清空，共 1 个隔离页面场景通过；使用 AstrBot 外的本地合成桥接和已安装 Chrome，不访问模型或 QQ；
- 无 schema 迁移、在线重载、真实模型/QQ 调用和 V1 数据访问，所有新增文本保持 UTF-8、无 BOM、LF。
