# V2 优化与升级整改计划

更新时间：2026-10-02。本文作为本轮整改的执行清单；历史审计保留原始结论，不用新文档覆盖旧证据。

## 原则

- 本轮用户明确授权保留显式的一次性 V1 迁移。迁移必须由管理者主动检查、试算并点击执行；启动过程不得探测或自动应用。V1 保持只读，写入只走已认证的 V2 配置 API。
- 规则门通过静态检查和定向测试证明；真实设备、外部发送及宿主环境没有实测的项目继续保持待验，不根据代码存在推断完成。
- 页面只呈现有实际合同的控件。配置 schema、宿主管理接口、公开页面与实现逐项对账。
- 不清理或重置现有工作树改动。构建测试使用当前源码，不能借用旧交付包结果。

## 本轮边界

阶段 1 优先消除与现行工程规则直接冲突的可执行路径。阶段 2 和阶段 3 涉及多个领域及页面接口，先逐项查清当前源码，不能仅按历史审计的旧行号批量修改。现实世界验收依赖真实 AstrBot、OneBot、可选伴侣及设备；没有这些环境时保留待验状态。

## 本轮执行记录（2026-10-02）

- 一次性迁移授权仅限显式管理者操作；启动自动迁移仍不启用。V1 输入保持只读。
- 群聊目标的「关系与记忆」工作区改为加载独立群公共档案页；私聊仍使用原关系记忆页。群页面接入生效陈述、原消息详情、管理员撤回、撤回操作回执、安全命中和仅记录结论的安全审阅。嵌入桥只允许该档案 API 的六类已注册方法，不能借群目标调用私聊路由。
- 修正生图 API 密钥清除：清除标志现在进入配置差异，提交 `api_key: ""`；新增页面回归测试。
- 复查导航：重复进入当前路由不会再次重置滚动位置；`tests/test_navigation.cjs` 覆盖该行为。导航组中只有一个「外观与设置」入口，`renderAppearancePageOriginal` 和旧 `appearancePanel` 属于未挂载的遗留实现，实际页面由 `appearance-page.js` 提供。
- 定向验证：隔离和迁移 62 项通过（65 个子用例）；Qzone 103 项通过；导航、外观、工作区和模型页面 84 项通过；宿主工作区 API Node 测试 64 项通过；唯一公开页嵌入构建 `--check` 和 `git diff --check` 通过。

- 外部/真机验收以及阶段 3、4、5 尚未完成；替换能力缺口和历史审计数字冲突仍需从当前源码生成统一基线。

## 已核实的起始状态

- 2026-10-02 在当前源码执行 `python -m pytest tests/test_isolation.py -q`：1 项失败、2 项通过，扫描报告 8 条违规（不是旧审计记录的 9 条）。
- 失败项包括 `qzone/configuration.py` 的动态导入、`legacy/migration.py` 的 V1 路径/SQLite 读取，以及 `references/management.py` 对 `BytesIO` 字节进行的图像解码。

- V1 迁移 API 只在显式管理者试算并点击确认后运行，不在启动时执行；schema 保留显式 `legacy.v1_root`，已删除没有实现的 `allow_auto_apply` 开关。
- 当前工作树中的 Image 密钥清除已有前端勾选和空值提交实现，Screen glance 开关也已接入「主动与联系」页面；两项仍需纳入新交付包统一验收，不能再记作源码缺失。
- 群公共记忆后端提供六条管理路由，现由唯一公开页的关系工作区按群目标呈现入口。
