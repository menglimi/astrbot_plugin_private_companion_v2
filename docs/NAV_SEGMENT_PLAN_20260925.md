# 陪伴小屋导航 · 第三版：按能力分段组织

日期：2026-09-25
替代：`NAV_LEAN_PLAN_20260925.md`（第二版，按 生活/关系/表达/设置 组织）
基准：`V1_CONFIG_TAXONOMY_20260925.md`（1010 条 / 21 子类）、`CAPABILITY_SEGMENTS_20260925.md`

## 一、为什么换掉第二版

第二版用「生活 / 关系 / 表达 / 设置」分组，有两个硬伤：

1. **「日程与状态」与「日记与生活」界限不明**。前者是计划、后者是记录，但都属于"角色今天怎么样"，用户分不清该去哪看。
2. **分组维度不直观**。生活/关系是按"内容主题"切的，设置是按"是不是配置"切的——两套维度混在一个列表里，没有一个统一答案回答"这条属于哪一组"。

改用能力分段后，分组维度统一为**信息在系统中的流向**，每段只回答一个问题：

| 段 | 回答的问题 |
|---|---|
| 感知 | 她从哪里得到信息 |
| 决策 | 她怎么认识你、决定做什么 |
| 行动 | 她实际去做了什么 |
| 产出 | 她做出了什么可留存的东西 |
| 表达 | 她怎么把它说出来 |
| 治理 | 谁说了算、花多少、留多久 |

## 二、首页与侧边栏的职责切分（关键改动）

**首页（小屋）不再是"总览跳转页"，而是生活内容的承载页。**

代码已支持：`workspaces/life/app.js` 用 `data-tab` 承载 archive（书写/日记）、reading、sleep、receipt（操作回执）等分区，`app.js:396` 的 `lifeEntries` 把书桌/日记→archive、床→sleep、沙发→reading。

因此以下内容**全部在首页内以标签形式呈现，不进侧边栏**：

- 角色状态（饱食/健康/睡眠/生理阶段）
- 日程与安排
- 日记、书写、梦境
- 阅读片段与睡眠记录
- 成长花架（有成长提案时出现）
- 操作回执

这直接消掉了第二版的「日程与状态 / 日记与生活」边界问题——它们本来就是同一个工作区里的两个标签。

## 三、侧边栏结构

**默认 7 个入口，按需 2 个**（组头无内容时整组不显示）。

| 段 | 入口 | 承载 | 类 |
|---|---|---|---|
| 感知 | 感知 | 世界源（天气/历法/预警）、交互源（收口/引用/撤回/群黑话）、媒体理解（识图/语音/视频） | 配置 |
| 决策 | 记忆与经历 | 共同经历、原话、来源（B1 73 条） | 内容 |

| 决策 | 主动与联系 | 主动强度、间隔、免打扰、群参与（B4 144 条，全分类最大子类） | 配置 |
| 行动 | 生活与活动 | 生活行为、一起活动、设备与直播、社交发布 | 按需 |
| 产出 | 创作与作品 | 图像生成、作品与相册 | 按需 |
| 表达 | 回复与表达 | 分段、注入、时机；语音与表情为页内分区（D 段 178 条） | 配置 |
| 治理 | 身份与权限 | 角色、人格、三档权限（E1） | 配置 |
| 治理 | 模型与连接 | 公共模型与任务路由（E2 44 条） | 配置 |

## 四、行动段与产出段的特殊性

**这两段在 V1 的 1010 条配置里几乎没有体量**（生活行为 8 条 + 社交发布 10 条 = 18 条，产出段 91 条里 55 条是生图）。

原因：伴侣活动（共读、棋桌、通话、设备、直播）的配置分散在七个伴侣插件各自的配置里，**不在主插件 schema 中**。所以侧边栏的「行动 / 产出」两组不是配置项入口，而是**能力状态聚合与跳转**——显示装了什么、接没接上、跳去哪配。

这也解释了为什么 V2 这两段默认可以隐藏：五个伴侣尚无原生业务链，组里本来就空。等能力接通，按 V1 的 `hidden` 机制长出组头即可，不必预先占位。

## 五、与第二版的差异对照

| 第二版 | 第三版 |
|---|---|
| 生活：日程与状态、日记与生活、主动与联系 | 首页承载状态/日程/日记；主动与联系移入决策段 |
| 关系：人物与关系、记忆与经历 | 决策段：人物与关系、记忆与经历 |
| 表达：回复与表达 | 表达段：回复与表达（不变） |
| 设置：感知能力、身份与权限、模型与连接 | 感知段：感知；治理段：身份与权限、模型与连接 |
| 创作与作品（按需） | 产出段：创作与作品（按需） |
| — | 行动段：生活与活动（按需，新增组） |
