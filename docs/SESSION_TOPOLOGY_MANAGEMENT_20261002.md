# 账号、角色／人格与会话窗口

## 页面合同

「陪伴小屋」的账号与会话工作区只表达一条拓扑：**账号 → 人格 → 会话窗口**。

- 账号表示 AstrBot 已连接的平台账号和 Bot 身份。
- 角色是人格的分组框。一个角色可以包住多个 AstrBot 人格，例如把「星缘-私聊」与「星缘-群聊」归入「星缘」。角色本身不作为连线端点。
- 人格是实际连线节点。账号连到每个人格，人格再连到它当前使用的私聊或群聊窗口；因此同一角色内的不同人格仍保持各自会话边界。
- 未关联窗口的人格可以在编辑器中隐藏。已经归入角色或保留草稿的人格不会因筛选消失。
- 群成员线索、熟人卡和私聊熟人属于关系网页面，负责辨认同一个平台成员和其出现过的窗口，不负责账号接管或角色映射。

## 配置与运行

账号卡内编辑角色名并勾选人格；保存请求只提交 `enabled`、`accounts` 和 `personas`。不再提交手工窗口清单，也不要求用户绑定窗口、执行探测、停止宿主或重启页面。

保存由后台校验当前账号和人格，保留历史身份与旧会话范围，应用新的角色映射，自动准备已存在的真实私聊窗口，并重新注册运行路由。通配私聊只表示“这个账号允许接收已核验的私聊窗口”，不会制造虚假成员；已经准备过的真实窗口在启动时直接绑定生活、状态和平台状态能力。

页面收到配置回执后增量刷新目录、工作区路由和关系网目录，保留当前选择与滚动位置。随后状态读取失败只提示目录暂时待刷新，不把已收到的保存结果改写成失败。

## 身份与历史

账号、平台、Bot、真实参与者和人格映射由后端核验。角色改名或合并只影响后续新作用域；历史会话仍保留原来的角色范围，避免旧消息跨角色漂移。窗口目录只读取 AstrBot 会话元数据与已核验的 V2 路由，不读取聊天正文，也不读取 V1 插件数据。

## 验证记录

本轮覆盖：桌面与 320px 页面、角色框内人格节点、账号→人格→窗口连线、高亮具体人格边、隐藏未关联人格、同 Bot 多账号映射、部分账号保存、保存回执后的增量刷新、自动准备已有私聊、群成员关系网只读展示，以及未授权管理账号不能保存。

浏览器合成检查使用 AstrBot 页面桥和合成账号，未调用真实模型、未发送平台消息。后端定向检查使用 AstrBot 自带 Python 与临时数据根；Windows 测试进程结束时可能留下 SDK 的临时数据库句柄提示，不影响测试结果。真实平台各类型主动消息完整链路仍需现场验收，本轮不以窗口准备测试代替该验收。
