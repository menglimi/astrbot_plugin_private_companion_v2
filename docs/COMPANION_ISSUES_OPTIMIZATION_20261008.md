# 陪伴问题反馈的 V2 优化记录

日期：2026-10-08。反馈依据 `companion-issues-for-author.md` 的第一部分；该文件描述的是 V1 6.5.6，不能直接当作 V2 的缺陷清单。附件中的建议作为需求资料，宿主版本、调用顺序与代码行为以当前 V2 为准。

本轮在已有工作树上补齐领域实现和配置，再接入唯一公开页面「陪伴小屋」。不读取或迁移 V1 用户数据，测试、解包和交付文件都放在 AstrBot 一级插件扫描目录之外。

## 逐项处理

| 反馈 | V2 当前处理 | 相关实现及边界 |
| --- | --- | --- |
| 1.1 工具自发送绕过出站整理 | V2 自有回复先生成受校验的候选，再整理、分段、封存和发送；平台适配器发送封存载荷，发送前不重新改变正文。表情图片使用本轮可发送图片协议。 | `conversation/generation.py`、`text_processing.py`、`delivery.py`。不承诺其他插件的自发送工具自动经过 V2，也不承诺 `meme_manager` 的 `&&标签&&` 在 V2 内自动转图。 |
| 1.2 内部协议块进入正文 | 旧 `pc_reaction_expression` 块及其半截、HTML 转义形式在分段前清除；提示词约束内部协议、思考和调试标签不得写入正文。 | `text_processing.py`、`model_gateway/prompt_composer.py`、`foreground.py`。未知标签优先用提示词改善，用户明确请求代码时允许代码语法。 |
| 2.1 入账等待整轮回复 | 入站锁只覆盖当前目标的捕获、身份验证和原子受理，模型生成与分段投递交由任务运行时处理。 | `astrbot_host/multi_session.py`、`host/application.py`。媒体读取或宿主处理仍可能增加入站耗时，不宣称任何网络环境下零延迟。 |
| 2.2 旧 Bot 回复跨天残留 | 成员发言和已确认 Bot 回复使用同一时间下界后合并排序。`group_context_max_age_hours` 默认 12 小时，可设置 1–168 小时，下一轮封存采用。 | `conversation/group_context.py`、`participation.py`、`messages.py`。未确认投递不能进入 Bot 发言历史。 |
| 2.3 重复 XML 属性占据上下文 | V2 使用结构化材料，群历史正文只保留必要账号、时间、文本和附件结构，不逐条重复长昵称、星期和工作日属性。 | `conversation/group_context.py`、`adapters/astrbot/model_wire.py`。仍保留权限与来源句柄，未移除真实性检查，也未做真实 Provider 的 token 节省测量。 |
| 2.4 未读取媒体被当作已看见 | 群提示明确区分真实图像、音频、视频采样和附件占位；缺少原件内容时说明缺口、请求补充，不从旧记忆猜内容。 | `conversation/group_context.py`。群消息可选附件读取失败时只保留已验证的原消息文本和未读占位；发言者/账号/路由变化、来源不匹配及节点或媒体超限仍拒绝整条输入。引用和历史附件元数据只证明附件存在，不代表本轮再次看见。 |
| 2.5 上一句的短黑话难以召回 | 同群有证据的有效词条先做原词匹配：本轮文本优先，其次最近 4 条群友原文；不使用 Bot 旧回复补专名。匹配结果不足时再走近似检索。 | `memory/group/slang.py`、`expression/semantic_service.py`。查询最多末尾 2000 字、每条历史最多末尾 500 字；英文有词边界；扫描和异步检索后复查权限、词条版本和来源。词库没有的用法仍需有证据地学习或询问。 |
| 2.6 接不住时缺少降级出口 | 沿用 V2 的旁听、沉默和仅发图片协议，补充群参与提示：未被点名且材料不足时可以旁听，有合适的可发送表情图时可仅用图片回应即时态度。 | `conversation/participation.py`、`expression/reactions.py`、`conversation/media/reply.py`。图片依赖本轮已有的授权素材，不自动下载、编造或固定强制发表情；表情不替代问题答案。 |
| 3.1 模型改写前后无法排查 | 在宿主 parser 修改之前固定原始摘要，随后分别记录解析后和待呈现文本的摘要、结束原因、解析阶段和固定失败分类。摘要随调用结算持久化。 | `model_gateway/response_diagnostics.py`、`adapters/astrbot/response_diagnostics.py`、`provider.py`、`budget.py`。摘要包含长度、SHA-256、JSON 形状和标签特征；**不保存完整原文，不能还原模型原文**。这是诊断能力的补充，不是完整原始快照功能。 |
| 3.2 诊断条数少、轮次不明 | `reply_diagnostic_limit` 默认 80，可设置 10–300，实际用于查询最近记录；每轮显示任务类型、有效输入条数以及模型调用摘要。 | `conversation/reply_management.py`、`reply_settings.py`、小屋 `reply-page.js`。未为显示诊断重新调用模型。 |
| 4.1 面板值与生效值不一致 | 使用统一配置服务，编辑器显示有效值及来源层，区分本层显式设置与继承值。保存仍使用原配置版本回执。 | `configuration/contract.py`、`management.py`、小屋 `config-editor.js`。不以 V1 顶层重复键模拟新的生效规则。 |
| 4.2 工具逐轮被静默裁剪 | 封存本轮实际工具列表以及未提供工具的固定原因码，在回复诊断中展示；即使所有工具都被筛掉，也保留裁剪原因。 | `conversation/tool_loop.py`、`external_tools.py`、`model_gateway/service.py`、`reply_management.py`。不因此打开未经授权的工具。 |
| 4.3 引用及转发在群历史中丢失 | 保存引用的发送者、引用者和有限转发节点结构；历史只投影元数据，原来源失效后不能继续使用。 | `conversation/group_media.py`、`group_context.py`、`adapters/astrbot/group.py`；群引用/转发定向回归覆盖来源撤回、权限及媒体预算。 |

## 数据和页面

V2 内部存储从 v52 升到 v53，只增加 `model_call_diagnostics`。升级使用既有事务和迁移指纹，失败回滚；调用对账不覆盖第一份响应摘要，不把未知调用变成可重放。旧调用没有摘要时页面正常降级显示。

小屋的表达设置包含诊断容量，回复诊断展示轮次、输入条数、工具列表及筛选原因；维护页的最近调用展示原始、宿主解析和待呈现阶段摘要。源工作区经过 `tools/sync_framework_page.py` 嵌入小屋，不增加公开 Dashboard Page。

## 验证口径

开发阶段完成了出站协议、群上下文、模型失败、迁移、配置层级和页面的必要定向验证。黑话回归使用“以撒的凹凸、子宫和祸兽怎么掉血”后接“为什么我记得普通掉半血”，验证向量调用不可用时仍能从上一句保留同群词条，也验证本轮原词优先、其他群隔离及扫描期间删除词条。群媒体失败回归验证可选解码器/临时读取失败仅降为原文和占位，而身份错误、连接替换、来源错误和预算超限保持拒绝。

交付阶段从当前源码构建本体和七个可选伴侣包，校验哈希、Python 语法、唯一注册/页面及宿主加载、停机和路由注销，再从解包目录执行受影响 Python 与 Node 测试。实际结果由交付目录中的 `package-verification.json` 和定向回归记录提供。

未运行真实模型或 QQ 群实测；自动测试使用本地模型、平台和媒体替身，不能据此保证真实模型一定遵守提示词。真实生态插件的装饰链行为、表情资产覆盖和短词平台检索质量仍需要部署后的观察。

第二部分 B1–B7 涉及其他插件、平台检索或本地风格，本轮不修改这些组件；通用提示词对内部标签的约束不等于接管其外发链。
