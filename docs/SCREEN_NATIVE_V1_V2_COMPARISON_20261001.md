# Screen 原生拓展：V1 功能与 V2 优化对照

核对日期：2026-10-01。对照 V1 主插件及 Screen Companion 3.3.1 源码、V2 Screen 提供方与核心消费链。只审查代码与能力合同，不读取 V1 用户数据。

## 功能对照

| 能力 | V1 | V2 原生 Screen | 结论 |
| --- | --- | --- | --- |
| 即时识屏 | `/kp` 截图、自然语言识屏工具 | `screen.capture` 原生工具；当前轮明确需要屏幕信息时，采集一次并交给续答模型 | 已覆盖，入口从命令/插件工具改为 V2 原生工具合同 |
| 主动窥屏 | 定时检查、概率触发、变化感知和主动回复 | `screen.peek` 后台任务；支持晚安后识屏和主动联系未回应后的沉默跟进，分别受日上限与冷却控制 | 主要场景已覆盖；没有移植 V1 的随机轮询与窗口变化探测 |
| 录屏识别 | `/kpr`，可按帧率、时长与 ffmpeg 采样 | 单次静态桌面截图 | 未覆盖。需要先定义视频原件、抽帧预算、受众和撤回语义 |
| 设备与桌面来源 | 本机、远程客户端、活动窗口/窗口轨迹及多类系统状态 | Screen 提供方绑定一个本机设备和平台账号；当前采集主显示器静态图 | 本机主屏已接；远程推流、活动窗口裁切、应用/站点轨迹、音量/内存/电量遥测未接 |
| 解读与连续上下文 | 可结合最近识屏结果、插件回复、短期记忆和应用描述 | 异步 `screen.interpretation` 任务；结果作为受治理来源，用户请求、主动窥屏与日记用途分别记录反馈锚点 | 已有解读与用途记录；V1 的持续活动轨迹和学习/纠偏体系没有整体移植 |
| 日记 | 可将昨日屏幕摘要作为独立上下文，并补充当日窗口轨迹 | 经授权的屏幕解读可融合到 V2 当日日记素材，条目长度受配置限制 | 采用日记融合方案；不读取 V1 日记文件，也不另建“昨日屏幕日记”上下文 |
| 撤回/转述 | V1 可缓存撤回消息并在转述中补发图片 | V2 只读展示获准窗口里的撤回原文；Screen 原图走 Source/Asset 授权，不自动补发 | 原图转述未覆盖，保持来源和受众治理边界 |

## V2 优化

- **按需触发**：`screen.capture` 不接受模型提供的文件路径、设备名或任意参数；V2 仅在当前私聊请求需要画面时调用已绑定设备。
- **分层授权**：Dashboard 管理员按当前私聊窗口授权；V2 每次采集、采纳、模型读取都会复核用户、角色、作用域和来源。Screen 提供方另核验平台实例、Bot 登录账号、设备绑定与当前安装代。
- **非阻塞解读**：采集原件提交后排入独立后台任务，当前回复不等待屏幕解读；窗口未启用解读时不会调用视觉模型。
- **范围和体积受限**：V1 本机提供方将图像缩到最长边 2048、JPEG quality 80，单件上限 5 MiB；V2 保存内容寻址原件，Source 有效期 30 分钟，覆盖范围与时间质量随记录保存。
- **重复与撤权可核对**：提供方以 invocation 记账；已知结果可回读，未知结果不自动重采。V2 撤权后重新校验原图和解读来源，授权恢复也不会复活旧权限下的结果。
- **不混入出站**：截图是模型观察输入，不会自动变成回复附件或转发内容。

## 未移植项与现场边界

当前 V2 Screen 仍是“私聊内按需或受控主动触发的一张静态截图”，不是 V1 的持续桌面监控套件。录屏、远程客户端、活动/输入统计、窗口变化探测、系统资源遥测和撤回图片转述均未覆盖；这些能力需要独立的数据合同、配置和授权，不能由 `screen.capture` 单次截图推定已经具备。

源码测试覆盖提供方回执、重启去重、授权变化、来源撤回、异步解读、主动触发、日记素材和宿主装卸。它们使用合成截图、模型与平台回执；不替代在线 V1 停用后的受控 QQ 私聊验收，也不证明远程采集或录屏现场可用。
