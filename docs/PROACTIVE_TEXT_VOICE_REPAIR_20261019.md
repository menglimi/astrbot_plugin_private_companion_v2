# 主动消息正文与语音修复

## 已核对的现象

2026-10-19 00:02 的主动消息已经生成完整正文，封存为三段；最后一段为“现在也安静下来了吗？”。旧发送器将该段文字与 record 放进同一条 OneBot 请求。接口返回消息 ID，但用户确认后半句文字未显示。平台回执不能证明混合请求中的每个组件都已在 QQ 展示。

主动语音旧路径直接截取中文正文，并构造默认 VoicePlan，未继承窗口保存的日语及对应 TTS 服务。另有旧台词在字数边界被切成半句话。

## 当前实现

- OneBot 混合文字、图片与语音时，必需内容和可选 record 分别请求；必需内容以自己的消息 ID 确认。语音单独记录结果，不将语音回执冒充文字回执。
- 文字已确认后，可选语音失败、撤权或取消均保留文字回执；文字未知时不追加尾随语音。若前置语音已发送或结果未知，后续文字受阻仍保留未知外部结果，不允许安全重放。
- 引用回复附在必需内容上，前置语音的顺序判断忽略 reply 元数据。每次外部发送前继续检查原账号、窗口人格和授权。
- 主动语音独立启停，同时继承窗口保存的语种、对应 TTS 服务、超时与位置。模型在同一次调用中分别提供完整可见 text 和适合朗读的 voice_text；参考字数作为提示，不按字符硬截。
- 外语台词缺失时只保留文字，不将中文正文静默交给外语 TTS。语音仍遵守已有的封存台词长度合同，过长时省略可选语音。
- 陪伴小屋说明语音设置来源及参考长度的含义。

## SQLite 与日程超时的边界

00:02 的慢事务来自主动联系准入，日志 lock_wait_ms 为 0，耗时主要在事务体。只读抽查的额度及历史轮次 SQL 均为毫秒量级，尚不能由此解释全部 2.277 秒。历史读取会反复校验相互依赖的旧投递；现在仅在同一次同步数据库快照内复用单条已验证记录，每个根仍检查依赖、引用冲突与祖先上限。后续读取和发送边界重新验证撤回及授权，没有跨调用缓存。尚无生产环境修复前后的耗时对比。

两条日程规划分别属于每日和新周机会，各在模型调用约 60 秒时超时，未取得响应或用量回执；不能解释为同一任务重试，也不能认定与 QQ 混发缺字是同一故障。当前日程模型继承的输出上限较大；本修复未据此盲目延长超时、修改额度或重放未知调用。

## 验证要求

从当前源码构建交付包后，验证包内主动语音语言、完整正文、引用回复、独立发送回执、超时、撤权、取消、未知结果不重放、历史快照复用及下次读取重新校验；同时验证唯一页面、宿主加载与停机、路由注销及迁移合同。测试使用合成数据和临时 AstrBot 数据根，不发送真实聊天消息。QQ 客户端展示仍需下一次实际消息核验。
