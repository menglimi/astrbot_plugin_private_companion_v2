# CORE-05 角色技能与长期目标正本

日期：2026-09-23。为角色成长建立可修订、可追溯的持久正本；本切片只负责可信领域存储，不从日程、日记或梦境推断成长。

## 已交付

`companion_v2/role_work/growth/` 定义技能和长期目标记录、稳定 JSON codec 与 `PersistentRoleGrowthLedger`。记录按 `RoleOwnerRef` 归属，绑定已解析的私聊 scope、同安装/Bot 的私聊来源引用、提案人和显式确认/变更主体。相同成长 ID 在不同角色下独立；单个角色的记录保留完整修订历史。

V2 内部数据库升至 v22。v21→v22 迁移增加当前记录、历史修订及操作回执表；升级保持原记忆表和数据，失败回滚 DDL/版本且可重试。角色成长写操作使用原操作账本、参数指纹与 expected revision；完全相同的新增可幂等重试，修改操作重放返回首次提交的结果。

成长记录从 `proposed` 开始，只有显式的人类确认才能进入 `active`；可暂停、恢复、完成目标或退休。技能使用文字进展记录，不使用数值熟练度或二元“已完成”。修订会产生新 revision、清除旧确认并重新进入 `proposed`，提案归属记为本次修订的提案人。闭合记录不能复活修改，过期 revision 不能覆盖新版本。

## 未接入的边界

初次交付仅含可信内部持久 ledger。2026-09-24 已接通普通对话读取边界与已认证 Dashboard 管理 API，独立人类操作者经当前身份/CORE 权限核验，记录每次提案、确认、修订和退出的实际归属；详见[成长授权读取与管理](CORE_ROLE_GROWTH_CONTEXT_SLICE_20260924.md)。成长管理页面和角色写工具仍待接入。

账本验证来源引用结构及私聊 Bot/安装范围，但不会在写入时验证 Source 当前有效性、受众或原文哈希。任何后续提示、工具或管理消费者都必须在展示正文前按当前主体重验每个 Source；不能把账本中保存的文本直接投影给另一会话。后续消费者已经在生成、逐段发送和管理正文投影前复核来源；来源撤回会使旧读取不可用。退出保留审计历史，物理删除治理仍未实现。

因此当前交付证明的是成长记录可持久保存和版本管理，不代表角色已经掌握某项技能、正在执行某个目标或允许任何受众读取这些内容。进展只能来自明确修订与原来源，不会因经过时间、计划到期、活动状态或日记措辞而自动增长。
