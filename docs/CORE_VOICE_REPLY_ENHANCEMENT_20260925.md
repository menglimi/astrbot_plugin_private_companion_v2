# V2 出站语音回复强化

2026-09-26 补充：[小屋语音配置与组合预览](CORE_REPLY_VOICE_SETTINGS_20260926.md)已落地。下文记录的是首批宿主配置行为；加载新版后，小屋按对象/角色保存的语音设置从下一次输入封存开始生效，无需重载，已封存回复保持原配置。

日期：2026-09-25。`voice_reply.enabled` 默认关闭，覆盖 V2 私聊和已授权群聊的被动回复。生成时封存每段可见文字和语音计划，投递时按原会话选择 AstrBot TTS Provider，或使用配置的通用/语种专用 Provider。配置修改需重载宿主；已封存回复继续使用原计划。

## 策略与分段

- `trigger_mode` 支持总是尝试、仅用户请求、模型自选；私聊和群聊概率可单独覆盖。概率按回复批次确定，同一批次的分段不会分别抽签。
- `generation_mode=plain` 朗读选中的可见段；`model_tag` 仅朗读模型置于 `<pc_tts>` 中的短句。模型提示说明标签、分段标记、外语译文和附加风格要求，标签不进入最终可见回复。`adaptive` 同样由标签决定是否朗读。
- `segment_mode` 可选每段、首段或末段。模型标记和规则分段先确定完整可见正文，再把朗读片段映射到相应段；语音计划不改变原文、图片归属、分段顺序或发送清单。
- `language` 可选中、日、英；外语 `foreign_text_mode` 可显示原文、译文或双语。译文缺失时按该语音标签保留原文，避免吞掉整段回复。语种专用 Provider ID 优先于通用 ID；全部留空时由 AstrBot 按原会话选择。
- `delivery_mode=voice_only` 仅在合成成功且朗读覆盖整段文字时隐藏该段文字。部分朗读、译文与语音内容不同、超长或合成失败时保留完整文字。

每段文字、原图和语音使用同一次 OneBot 调用与 ACK。`position` 可使语音位于文字前、文字后图片前，或图片后（默认）；各分段仍逐段确认，前段 ACK 未知时不投递后段。冷却按安装、平台、私/群、Bot、账号、会话及角色隔离；同批次后段可继续发声，新回复在冷却期仅发送图文。合成期间取消会释放发送前的冷却占位，投递结果未知不会释放并重试。

音频仅从 AstrBot 临时目录读取，要求非空且不超过 8 MB。合成失败、超时、Provider 不可用时保留图文；等待合成后重新核对授权、人格和原账号连接，再执行原投递栅栏。语音开关不重钉已初始化运行档的身份指纹。

## 验证与边界

使用 `E:/astrbot/backend/python/python.exe`、`E:/astrbot/backend/app` 和隔离的临时 `ASTRBOT_ROOT`。本轮策略、Provider 与 OneBot 定向 **15 项通过**，包含模型标签、外语译文、语音计划持久化、两段语音和图片在真实 SDK 形状下的本地 socket ACK。此前私群语音、分段、迁移和生命周期范围 **62 项通过**；两组有重叠，不相加。基础链记录见[原出站语音接入](CORE_VOICE_REPLY_20260925.md)。

本地验证使用合成模型、音频和 socket，没有调用真实 TTS Provider 或向 QQ 发送。真实 QQ 客户端能否正确显示图文与语音混合组件、具体 Provider 音频格式、延迟和体积仍需现场验收。旧版 MiMo Voice Clone、独立文本转换模型、Fish Audio 专用情绪控制、主动消息语音和本机播放属于独立能力链，本次被动回复强化没有接入，也不声称 V1 全功能对等。
