## 接入边界

`_conf_schema.json` 的宿主原生设置仍由 AstrBot 表单维护。拓展页只在已有安全读写接口时提供编辑；提供方安装、状态可见或有跳转入口，不等于其 V1 配置项已迁入。感知页的屏幕和现实来源设置由对应插件保存；小屋天气只是本地场景偏好，不代表 V2 已接入天气感知。行动与产出的提供方状态也不代表社交发布或作品配置已接入。治理页中的预算服务与页面读写进度分开记录。

## 进度表维护

- `V1_V2_SUBCATEGORY_PROGRESS_20260926.csv`：23 行子类汇总，记录所属页、V1 数量、子类状态、已有范围、待办与依据。
- `V1_V2_CONFIG_PROGRESS_20260926.csv`：1010 行逐项清单。`V2子类进度`从汇总表带入，`V2配置项进度`初始均为「待逐项核对」，不能用子类的「部分接入」批量推断每个配置键已完成。
- 核实某个配置键后，在逐项表填写 `V2配置项进度`、`V2实现依据`、`下一步`；子类范围或页面归属发生变化时更新汇总表。重新运行 `tools/update_v1_v2_config_progress.py` 会同步汇总字段，并保留逐项人工审核的三个字段。
- 原始 `V1_CONFIG_BY_SEGMENT_20260925.csv` 实际是 XLSX 容器，只作只读分类来源；不改写原始文件。生成的进度表才是 UTF-8 CSV。

页面分区只说明配置将放在哪里。新增真实功能时，应同时核对对应 V1 配置键、更新实现依据和定向测试，再将状态从「待接入」或「部分接入」推进。
