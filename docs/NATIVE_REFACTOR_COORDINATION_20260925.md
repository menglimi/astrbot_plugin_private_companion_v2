## 完成标准

- 不存在或停用 V1 核心时，V2 本体及原生提供方可以加载、启停和完成对应业务；不调用 V1 私有 API，不读写或自动迁移 V1 用户数据。
- 沿 V2 的任务、身份、原角色、原受众、能力授权、来源和回执合同执行。状态展示不代表提供方可执行，产物生成不代表角色采用或平台已发送。
- 生成/编辑、产物保存、采用和最终投递分别留据。unknown 不换调用编号自动重做；重启只读取原正本及核对原回执。
- 纯后端调用可以复用；旧宿主绑定、用户路径、调度及隐式授权需要解除。可选伴侣保留各自插件身份，本体与公开小屋入口沿既有统一约定。
- 代码按领域分层，新增实现不堆回根目录；临时副本、日志和验收数据库位于插件扫描目录外。

## 接口交接

原生协议以 `NATIVE_PROVIDER_CONTRACT_20260925.md` 为唯一依据。插件不导入另一个插件临时命名空间下的核心类型；宿主负责将原请求映射为版本化文档，并把产物字节转换为核心可信图片合同。

核心外部调用已提供默认空的同步 `before_dispatch` 护栏，复查原 task、package、role、consent 与实例代；端口在实际 I/O 前执行它。宿主另复核异步角色绑定。Image 产物携带 provider operation、artifact ID、内容哈希及媒体信息；字节只进入有界媒体管道，不作为 base64 工具文字发送给模型。合法成功先按原请求验证回执，之后撤权或采用失败仍保留控制回执，材料转为不可读。

模型在本轮选择可发送产物后，采用结果封存到既有回复图片清单，最终投递复用 V2 sender、原群/私聊受众和图文回执。失败或未知执行不会生成可发送图片。

## 验收顺序

1. 独立 owner 与协议专项：幂等、参数/作用域冲突、撤权、unknown、重启与产物不可变。
2. V2 对话联合：工具生成/编辑 → 原产物读取 → 模型选择 → 保存采用 → 原 sender → 图文回执和历史；未知及迟到回执不得重复生成/发送。
3. 无 V1 的真实 SDK 临时进程：只加载 V2 与原生提供方，合成后端/模型/平台，验证导入、启停、授权、撤权、路由注销及数据目录隔离。
4. 各切片实际通过后才更新安装快照。真实后端与 QQ 现场效果单独安排，不能由合成测试代替。

首批完成后依赖审查记录安排 Together、Screen、Reality、Game、Live 的原生执行切片，不把七个旧入口的简单包装作为七个重构完成项。
