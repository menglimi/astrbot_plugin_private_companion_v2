# 原生工具目录装配与模型预算

日期：2026-09-25。

Content 接入时暴露两个实际阻塞：宿主构造按安装内全部注册动作计数，未授权工具也会使启动失败；即使按上下文过滤，默认重要用户的核心工具加 Content 七项仍有 36 项，超过原来各处独立写死的 32 项。

现在安装时保留已注册 owner，模型回合开始前才在同一数据库读取快照内收集当前上下文的可用工具。核心记忆、关系、成长、日历、外部能力继续使用各自的当前授权检查，便签和提醒目录也复核 feature_access。群工具保持群公共范围，不暴露私人 Content 或关系工具。

模型目录统一使用 `model_gateway.models.MAX_TOOL_CATALOG = 64`。角色工具、模型网关和 AstrBot wire 共用该合同，别名逐一对应原动作；已声明的操作不会因注册顺序被截断，后续轮次也不能临时获得原目录未提供的工具。上游原生声明和宿主工具映射同步使用该目录预算。

实际可用目录超过上限时，在模型调用和工具派发前返回 `tool_catalog_budget_exceeded`，说明实际数量和上限；不改变授权记录，不猜测应删除哪个工具。每轮业务调用次数、来源数量、结果字节、模型回合和费用预算继续由各自原合同核查。

专项 `tests/test_tool_catalog.py` 验证注册全集不阻塞装配、当前授权和撤权、完整保留七个外部操作、64 项完整进入模型会话、65 项在 I/O 前拒绝。`test_astrbot_model_wire.py` 新增 64 个别名完整送入 native provider 并能返回最后一项动作、65 项不新增调用的测试。

工具目录与模型 wire 共 **19 项通过**；既有角色工具、外部执行和外部宿主共 **49 项通过**；上游声明边界、原生合同、映射、目录和宿主共 **43 项通过**，其中新增 3 项 64/65 边界测试。各范围有重叠，不相加计算总数。测试使用临时数据根和 AstrBot 自带 Python，模型调用均为本地替身。Content 全链实测另在消费者交付记录中报告，不以目录专项代替。

下一步根据实际提供方工具数量继续检查目录与执行注册预算，保持生产实例、当前授权和模型已见动作一致。
