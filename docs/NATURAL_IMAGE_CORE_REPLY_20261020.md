# 自然语言生图接入核心回复（2026-10-20）

## 现象与原因

用户说“来张自拍看看”，随后补充“看看”“当然”，角色持续用文字确认、整理头发并改邀其他活动，没有交付图片。

源码对照发现三处缺口：

- 图片调用偏好仅由 `conversation/generation.py` 的 V2 自有回复流程注入，AstrBot 核心回复工具入口没有读取 `conversation.image_output`。自然语言触发、提示词格式与场景预设因此没有进入实际对话请求。
- 人设参考图、衣柜与每日穿搭也只接在自有回复流程，核心模型没有获得可用 `reference_ids`，难以选择基于角色身份的自拍。
- 图片工具的通用描述称“采用和发送由 V2 负责”。核心路径实际返回 MCP 图片，AstrBot 先缓存图片、展示给模型，后续仍需要调用 `send_message_to_user`。仅调用生成工具不会自动交付。

以上是可复现的接线缺口；用户粘贴的对话没有附当轮工具日志，不能据此断定当轮是否曾尝试调用或后端是否配置可用。

## V1 对照

只读查看 V1 保留的测试及 `_private_companion_backups/_worktree_pr215_20260909` 源码。`llm_tool_actions.py::_photo_generation_tool_prompt_section` 与 `main.py::pc_generate_photo` 说明自拍、穿搭、续拍、参考图选择和真实投递；`main.py::_annotate_photo_tool_prompt_format_for_request` 将格式标注到请求专属工具，避免污染共享目录。

V1 默认 `tool_first`，由主模型理解普通聊天后调用图片工具；可选 `rule_fast` 才在主链前匹配明确请求。此次沿用工具优先思路，不新增关键词拦截、自动强制生图或补发任务。V2 现有 `rules` 仍沿用图片工具并应用其额外每日限额，本轮没有新增 V1 前置快判器。

## 实现

- `conversation/media/output_settings.py` 补充自然语言自拍、画图、穿搭与改图的语义示例。未完成的看图请求可按近邻历史理解短跟进；明确请求直接执行，画面缺少关键信息才追问；已完成请求不会因普通应声再次生成。
- `astrbot_host/core_reply_image_prompt.py` 读取当前角色的有效偏好，按真实开放的操作展示生成、参考图改图与局部编辑工具。用户生图关闭时从本次请求移除图片工具；执行边界仍复核开关、额度与授权，旧工具对象不能绕过关闭。
- 请求专属工具描述和 `prompt` 参数说明同时标注自拍与当前回复链的投递语义，保持提供方共享目录及原调用身份不变。
- 稳定规则留在 system。角色参考图、衣柜与每日穿搭通过既有临时 `companion_v2_context.image_reference_material` 注入当前 user 消息，按入站时刻及感知时区读取，供模型选择身份和服装参考；不写入持久历史，也不随素材更换改动 system 前缀。
- 复用现有 Image 原操作、MCP 原图、AstrBot 图片缓存及当前会话发送工具。生成成功后使用工具返回的原路径投递，unknown 不换编号重放。

## 检验范围

定向验收覆盖自然语言与短跟进指导、角色偏好传到原图片提供方、请求工具描述隔离、关闭后旧工具复核、临时参考资料及时区、稳定 system 前缀，以及真实 SDK 工具循环中的生成→图片缓存→当前会话投递。模型、图片后端和平台发送均使用本地替身，不向真实聊天发送消息；模型的自由语义选择仍需在重载后的实际会话中观察。
