# 回复链路与 V1 分段默认值

本次只读取用户明确授权的 V1 分段配置。V1 私聊／群聊独立档开关关闭，因此以全局值为准；不读取或迁移 V1 记忆、身份等数据。

| 配置 | 已选择的分段预设 |
| --- | --- |
| 分段总开关／模型分段 | 开启／关闭 |
| 规则方式／正文长度上限 | 按词／500 字 |
| 每段最短长度／最多条数 | 5 字／5 条 |
| 分段词 | 沿用 V1 标点列表，按原顺序去重 |
| 全角／半角匹配 | 开启 |
| 清理方式／范围／清理词 | 按词／仅句尾（每段末尾）／“。”、“，” |
| 内容替换 | 关闭，无替换规则 |
| 间隔 | 对数模式，基数 2.1 |
| 随机模式备用范围 | 1.5～3.5 秒 |

V1 的对数模式按字数计算间隔并附加最多 0.5 秒的变化，随机模式的上下限不会限制对数模式。V2 保留此行为，同一封存回复的间隔保持稳定。

该预设将清理范围设为 `trailing`；短句合并在同一消息中时，句中标点保留，每段结尾连续的清理词会移除。当前新配置默认关闭内容清理，正文标点保留；显式保存的清理开关、范围和清理词仍按该会话配置执行。此记录说明历史预设，不要求重新读取或迁移 V1 数据。

日志桥只连接 `companion_v2`、本插件的 `astrbot_host` 和对应相对导入命名空间，使用 AstrBot 正式插件 logger。重载替换旧桥，正常停机恢复原 logger 配置；不修改 Python root logger、AstrBot 主 logger 或其他插件。

回复前台任务启动后再执行周期维护。私聊语义增强只生成当前意图向量，事实与经历共用它；文档索引补全使用既有后台任务与权限检查。向量服务失败时仍使用已封存的词法上下文。

分段低层仍保持原字符与语音源偏移，最终发送前只移除首尾空白行。内部段落、代码缩进、授权原文和已封存的投递计划继续按原合同处理。提示词明确允许本轮启用的分段与语音协议。

`tools/migrate_reply_segmentation.py` 复用现有 V1 配置转换规则。默认仅预览；显式 `--apply` 会备份指定的 V2 配置，更新插件和指定 V2 运行档，并通过回复配置 owner、修订检查和操作台账写入指定回复所属会话。迁移报告保存旧分段值与操作 ID，不保存其他配置或凭据。

验收使用本次源码构建的新交付包；结果见交付目录的 `verification.json` 与 `reply-tests.log`。

新增 `streaming_mode=buffered|incremental`，默认 `buffered` 保留收齐后分段；小屋启用流式后可切换。`incremental` 要求模型先输出 action、claims、可选 images，最后输出 text，程序按 JSON 字符串语法增量解码，仅发送正文。引用来源、原人格、权限、任务和模型调用在发送前复核。工具调用仍须收齐，思考和原始 JSON 不进入投递。

流式分段按收到的正文识别词、正则及模型标记，最短字数和最多段数生效；最后一段收齐后发送。已发送段落固定，阈值按当时收到的字数判断，超过阈值后停止新增规则边界。每段经清理和可信投递 owner 发送，按封存节奏等待回执。语音或图片组合、未遵守字段顺序的模型和单槽运行环境保留收齐发送。流式模式无法撤销已发内容；中断、权限变化或结果未知会停止剩余段落并记录未完成，不自动重发。

存储 v54 增加流式发布记录，区分开放、完成与中断；原有已封存完整回复保持原投递合同。

重载现场修复：旧主动联系记录缺少 `parts` 时，从原联系正文及已封存指纹恢复单段请求，继续校验原窗口与正文指纹。最终段和过期机会不再尝试推进；后台扫描排除过期分段，避免旧记录反复占用扫描名额，不重放已发或结果未知的消息。

慢模型工具续答修复：日历及近期纪念日投影固定使用本批最后一条已封存输入的接收时间，跨分钟、跨日续答保持同一材料。权限、来源有效期和工具结果仍使用实时观测时间复核。模型会话的不匹配日志只记录任务、轮次及变化字段名，保留原身份、人格、流式模式、提示词前缀和材料变更授权校验。

最小回归覆盖旧单段回执、原窗口边界、过期分段不重放、跨分钟／跨日材料稳定、65 秒群参与工具续答，以及不可变字段变更必须在调用模型前拒绝。最终交付包需重新执行回复、流式、主动联系与宿主生命周期检查。
