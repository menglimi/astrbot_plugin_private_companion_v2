# 我会永远陪着你 V2.0

版本：2.1.0 · 当前改造日期：2026-10-10 · 声明兼容 AstrBot >=4.27.2,<5，验收基线为 4.27.2。

本版把已经落地的 V2 领域框架、AstrBot 宿主和体素小屋组织为一个可安装插件。插件目录为 `astrbot_plugin_private_companion_v2`，拓展页的正式入口为 **我会永远陪着你 V2.0 → 陪伴小屋**。

2026-10-10：普通私聊和获准群聊已回归 AstrBot 核心回复管线。模型选择、工具循环、流式、分段、TTS、其他插件装饰与平台发送使用核心路径；V2 提供当前窗口背景、表达提示和原生工具。关闭的窗口、明确拒绝和群旁听仍保持安静。治理页分别展示核心回复、历史 V2 回复和插件任务的实际观测，发送调用返回不作为平台送达确认。技术说明见 [核心回复路径](V2_CORE_REPLY_PATH_DESIGN.md)。

## 安装包

- `astrbot_plugin_private_companion_v2-2.1.0.zip`：唯一安装包，包含本体、七项原生内部拓展、配置 schema、小屋与管理工作区、测试与构建工具。AstrBot 只注册一个 V2 Star。
- `release-manifest.json`、`SHA256SUMS.txt`：记录同一个 V2 包的版本、文件数量、包哈希、七项内部模块清单及执行归属。
- 包内 `RELEASE_FILES.json`：逐文件 SHA-256 清单，以及唯一注册和原生模块清单；验收从新解包副本运行。

已安装本体的本机可直接从 Dashboard 打开小屋。其他安装环境在 AstrBot 插件管理中导入本体 ZIP，或将 ZIP 内唯一的插件目录放入 AstrBot 的 `data/plugins/`。依赖由 `requirements.txt` 声明；Windows 使用 `tzdata` 提供时区数据。

| 角色状态 | 饥饿、健康、睡眠、周期、共享作息、日历和 QQ 展示诊断 | 小屋「日程」及「角色状态」 |

| 主动与后台 | 便签/提醒、主动联系、免打扰、后台队列、公平调度、预算和未知结果恢复 | 领域服务、原角色工具及已有管理 API |

## 七项原生内部拓展

| 模块 | 随包能力与资源 | 小屋入口 |
| --- | --- | --- |
| Content | 作品/候选、不可变版本、采用、读取与撤回传播 | 创作书架 |
| Image | 原生生成/采用/投递、私聊多参考及蒙版局部编辑、后端配置 | 画面工作室 |
| Screen | 单次本地屏幕采集、V2 原件及模型图片上下文 | 屏幕台 |
| Reality | 设备、现实来源、手机终端及设备测试资产 | 现实设备台 |
| Together | 共读、观影、通话及房间网页 | 共处电话 |
| Game | 原生对局规则、房间与共同游戏网页 | 游戏棋桌 |
| Live | 直播、角色呈现、Bilibili 客户端、VTS/SoulLink 运行模块 | 直播与表演 |

七项模块归同一个 V2 插件，执行入口和配置随包提供，启停由 V2 生命周期管理。领域代码分别位于 `companion_v2/content/`、`reality/`、`together/`、`games/`、`live/` 等目录；SDK 集成、原生配置及网页/设备资产位于 `astrbot_host/native_extensions/`。安装一个 V2 包即可获得这些入口，同级旧伴侣插件不作为运行依赖。

涉及外部服务的能力按小屋实际设置和授权启用：Image 需要真实图像后端，Reality 需要设备或手机终端连接，Together/Game 的远程房间需要可达服务，Live 需要对应直播或 VTS/SoulLink 连接。Screen 的采集由当前私聊权限决定。未连接外部后端时，如实显示就绪状态。

七项模块使用 V2 独立数据根的内部拓展目录，V1 读取仅在用户明确请求的正式迁移流程中发生。Live 的运行模块随包提供；个人 Live2D 模型及桌宠/VTS 独立客户端仍由实际使用环境提供。

## 配置与运行

1. 在插件配置中设置单目标 `staging`，或启用 `multi_host` 并配置目标/角色映射。已有兼容键名继续使用，避免破坏原 V2 配置。
2. 保存并重载 V2。打开小屋 → 开始使用，先选择单/多账号与单/多人格，再在核心管理员私聊窗口发送固定绑定指令并确认。
3. 绑定确认后配置插件模型，再补世界知识、关系教学和主动消息测试。向导完成后不会要求每次使用插件都重新配置。
4. 主动消息和独立插件任务使用正式 OneBot 投递；旧配置里的 `delivery_mode: preview` 只在读取时归一化为 `onebot_private`。普通聊天的回复、分段和 TTS 使用 AstrBot 当前会话设置。
5. 真实投递使用已绑定的账号、平台、私聊对象、人格与按人权限。已保存且启用的 V2 会话可在重载后恢复；普通回复由 AstrBot 核心生成和发送，模型参数变化不会阻止固定运行实例连接。
6. 小屋顶端选择会话对象和角色。首页、记忆、关系、状态、生活和成长使用同一选择；切换对象或失去权限时清空旧内容。
7. 在小屋对应家具中启用和配置七项内部拓展，填写实际连接信息。V2 包统一更新这些模块及资源。

V2 使用独立数据根，已有 V2 Profile/installation 继续按原契约读取。不要把旧数据库复制为 V2 运行库。
2.1.0 内部能力目录升级仅处理已有 V2 能力记录，将旧提供方身份转换为内部模块身份，保留生命周期状态、授权、角色选择和历史；此自动升级不读取 V1 数据。
V1 配置迁移采用只读检查、试算、再写入 V2 的单向流程：配置台账逐键审计，403 条通用规则覆盖 V2 配置注册表、插件设置和语义目录，账号/目标/人格及天气、分段、技能强度另由专用转换器处理。无法表示或仍未实现的配置会在试算中说明，不会按相似名称硬写；V1 原数据不被修改。记忆、关系档案、工作/投递记录和世界资源等用户数据仍不属于此配置迁移范围。

## 页面与数据边界

- 小屋是唯一公开 V2 拓展页，不再以 Content 静态预览目录作为规范源。宿主、日记生活、关系记忆三个工作区的源码入口改为 `workspace.html`，保留完整功能并从小屋进入；Content 预览移至 `design-previews/companion-v2/`。
- 宿主内首页读取真实的生活、状态、记忆、关系和成长摘要；无记录时为空，不显示设计样例。
- 独立工作区被构建为小屋内部资源，通过已登录 Dashboard 的消息桥复用原 API，适配 AstrBot 的 opaque-origin iframe 沙箱。
- 天气实况使用明确配置的角色地点；感知总览显示当前读数，私聊询问天气时按需读取，日常计划可参考。关闭天气感知后不读取天气源，也不访问精确 GPS。场景时段和家具摆放仍属于显示偏好；沙箱禁止本地存储时，布置仅保留当前页面会话。
- 衣柜是陈设；没有新增衣橱、换装或手账业务。见闻电台尚未接入新闻工作台。
- [群聊已有原图出站](CORE_GROUP_IMAGE_DELIVERY_20260925.md)已通过本地模型替身和真实 SDK 验收；Image 原生生成、编辑和局部编辑有合成回归，真实后端与 QQ 客户端效果仍需现场验收。群聊蒙版局部编辑明确关闭；群语音/视频出站、真实多账号连续运行、完整模型/提示词/主动联系管理页面也仍需后续工作。已有模拟/SDK 检查不等于这些平台效果均已验收。

## 构建与验证

所有源码文本采用 UTF-8、无 BOM、LF。打包使用允许目录与文件清单，跳过用户数据、缓存、日志、凭据配置、个人模型和构建产物。构建脚本核对七项内部模块、配置与运行资产、唯一 Star、代码语法、JSON、版本、页面清单及常见凭据模式，敏感值不输出。

构建器同时固定 Content、Image、Screen、Reality、Together、Game、Live 七项原生能力的运行时工件哈希与发行版本。修改这些能力对应的哈希源文件时，必须先提升产品发行版本并同步 `metadata.yaml`、`pyproject.toml` 与产品版本，再运行 `python tools/build_v2_release.py --refresh-native-capability-baseline`。普通构建和解包验收都会核对基线；同一版本下哈希变化或基线过期都会失败。

```powershell
python -X utf8 tools/sync_framework_page.py
python -X utf8 tools/sync_framework_page.py --check
python -X utf8 tools/build_v2_release.py --output <交付目录>
python -X utf8 tools/verify_v2_release.py --release <交付目录> --extract-to <新的验收目录>
```

构建脚本只读取当前 V2 源码，默认生成一个包含七项内部拓展的 ZIP。旧 `--core-only` 是兼容参数，产物相同。验证脚本检查单包哈希、逐文件清单、七项模块及资源、唯一注册、默认设置和唯一公开页；使用 AstrBot 自带 Python 加 `--host-check` 可验证新解包副本的临时宿主和迁移合同。该检查将 SDK 数据根设为临时目录，导入路径仅含候选包与 `backend/app`。页面静态设计预览可用 `tools/sync_framework_page.py --preview <预览目录>` 单独发布；静态预览不提供 Dashboard 业务连接。

本轮七项内部拓展的单包构建及验收状态见 [V2.0 整合验收](INTEGRATION_ACCEPTANCE_V2_0.md)，领域和小屋改造完成后统一执行。此前的 [核心管线验收](CORE_REPLY_ACCEPTANCE_20261010.md) 和 [Screen 接入记录](SCREEN_NATIVE_HOST_INTEGRATION_20260926.md) 保留历史结果，不替代新单包验证。完整历史见 [构建状态](BUILD_STATUS.md)。
