## 2. 一个字段定义，一个数据归属

核心与拓展都向公共配置服务登记字段。定义可以按领域拆文件，应用装配时形成同一版本化注册表；不再在前端、API、启动加载和工具中分别维护概率名单、默认值及允许字段表。

| 字段定义必须包含 | 用途 |
| --- | --- |
| 稳定命名空间/字段 ID、schema 版本、数据 owner、旧字段别名与适用版本 | 防重名、防错迁；注册冲突在装配时暴露。别名不成为第二份写入正本。 |
| 类型、存储单位、显示单位、合法范围、精度、枚举、空值规则及默认值 | 服务端校验、页面控件、工具参数、导入导出共用；服务端始终复核。 |
| 适用 scope、继承顺序、可写身份、敏感级别、依赖和启用条件 | 不能把公共参数误存为人格参数，或把读取权限误当配置权限。 |
| 消费模块、生效边界、迁移规则、废弃/替代关系 | 知道由谁读取、何时采用、失败如何恢复；升级不静默丢弃显式选择。 |
| 分组、名称、搜索别名、基础/高级级别、控件种类及自定义编辑器 ID | 生成轻量目录和按需表单；自定义编辑器也走同一读写协议。 |

字段接入需核对定义、写入 owner、运行读取者及实际入口四者一致，并以注册表驱动检查默认值、校验边界与读写往返。只有表单而没有消费者的字段不能显示为可生效设置；只读字段和未接入功能明确标识。高风险的跨字段关系另做领域验证，不为千项配置各维护一份手写表单测试。

继承沿 CORE-01 按字段解析适用的安装、Bot/角色、关系/用户和窗口层级，不把所有字段都强行放进同一继承链。返回有效值、来源以及参与解析的修订；显式 `false`、`0`、空字符串、空集合与缺失分别处理。只有定义允许的字段接受 `null`；“恢复继承”是显式操作，不使用 `-1`、空输入或 `null` 通用代指。

运行依赖与配置值分开。例如用户设为开启但设备未连接，应显示“已开启，待连接”；角色覆盖了公共值则显示实际采用的角色值及来源。不要把依赖不满足时的临时停用写回成用户关闭。

配置服务是共同入口，不接管所有领域数据。已有 [CapabilitySettings](../companion_v2/capabilities/models.py)及其 Repository 接入相应 owner 适配器，迁移或适配后只有一份权威记录；家具、列表、工具读取同一投影。安装、丢弃、设备授权和撤权继续走各自操作服务，不能伪装成任意可写布尔设置。

宿主配置页、独立 WebUI、引导、导入及聊天调参均调用同一服务。宿主必需的启动定位参数单独登记为 bootstrap 项；宿主镜像有版本和方向，运行模块不再同时从宿主文件、页面缓存及自身属性选择“最新值”。敏感字段返回是否已设置及可用状态，不回传原文；遮罩值不参加保存，搜索、审计和普通导出不携带凭据。

## 3. 从保存到实际采用

### 3.1 写入协议

1. 页面按当前安装/角色/scope 取得所需分组的定义、显式值、有效值、来源、schema 版本及解析修订。解析修订覆盖该字段依赖的上级配置和当前绑定，不能只比较本层版本。
2. 草稿保存基线和字段差异。提交携带原操作 ID、精确目标、预期修订、`set` 和 `reset_to_inherit`；不把未打开、未修改的字段或整个 overview 重新提交。
3. 服务端重新检查当前权限、绑定、schema、字段类型、范围和跨字段约束。未知字段、单位错误及版本冲突返回字段级问题；不静默忽略、截断到范围内或补默认后声称成功。无变化操作返回明确 no-op，不触发刷新任务。
4. 同一 owner 的一个配置修改单，在短事务内保存显式差异、新版本、原操作结果和待分发记录；校验失败不部分落库。涉及不同 owner 的批量动作按既有操作计划返回各自结果，不宣称跨库原子成功，也不把全局和人格两次提交包装成一次全成功。
5. 提交后发布配置失效/应用事件；模块按当前版本重新解析并原子替换自己的不可变快照。网络、模型、设备连接和重建服务不占用配置写事务，不把外部完成时间绑在保存 HTTP 请求上。
6. 保存回包只含受影响字段、来源、版本、操作 ID 和应用状态。超时则查原操作；同 ID 同内容重试返回原结果，同 ID 不同内容报冲突。页面收到迟到回包时只更新对应提交基线，提交之后继续输入的草稿仍保留。

两个标签页或页面与工具并发修改时，返回基线/当前/草稿差异。首版保守拒绝过期修改单并保留草稿；以后可自动合并互不冲突字段，但必须重新校验全部依赖，不能用最后写入静默覆盖。旧页面遇到 schema 变化先重取定义并重新核对草稿。

### 3.2 三种事实分别呈现

| 事实 | 含义 | 页面可见结果 |
| --- | --- | --- |
| 已保存 | 显式选择已持久化到 owner 的新修订 | 保存成功及保存时间；不据此显示全部已生效。 |
| 解析有效 | 在当前绑定、继承和字段依赖下，运行应采用什么 | 有效值、来源；可指出被角色/个人覆盖、上层关闭或缺少依赖。 |
| 运行采用 | 对应消费者在当前运行代实际装载或读取了哪份解析结果 | 已生效、下次任务使用、待应用、应用失败、需重启或无法确认；显示仍在使用的旧版本。 |

例如公共语音概率从 25% 改为 30%，角色显式覆盖 10% 时，该角色仍用 10% 是正常继承结果；角色自身改为 5% 而消费者仍用 10% 时，则需显示“已保存，待应用”。不靠一次随机回复是否用了语音判断保存成功。

消费者按模块/相关字段批次回执，不为每个字段建独立轮询器。事件按 scope 和修订合并，旧事件处理时读取最新目标；应用回执绑定解析修订和 runtime generation，迟到回执不能替新版本报成功。上级值改变只使依赖它的快照失效，显式覆盖不被重置；参与任务记录实际使用的配置版本。

会产生外部效果的应用步骤声明幂等、结果查询和恢复能力。回执丢失先协调当前目标与实际运行状态；无法确认时保留未知，不凭一次超时重复外部动作。重启确需重建连接时登记本次运行代的恢复步骤，不把它当作原操作从未执行。

| 生效边界 | 处理方式 |
| --- | --- |
| 立即采用 | 更新轻量模块快照；不可出现同一跨字段约束的一半新值、一半旧值。 |
| 下次任务/会话边界 | 已开始任务使用封存的相关配置；后续任务使用新版本，页面明确边界。普通调参不重跑已经完成的生成或发送。 |
| 后台重建/重连 | 沿原操作及监督任务应用，分别报告等待、失败和当前可用性；失败不抹掉已保存选择。 |
| 需重启 | 只有实际不支持热更新的字段可声明，指明需重启的模块或宿主；重启并核验前不标为已生效。 |

明确停用、撤权和换绑仍在下一次实际使用前检查当前状态，不能用封存配置绕过；已发消息或已开始的远端效果不能谎称撤销。权限变更不等待普通设置轮询。

重启从持久正本恢复目标和未完成应用，当前运行代重新报告采用状态；旧进程的“已生效”回执不证明新进程已装载。应用失败时保留目标值、当前采用值和失败原因；回退是携带当前修订的新修改单，不能在后台恢复旧快照覆盖用户后续编辑。诊断只读这些事实，不通过发消息、拍照或调用模型“试一下开关”。

## 4. 数值单位与旧配置迁移

### 4.1 概率与其他数值分开

V2 概率的 API、持久值和运行读取统一为有限 JSON 数值 `0..1`，界面统一显示百分比。页面/工具的带单位输入适配器将百分数转成规范值一次；服务端校验规范单位，消费者不再做百分比猜测。

| 用户输入/显示 | API 与持久值 | 意义 |
| --- | --- | --- |
| 0% | `0` | 概率为零，不等于未配置。 |
| 0.1% | `0.001` | 小概率不被误当 10%。 |
| 1% | `0.01` | 不能保存成 `1`。 |
| 12.5% | `0.125` | 保留字段允许的精度。 |
| 100% | `1` | 规范值 `1` 唯一表示 100%。 |
| 恢复继承 | 独立重置操作 | 移除本层覆盖，返回新有效值及来源；不写负概率。 |

API 收到 `100`、负数、布尔值、NaN/Infinity 或未声明的字符串时拒绝；空输入在草稿中保留为未完成编辑，不能自动提交 `0`。每字段登记精度，十进制解析和量化规则统一；显示再保存不得逐次漂移。现有兼容精度不能为统一控件而静默降低。

“相似度/置信度”“CPU 百分比”“概率”是不同语义类型，即使范围相同也不共用概率名单。秒、分钟、次数、额度亦按字段标单位。多念头竞争权重为无单位的正有限数，沿当前 G6 规则处理；不显示 `%`、不归一化为发生概率，停用使用独立开关。权重只影响多个可行念头的竞争，不改变获取频率、资料读取、预算或单个念头资格。

### 4.2 迁移按来源版本解释

迁移表至少保存旧版本/入口、字段名、旧单位及继承含义、目标字段/单位、转换版本和证据。已知整数百分比字段 `25 -> 0.25`，已知小数概率字段 `0.25 -> 0.25`；旧值为 `1` 时由字段在该版本的定义决定，禁止 `<= 1` 猜测。只有旧字段确实以 `-1` 表示继承，才转换为移除覆盖。

旧 schema 顶层/分组、别名和人格覆盖需要确定原实际读取优先级，不能遍历到最后一项就覆盖。迁移保留显式值、来源、原值与变更报告；有依据的字段自动转换，重跑不二次除以 100。历史错误已经把 1 写成 100 时，没有依据不能推断用户原本想填 1%，需如实保留已记录语义并列出可核对差异。

未知旧版本、互相冲突的来源或无从确定单位的值保留原记录和问题，不静默用默认值宣告迁移成功。影响核心设置的未决差异继续受 [直接替换门槛](../../astrbot_plugin_private_companion/docs/V2_REPLACEMENT_RELEASE_GATE_V0.md)约束；正常可识别配置不增加逐项人工批准流程。迁移通过的是旧功能意图和显式选择，旧概率/阈值也不能自动变成新角色语义的硬规则。

## 5. 大型管理页的结构

### 5.1 导航与加载

统一工作区承载本体和拓展设置：当前安装/角色/用户范围清晰可见，左侧或移动端抽屉列出领域，内容区显示一个分组。基础项、已修改、覆盖项、待生效/失败及高级项可筛选；全局搜索支持名称和旧键别名，结果直接定位字段，不要求用户记住字段所在家具。

首屏只请求轻量目录、当前分组 schema/值和可见状态。目录不包含全部提示词、选项数据、私密值或完整诊断；字段详情、模型目录、日志、图像和历史按需查询。搜索索引仅包含获准字段的元数据，可独立缓存或由服务端分页搜索；不为搜索预取全部配置值。

只挂载当前子组的编辑器，长搜索结果或素材列表分页/虚拟化；隐藏其他字段不等于已经避免下载、查询和装配它们。开关、字段错误和生效状态局部更新，不因输入一个字符重建整个表单。大提示词编辑器、图表、资源预览及各领域脚本/样式按路由拆包。

3D 小屋沿已有 Three.js 方案按需加载，与等价列表共用配置投影；普通设置首屏不下载场景资源，离开或不可见时暂停渲染并释放无消费者资源。小屋加载失败仍能通过列表完成相同管理操作。触屏、键盘和减少动态效果的偏好均有可用入口。

### 5.2 草稿与并发请求

- 草稿以安装/角色/scope/字段 ID 为键，保存原值、当前编辑值和基线修订，独立于控件是否挂载。切分组、搜索、虚拟滚动和验证失败不丢编辑。
- 切角色后进入对应草稿空间；晚到的旧角色请求通过目标与请求代校验丢弃，即使取消请求未成功也不能覆盖当前页。未保存状态可见，离开时可保留或明确丢弃，不自动将草稿保存到新角色。
- 保存捕获本次差异快照；等待回包时可继续修改其他字段。成功只清除仍等于已提交值的差异，失败保留草稿，冲突显示来源与差异。刷新后状态通过服务端原操作恢复，不能仅靠浏览器 toast。
- 首版未保存草稿放内存，跨刷新本地恢复是可选实现；不得把凭据或跨账号草稿持久化到共享浏览器存储。注销清理状态和缓存，重连时重新鉴权。
- 普通数值用有单位的输入/步进器；概率可配滑条但保留精确输入。继承与覆盖独立控制；布尔用开关/复选框，枚举用选择控件，专业参数可使用领域编辑器。

### 5.3 查询、缓存与后台负载

schema 缓存按安装、schema/包版本及可见字段权限区分；配置值/状态缓存还包含主体、角色/scope、绑定/权限版本与解析修订。敏感值不进共享缓存。上级配置改变使对应继承视图失效；包升级、换绑、撤权和注销都不能继续展示旧私有数据。

更新接口返回差异和操作状态，不再通过保存重新取得总览、统计、目录或素材。分组读取在一致快照内批量解析相关字段，消除逐字段查库/逐控件 HTTP；独立领域的耗时数据使用单独接口。页面诊断和编辑不扫描聊天历史、触发 LLM 或探测全部设备。

可见页面优先订阅获准 scope 的增量状态；断线后按当前修订补读，必要时刷新当前分组。轮询作为受限退路，仅服务可见页和未完成操作，离开后停用、异常时退避。服务端任务继续恢复，不依赖浏览器一直开着；不存在每项配置、每件家具或每个隐藏页一个轮询器。

配置快照在前台回复开始前按需要取得一次，任务只记录所用字段及版本；局部配置更新不重算全部角色上下文。管理页刷新、检索和应用任务有并发上限，并让出普通回复/取消/撤权需要的资源；这些约束纳入 CORE-08 的共享调度。

## 6. 性能预算与测量方法

以下为初始工程预算，不是已经取得的性能数字。实际浏览器、宿主硬件及生产体量确定后可以有记录地校准；未运行的项目保持 `not_run`，不把源码文件变小当性能通过。

夹具使用 700 和 1500 个唯一字段，覆盖 10 个角色、逐层继承、10% 的 4 KiB 提示词、依赖/选项、覆盖值及未完成应用；秘密使用合成占位数据。分别测冷缓存、暖缓存和已有草稿，不把 1500 项一次性加载当测试前提。

桌面以 1440×900、移动以 390×844 为起始视口。固定 Chromium 版本，记录服务器 CPU/内存/磁盘；桌面使用本机连接，移动模拟 4 倍 CPU 降速、150 ms RTT、1.6 Mbps 下载，随后补真实手机。模拟成绩不代替真机。冷启动和暖交互各至少 30 次记录 p50/p95，保存轨迹、网络请求和构建版本。

| 指标 | 初始目标与测量边界 |
| --- | --- |
| 首个配置分组可编辑 | 从进入已登录管理路由到控件可用：桌面 p95 ≤ 1.5 秒，移动模拟 p95 ≤ 3 秒；不等待全部领域、3D 或后台诊断。 |
| 首屏工作量 | HTML/JS/CSS 合计压缩传输 ≤ 300 KiB；首屏业务 API ≤ 3 次、响应合计压缩 ≤ 100 KiB。记录未压缩解析体积；未进入的 3D、素材、完整提示词组不加载。 |
| 编辑、搜索、切组 | 输入到绘制 p95：桌面 ≤ 50 ms、移动模拟 ≤ 100 ms；搜索包含去抖在内 p95 ≤ 300 ms；已缓存分组切换 p95 ≤ 200 ms。冷分组查询独立记录。 |
| 挂载规模 | 同时挂载的配置行含预渲染缓冲不超过 80；长列表使用分页/虚拟化，焦点不丢失。单次管理页主线程任务不超过 50 ms，重型可中断工作分批执行。 |
| 服务端保存 | 标准夹具下 20 字段修改单，入口到持久提交及待分发记录完成 p95 ≤ 300 ms；不含设备/网络重连。实际采用耗时独立按消费者报告，不能拿保存耗时冒充生效耗时。 |
| 保存响应 | 标准修改单响应压缩 ≤ 30 KiB，只返回差异和受影响状态；大正文另按实际提交字节计量，不以截断内容达标。收到回包到局部状态绘制 p95 ≤ 100 ms。 |
| 连续使用 | 暖态完成 20 次角色/分组往返并以相同方式 GC 后，保留堆增量 ≤ 10 MiB；请求、监听器和订阅数量无持续增长。后台页无常驻配置轮询或 3D 绘制。 |
| 并行聊天 | 合成 700/1500 字段管理负载下，比较同一无网络回复回放的阶段延迟；不得出现等待全量配置/总览的新增阶段，前台 p95 增幅目标 ≤ 10%。同时测试配置写入、取消与撤权，真实模型耗时另计。 |

规模从 700 扩到 1500 时，当前分组的请求数、挂载行数和读值数量保持有界；全局目录/搜索索引允许随字段数增长，单独计量。阈值之外还验证草稿正确性、范围隔离和生效一致性，不能用少返回字段、失去高级功能或丢编辑换取速度。

## 8. 完整验收场景

以下保留专项全量目标。已有本地子场景证据按 [切片记录](CORE_CONFIGURATION_SLICE.md)限定；包含真实入口、全量迁移或页面的条目不能因其局部测试通过而标成整项通过。

| 编号 | 必须证明的行为 |
| --- | --- |
| CFG-C01 | 页面、宿主入口、工具、引导和导入引用同一字段定义；未知键、重复注册、不支持的 scope、错误类型及跨字段非法组合明确失败。 |
| CFG-C02 | 公共/角色/个人覆盖保留来源；0、false、空值与恢复继承不同。修改上级值只改变受影响有效值，重启后不丢覆盖。 |
| CFG-C03 | 0%、0.1%、1%、12.5%、100% 显示、提交、保存、重读多次稳定；`100` 作为规范概率和空输入不能被悄悄接受。权重、置信度、资源百分比及秒/分钟不混用。 |
| CFG-C04 | 两标签页、工具与页面竞争；改配置期间换绑或 schema 升级；冲突保留草稿，提交只影响原授权范围。 |
| CFG-C05 | 同 owner 修改单中途失败无半份配置；跨 owner 操作部分成功按项展示；新运行值不在持久失败后偷偷继续使用。 |
| CFG-C06 | 提交成功回包丢失、同请求重复、进程重启及迟到旧事件均可查原结果；外部效果未知时不盲目重试，按运行代协调必要恢复，不用旧快照盖掉新设置。 |
| CFG-C07 | 已保存但模块未采用、部分消费者失败、下次任务使用和需重启分别显示；旧运行代回执不能替新进程报成功。恢复动作沿原操作协调。 |
| CFG-C08 | 同一任务内读取一致配置；普通修改不重做已发效果。停用、撤权/换绑仍在实际使用前生效，不能等旧任务自然结束才检查。 |
| CFG-C09 | 保存期间继续输入、切组/切角色、搜索和虚拟滚动不丢草稿；晚到请求不串角色；回包不清除提交后的编辑。 |
| CFG-C10 | 700/1500 字段、冷暖/桌面/移动、20 次往返验证第 6 节预算；保存不重取总览，隐藏页不持续轮询，普通配置首屏不启动 3D。 |
| CFG-C11 | 敏感值不进搜索/共享缓存/普通导出；遮罩不覆盖原凭据；权限收回、账号退出、包升级及绑定变更后缓存不可越权复用。 |
| CFG-C12 | 旧百分整数、小数概率、负数继承及顶层/分组冲突有版本化映射；重复迁移不再次换算，未知格式保留原值和未决结果，不算完整迁移通过。 |
| CFG-C13 | 家具、等价列表和本体设置对同一字段显示同一目标/有效/采用结果；依赖未连接与用户关闭分开，失败时普通列表仍可操作。 |
| CFG-C14 | 管理页持续查询/保存不堵住普通回复、取消与撤权；消费者数量和批量解析可观测，不产生逐字段任务、模型调用或数据库查询。 |
