# 原生能力缓存前缀修复

2.1.27 处理真实请求前缀中可避免的实时注入变化，并纠正全局趋势图对缓存未知的标注。

## 现场证据

用户截图来自 AstrBot 全部会话的逐日用量，不能作为逐轮缓存破坏记录。宿主 ProviderStat 未保留零缓存是否为显式回执，历史模型切换、开发期间的提示更新和服务端缓存失效也会影响统计。

本轮只读抽查 V2 运行库中的 183 个回合、211 条请求签名、32 个上下文，覆盖 10 月 10 日至 15 日；历史记录存在系统提示、工具、模型和 Provider 切换。抽查时今日的 3 条请求签名没有系统、工具、上下文或模型结构变化。同一窗口的两条输入分别为 28,917 / 缓存 24,320（84.1%）及工具续轮 29,338 / 缓存 29,184（99.5%）；另一模型未提供缓存回执，保留未知。这些样本不代表全局命中率，也不能保证后续服务端命中。

## 实现

- `request_context.py` 只管理带本体自有标记的临时材料和配置指令，保留用户原话、既有历史与其他插件内容。
- 游戏局面、胜负及实时直播事件使用 `TextPart.mark_as_temp()`；摄像头和本人现实配置提示、VTS 本轮授权入口提示同样使用临时材料。材料到达模型与工具续轮，保存历史时剔除；重复准备更新而不累积，能力暂停后清理。
- Soullink / Live2D 的配置指导继续放在稳定系统提示中，幂等替换自有块，关闭时仅撤销自有块。语音与表情的现有系统指导、主链回复归属不变。
- 游戏的角色/用户/私聊读取授权、暗牌与谜底隔离、结果 TTL 保持；摄像头仍须有真实已授权工具，现实提醒 Cron 的专用安全指导、工具与一次交付机制保持。
- 趋势蓝色图例为「其余输入」；每日提示仅在所有调用都有缓存回执时称为未命中，其余情况标为含缓存未知。数值仍为输入减已记录缓存输入，不推导全局缓存破坏次数或命中率。
