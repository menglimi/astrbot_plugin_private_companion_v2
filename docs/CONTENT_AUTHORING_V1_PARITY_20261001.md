# 原生创作 V1/V2 差异核对

日期：2026-10-01。核对对象是 V1 源码 `astrbot_plugin_private_companion/creative.py`、V2 私聊原生创作流程和 Content 0.2.3 的公开读取合同；未读取或迁移 V1 用户数据。

| 能力 | V1 | V2 当前行为 | 处理 |
| --- | --- | --- | --- |
| 新作 | 角色可在闲暇时自动立项，后台分段写入项目 | 用户明确要求创作时，一次生成完整正文并保存为 Content 新作品 | 保留明确发起；不自动替用户创建作品 |
| 连载连续性 | 故事设定、故事内时间、主线、人物表、提纲、相关记忆、人工修订共同进入每段写作 | 续写读取一个固定 Content 版本，按章节正文和角色人格提示继续 | 已增强提示词：核对时间、地点、人物、动作和未完成冲突；尊重提纲与人工修订；体裁已知时恢复诗歌、剧本、随笔、设定等输出形式 |
| 质量复核 | 另有提纲生成、质量评分、相似度检查及失败重写 | 单次写作提示内自检；没有独立审稿/重写模型回合 | 当前差距；不在续写时额外隐式调用模型，避免未经用户预期的重复成本和等待 |
| 修订 | V1 项目有手工修订约束和项目资料维护 | 新作/续写工具不代替用户编辑；Content 保留候选、人工编辑和采用的版本裁决 | 编辑继续由 Content 工作区处理；V2 续写候选永不自动采用 |
| 自动分享 | V1 有作品片段的主动分享候选和概率配置 | 本功能不自动披露作品；分享材料尚未接入主动候选 | 有意不迁概率触发；任何对外发送仍须走独立的受众和投递授权 |
| 输出长度 | V1 按单次字符预算分段并以目标字数调度 | V2 不设创作字符目标或候选数量设置；专用写作任务继承已选模型路线的输出 token 配置，Content 仍执行自身作品存储合同 | 已移除插件自有正文目标和候选数上限；模型/提供方与 Content 的合同仍是实际能力边界 |

| 版本连续性 | V1 项目数据自行保存分段与设定 | V2 读取固定版本并以原 `base_version`、`base_revision` 保存候选；Content CAS 拒绝过期 head | 已实现并由原始子调用回执复核 |
| 章节标题 | V1 以分段项目正文管理 | Content 0.2.2 的读取页不含章节标题，续写会因此清空候选中的旧标题 | Content 0.2.3 增加 `chapter_title`；V2 接受新旧两种读取页，新版能保留标题 |

实现复核还发现：V2 虽然向模型公开了按标题续写，但内部 Content 子调用白名单漏掉只读的 `content.work.list`，因此工具会在访问目录前失败。白名单已补齐，并由合成宿主闭环验证标题精确查找、固定版本读取和候选稿保存；不匹配或同名仍由现有明确错误处理。相邻 Content 版本采用测试耗时约 24 秒，已把不合理的 15 秒测试截止放宽到 45 秒；它仍只等待原流程，不增加模型调用或重试。

## V1 源码依据

- `CreativeMixin._bot_currently_idle_for_creative_writing()`、`_maybe_start_creative_project()` 和 `_maybe_advance_creative_projects()` 负责闲暇判断、后台立项和后续推进。
- `_generate_outline_for_chunk()`、`_generate_creative_chunk()`、`_review_creative_chunk()` 负责提纲、连续性材料、输出和审校重写。
- `_get_or_create_story_bible()`、`_creative_character_context()`、`_creative_manual_revision_context()`、`_retrieve_relevant_memories()` 负责项目设定、角色、人工修改和相关记忆。
- `_creative_work_output_rule()` 按诗歌、剧本、散文、设定等体裁调整输出方式。

## 本轮落地

- 续写可按完整作品标题查找；只接受精确唯一匹配，同名时停止并让角色向用户澄清。
- Content 子调用序号随目录分页和正文分页递增，跨多页不会复用固定编号。
- 写作任务超时设为 180 秒；输出 token 继续沿用已选模型路线，不另设插件长度项。
- 续写提示补入连续性、情节推进、重复检查、人工修订优先级和体裁写法；角色人格通过原始模型请求保留。
- Content 读取页携带章节标题；V2 对旧提供方保持读取兼容。
- 不迁入 V1 闲暇自动写作、随机推进、概率分享或自动采用候选。V2 的新作直接保存为完整 Content 作品；续写会产生固定版本上的候选稿，采用仍由用户决定。

## 尚未覆盖

V2 还没有 V1 那套可编辑 Story Bible、人工大纲/角色表、结构化后生成摘要与提取，或单独的审校和重写回合。它们需要有明确的 Content 数据合同、用户管理入口和版本回执后再接入；当前提示词自检是软性质量引导，不等同于 V1 的独立审稿器。

旧版 Content 提供方仍然兼容，但由于其读取合同不带 `chapter_title`，旧提供方下无法保留章节标题。升级到 Content 0.2.3 后才具备完整标题往返。
