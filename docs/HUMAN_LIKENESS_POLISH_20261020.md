# 拟人化打磨：本轮落地与剩余项（2026-10-20）

本文接续 [拟人感审计](HUMAN_LIKENESS_AUDIT_20261017.md) 和 [私聊收尾沉默](PRIVATE_CLOSING_GUARD_20261020.md)。目标不是增加人格文本，而是去掉最容易听出“机器”的机制和句式。

## 一、本轮已落地（不需要产品改默认值）

### 1. 常驻感知提示补上“篇幅跟对方走”

`astrbot_host/core_reply_perception._POLICY` 每轮随 system 注入，新增：

- 对方只发一句短话、一个应声或一个表情时，先用一两句接住，不展开分析、不总结对方、不每次给建议；
- 不必每轮都用问题收尾，也不必为了显得热络另起话题； “嗯，我在”“好，知道啦”本身就能接住话；
- 对方发来长文时先接住最在意的一点，不逐条复述；
- 避免连续两轮使用同一种开头或句式，也不要把日常闲聊写成对仗、清单或客服式收尾；
- 对方明确要步骤、比较或完整解释时仍按任务给足，避免“为了短而短”。

这属于提示词层的表达引导，不改事实、来源、授权或工具合同；它和已有的 `【表达偏好】`、`【对话附加提示】`、人格文本叠加，不会覆盖人格。

### 2. 分段间隔曲线恢复真实节奏

`companion_v2/conversation/segmentation.py` 的 `log` 模式此前有三个会出戏的问题：

- `part_gap_min_ms` / `part_gap_max_ms` 在 log 模式完全不生效；
- 纯标点、纯表情的可见字符数为 0，间隔只剩 0.1–0.6 秒，气泡“贴脸”连发；
- 全 ASCII 文本按词数、中文按字符数，`hahahahaha` 只算 1，中英文节奏不一致。

现在统一按“非空白可见字符数”计算，先夹在配置的上下限内，再叠加角色状态系数和稳定抖动。效果：

- “……”“🥺”等短气泡至少等待约 1.5–2.0 秒，不再瞬间连发；
- 很长的回复不会因为对数曲线无限拉长，上限回到运营者配置的 `part_gap_max_ms`（默认 3.5 秒，另加最多 0.5 秒稳定抖动）；
- 英文和中文使用同一尺度，英文笑声和中文短句的间隔不再出现数量级差异；
- 离线预览的 `minimum_part_gap_seconds` 与真实发送使用同一套可见长度和状态系数。

这是纯粹的节奏修正，不改变分段边界、分段条数或内容。

| 8 | **关系距离没有正向梯度** | `relationships/profile.py` 只有静态字段；称呼兜底是“拿不准就中性”，没有“熟了就直呼”的正向分支 | 越不确定越像客服，长期关系也难自然升级称呼 | 是否增加相处阶段/熟悉度字段，或先在称呼提示里补“已有明确昵称且关系亲近时可直接用” |

## 三、建议的下一批

如果要继续动默认体验，建议按这个顺序，一次只改一组并可回退：

1. **首条延迟**：分段链的第一条仍然立即发送；先做成可配置的稳定首条延迟，再和正在输入状态联动，解决“秒回”的最后一环。
2. **拟人表达默认 guided 或开**：只改提示词层，风险低于改分段和发送节奏；可以先在页面把 guided 设为推荐档。
3. **默认语义分段**：把 `llm_controlled` 或 `max_segments/threshold` 调成更克制的值，需要真实模型对照，避免长回复被过度合并。
4. **失败兜底与固定文案**：涉及真实发送和安全边界，应单独做发送前复核与限频，不和前三项混在一起。

- `tests/test_reply_management.py`：17 项通过（AstrBot 自带 Python，临时数据根）。
- `tests/test_proactive_contacts.py::test_role_state_reaches_contact_intent_and_pacing_settings`：通过，确认主动联系仍读取同一套 pacing 设置。
- 随后新增的[私聊连续输入防抖](PRIVATE_DEBOUNCE_20261020.md)默认开启，属于本页第 2 项的落地；纯文本 1.5–4 秒自适应、总等待不超过 8 秒，配置在「陪伴小屋 → 决策 → 参与节奏 → 私聊节奏 · 连续输入」。首条延迟、拟人表达默认值和失败兜底仍待产品决定。
- 真实 QQ 客户端的“正在输入”、首条延迟听感、防抖合并顺序和失败兜底文案未在本轮验证；宿主测试使用合成事件与本地替身。
