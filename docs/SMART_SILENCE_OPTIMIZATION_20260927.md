# T06 智能沉默优化设计与实施

日期：2026-09-27。依据 V1 `user_memory.py` 的智能沉默触发与模型判断，以及 V2 主动联系链和后台历史合同完成设计及首版实现。

## 设计

V1 会先以确定性边界规则筛选被动回复，再调用专用模型；将这条链直接移植到 V2 会在每次主动机会的生成调用之外增加一次判断。V2 已有 `proactive.compose` 单次调用，并允许角色选择 send 或 skip，因此沉默判断并入现有决定，不新增 provider、任务类型或模型调用。

模型按提示词同时返回 `decision_confidence`（0–1）。配置的 `silence_min_confidence` 默认 0.66；send 低于阈值时保存为 skip，不创建投递。旧自定义提示词未返回该字段时暂按 1.0 兼容，内置提示词要求返回该字段。模型主动 skip 且置信度达到阈值时，将该目的的下一次候选权重乘以 `1 - silence_feedback_penalty`，默认惩罚 0.2，权重下限为原值的 0.25。反馈只作用于同一完整窗口和同一联系目的的自动机会，不改变权限、定时、预算或人工显式机会。

置信度及反馈写入已有 `proactive_contacts.record_json`，无需新增表或迁移。提示词负责语义决定；程序仅执行明确阈值、skip 回执与既有投递边界。

## 验证范围

定向测试覆盖低置信 send 转 skip、无投递产生、决定置信度持久化、旧输出兼容，以及新配置通过统一注册表。主动联系与智能沉默仍由同一后台模型任务执行；没有真实模型或平台发送。
