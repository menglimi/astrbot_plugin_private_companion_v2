# 主动联系提示词页优化

## 入口与范围

唯一公开页面「陪伴小屋」→「治理与维护／运行诊断」→「提示词」→「主动联系」。直接路由为 `#manage/maintenance/prompts`。

原页面只能编辑 `model.proactive.compose.prompt` 的附加任务提示；控制表达的业务模板在源码中，页面无法查看或替换。本次将主动联系使用的表达模板绑定到原 `proactive.contact` 配置组，同时发布完整业务模板目录。其他任务继续使用原任务提示编辑器，其业务模板目录尚未逐个开放。

## 三个视图

- **表达编辑**：主动表达、新闻分享、主动篇幅、新闻篇幅、主动风格补充，以及原模型任务提示。展示完整文本、来源、继承来源、默认模板与版本令牌。
- **固定规则**：联系由头与事实、15 种目的、10 种来源，以及记忆、去重、预警、分段、JSON、末尾约束等模板全文。按适用条件查看。
- **提示组成**：角色指令、业务指令、任务提示、输出格式、能力协议和末尾规则的层次。角色设定与本轮新闻、历史材料仍按授权动态注入；模板目录不等于某次调用的最终 `messages`。

搜索同时覆盖任务名、用途、模板标签、条件与正文。编辑草稿在视图切换时保留；切换模板或任务前检测未保存更改。

## 配置与实际生效

| 页面模板 | 原领域字段 | 使用时机 |
| --- | --- | --- |
| 主动表达 | `proactive.contact.expression_prompt` | 每次主动联系 |
| 新闻分享 | `proactive.contact.news_sharing_prompt` | 新闻目的或新闻事件 |
| 主动篇幅 | `proactive.contact.length_prompt` | 非新闻联系且篇幅档位生效 |
| 新闻篇幅 | `proactive.contact.news_length_prompt` | 新闻联系且篇幅档位生效 |
| 主动风格补充 | `proactive.contact.style_prompt` | 非空时追加 |
| 模型任务提示 | `model.proactive.compose.prompt` | 路由准备请求时追加 |

四个新字段沿用安装、角色、关系、窗口继承。提示词页写当前窗口；「恢复继承值」移除该窗口覆盖，保留关系层或角色层设置。上级配置也可通过主动联系偏好的原配置编辑器维护，没有复制配置正本。

`request_for()` 直接读取生效模板，替换原对应业务段。默认表达移除了“一句话能说完就只说一句”，允许随内容自然展开、保留感想与段落。新闻分享保留原人格，同时表达遇见新鲜事后的好奇、惊喜和分享欲；来源、日期与原文链接仍留待追问。

篇幅模板必须保留纯 `{chars}`，运行时填入当前强度档位的总字数。校验拒绝未知变量、属性访问和格式转换，避免格式化错误；这不是额外的语言风格限制。

## 保存边界

沿用原模型管理路由 `/model/configure`，新增可选 `section`。页面提交当前模板自己的配置版本令牌；服务端只接受已注册可编辑模板，将它映射回原领域字段，并使用领域所有者和目标授权范围保存。

权限、版本冲突、稳定操作键与重放继续由既有服务维护。事实、来源、输出协议保持只读。冲突时保留草稿并阻止继续覆盖，读取最新值后由页面确认是否替换草稿。真实平台发送、身份派生和未知投递结果不重放均保持原程序保障。

## 验收方法

开发期针对阻断问题检查；从当前源码构建本体交付包后，在插件扫描目录之外解包并统一验收：

- `tests/test_prompt_templates.py`：模板进入真实请求封套、新闻/普通表达区分、关系继承恢复、窗口隔离、冲突与重放、格式变量、授权和固定模板目录。
- `tests/test_proactive_*` 与模型管理相关定向测试：既有起草、自然段落、配置和模型路由合同。
- `tests/test_model_provider_api.py`：真实 AstrBot SDK 的原模型路由保存新模板。
- `tests/test_maintenance_page.cjs`、`tests/test_config_editor.cjs`：草稿、搜索、保存令牌、冲突和四个字段覆盖。
- `tools/check_prompt_page.cjs`：使用交付包实际页面及模板、AstrBot 页面 SDK、合成配置；检查 1440、390、320 像素下的三个视图与键盘路径，保存桌面/手机截图和 JSON 结果。
- `tools/verify_v2_release.py --host-check`：包哈希、源码清单、唯一注册页、宿主加载、停机及路由注销。

宿主测试用 AstrBot 自带 Python，加入 `backend/app` 的 `PYTHONPATH`，导入时的数据根由测试支持代码设为临时目录。浏览器工具只维护合成数据，不调用真实模型或发送平台消息。

## 本轮结果

本板块在构建交付包后完成定向验收：Python 129 项与 31 项 subtest、Node 119 项通过。浏览器 5 项通过，49 段模板逐段核对；桌面与 390、320 像素手机截图已检查。窄屏长标题选择框改为上下排列，来源采用中文，技术版本信息折叠。最后封包后另运行模板保存、维护页和浏览器定向检查。

TTS 三个测试夹具原先把所有通用 Provider 查询置空，误移除仍需授权的主文本 Provider。本轮只修正这三处夹具，使主模型继续存在、TTS 仍仅从专用集合解析；复跑通过，没有修改 TTS 生产实现。

主动配置组 164 字段的覆盖审计通过。全局审计另报告知识组 `import_enabled`、`import_paths` 的控件、标签和段落缺口共 6 处，未归入本轮提示词页变更。

包哈希、文件清单、唯一公开页、真实 SDK 加载/停机/路由注销通过。没有热重载运行实例，没有调用真实模型或向联系人发送消息；表达效果尚需在实际角色和模型上观察。
