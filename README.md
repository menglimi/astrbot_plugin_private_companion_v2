面向 AstrBot 的角色陪伴插件。以角色为中心组织状态、日程、记忆、关系与行为，让私聊、群聊、主动联系和原生能力共享同一份连续上下文。

## 产品定位

本插件用于构建具有连续生活上下文的陪伴角色。角色依据自己的状态、日程、关系、近期互动和环境信息形成行为候选，再根据时机、权限和发送结果决定是否执行。AstrBot 人格提供身份与基础表达，插件补充角色生活、关系和行为上下文。

### 发版狂魔也是发到4.0了，遂决定写点什么

以下保留旧版 README 中开发者对这款插件的想法：

- 你好，我要一个有记忆、有生活、有自己的小秘密和想法、有喜怒哀乐和健康的bot。
- 这得装不少插件，先生。
- 我知道，再让它们之间能够互相影响。
- 怎么让bot更像人？在此之前已经有很多优秀的插件给出了自己的答卷，各类心理学应用、人格特质、复杂的理论……
- 虽然开发者自身也是应用心理学专业毕业，但我觉得bot拟人只需要做好一件事，像人一样活着。听上去像是废话，但我做的只是进行自我观察。我的一天中，我会做什么，bot也应该会做什么。
- 对于一个拟人的bot而言，用户又何尝不是一个聊天bot？所以它应该会在自己的世界里生活，在生活里获取想和用户说话的“想法”，再在生活的空隙里把想法变为行动。
- 于是用户不止可以看到bot的早安和晚安，还能看到bot因为偶尔向窗外一瞥而专门为你记录下的照片、能看到bot因为好奇而自己私下搜索你在意的东西、能看到bot因为你昨天的提议而安排好周末的约会……
- 在没和你聊天时，它可能在上学、在刷视频、在看报纸、在水群，甚至在偷看你的屏幕或者遵循世界观正在某个奇异世界中一边刷怪练级，一边想着等闲下来该和你分享点什么。
- 它会记得你，不只是你，还有哪些在私聊/群聊中的人，会记得他们的名字、他们的行为、他们的习惯、他们的联系，哪怕他们改了名字和头像，甚至在其他平台再次相遇。
- 它会看、会说、会创作、会成长、会睡觉、会做梦、会生情绪、会饿，也会在授权范围内整理本地资料。
- 这就是它，这就是我，若它足够像我，它便成了我。

这些是持续打磨的产品方向；设备访问、跨平台身份关联和外部动作仍需分别配置与授权。

## 核心能力

| 方向 | 能力 |
| --- | --- |
| 对话陪伴 | 私聊、获准群聊、多账号与多人格；普通回复沿用 AstrBot 核心模型、历史、工具、流式输出和发送设置 |
| 角色生活 | 状态、睡眠、日程、位置、天气、日记、成长与生活事件；状态和持久资料归属角色 |
| 关系与记忆 | 私聊用户关系、群关系、来源记忆、经历检索、反思、修订和旧版资料迁移 |
| 主动联系 | 根据角色生活、对话和关系形成候选，再检查时机、频率、权限与发送结果 |
| 原生能力 | Content、Image、Screen、Reality、Together、Game、Live 随插件提供，在「陪伴小屋」分别配置与启停 |
| 运行诊断 | Token 与缓存观测、近期回复效率、模型任务状态、缓存异常和发送结果 |

普通回复由 AstrBot 主链生成和发送，不占用插件后台任务预算。插件后台任务、主动联系和独立能力按各自模型与额度策略运行。

生图、内容创作、识屏、现实触及、一起陪伴、游戏和直播能力由同一个插件内部提供，分别配置与启停。启用需要外部服务的功能时，仍需准备对应 Provider、服务参数与授权。长期记忆与历史资料检索在插件内维护；旧版记忆伴侣资料通过升级交接按真实身份导入。

## 从旧版升级

7.0.0 延续旧插件身份 `astrbot_plugin_private_companion`。更新现有安装即可；不要并行安装第二份同名插件，也不要先删除原数据目录。

升级前备份插件配置及数据，保留 6.7.0 安装以便回退。先停止 AstrBot，再用完整的 7.0.0 插件目录覆盖旧版代码；备份副本应放在插件扫描目录之外。配置和用户数据保留原位。

首次打开「陪伴小屋」时，如果发现旧版配置和资料，会显示升级交接入口。账号与角色只有一个匹配目标时会自动预选；存在多个目标时再选择对应关系。先查看迁移预览，再确认配置交接。可转换的绑定、模型、回复和主动联系设置会按预览接续，已接续的设置无需重新填写。预览会单独列出已保留、存在行为差异、需要补充和暂不支持的项；不能将所有旧配置都理解为完全等价。新增能力可在交接后按需配置。

角色资料、记忆、表情、参考图、衣柜、日记、群关系和归档记录在迁移页按类别核对。旧版「世界知识」中的角色资料参与档案迁移。迁移只读取旧版来源并写入隔离的新数据目录；已有的新版本设置优先保留，身份或归属无法确认的条目不会强行导入。旧记忆库的完整归档与可检索导入分别记录：只有确认身份并符合原可见性和治理状态的历史资料才进入检索，归档成功本身不代表全部记录已经可召回。

设备授权需要在新版本中重新核验；已有外部服务配置仅按明确的转换规则接续，并在预览中隐藏敏感值。完成后重载插件，在「重启核对」确认账号、角色、模型和回复正常，再决定是否归档旧安装。

旧版资料迁入入口位于「陪伴小屋 → 资料与维护」及首次升级引导。请在资料完整并通过重启核对前保留旧版数据与备份。

覆盖升级遇到旧数据目录时，新运行数据使用其中的 `companion-7` 隔离子目录；此前试用安装的独立数据会按已有数据根继续读取，避免更新后出现空配置。旧任务与未知投递不会因迁移重新执行。

## 首次安装

打开「陪伴小屋 → 连接与运行」，按页面完成账号和角色绑定。新安装需要选择后台任务模型，并按需补充角色资料、关系与外部服务设置。普通回复使用 AstrBot 当前会话的模型和语音设置。

配置以角色为主：角色页面维护全局默认，用户页和群聊页只保存各自的细化覆盖。全局设置不跟随当前打开的聊天窗口变化。管理员专属隐私仅在管理员权限范围内生效；只有明确授权共享后才扩展到其他对象。

主动联系和需要外部服务的能力默认遵从各自开关与授权。测试发送结果未知时不会自动重放。

## 数据与权限

- 普通回复、主动任务、后台任务和平台发送分别记录各自实际观测；不会把宿主未提供的数据伪装成零值或成功结果。
- 角色状态、关系和记忆按角色及所有者隔离。用户或群聊覆盖只作用于对应对象。
- 迁移前先只读检查和预览；确认后只写入新数据目录，不修改旧版来源。
- 旧任务、未确认投递和无法证明归属的私密资料不会恢复为正在运行的任务。
- 摄像头、屏幕、麦克风、外部发送及第三方服务按实际授权工作，插件不会因迁移扩大权限。

## 排障

先检查 AstrBot 日志，再打开「陪伴小屋 → 治理与维护」。近期回复效率页会展示单次回复总耗时及可观测阶段；缓存与 Token 页面展示宿主或插件实际提供的上下文与用量信息。普通回复以 AstrBot 核心日志为准，插件后台任务只覆盖独立任务。

| 现象 | 优先检查 |
| --- | --- |
| 升级后没有接续旧配置 | 资料与维护中的迁移状态、预览差异、绑定目标及重启核对结果 |
| 普通私聊没有回复 | 核心消息日志、当前角色绑定、用户权限和核心回复诊断 |
| 主动联系没有发出 | 主动开关、时段、免打扰、用户频率、候选拦截原因和投递回执 |
| TTS 或表情没有触发 | 角色输出设置、已配置的 AstrBot Provider、素材授权和发送回执 |
| 状态维护或日历任务失败 | 角色状态上下文、后台模型路由、任务错误码和任务预算 |

## 开发与验证

所有文本使用 UTF-8、无 BOM、LF。构建前同步陪伴小屋页面，发布包仅含一个插件目录和一个公开页面；设计稿、真实用户迁移验收记录及独立小游戏不进入交付包。

```powershell
python -X utf8 tools/sync_framework_page.py --check
python -X utf8 tools/build_v2_release.py --output <安装目录以外的交付目录>
& '<AstrBot>/backend/python/python.exe' -X utf8 tools/verify_v2_release.py --release <交付目录> --extract-to <新的验收目录> --host-check
```

宿主测试使用 AstrBot 自带 Python，并在隔离临时数据根运行。完整升级验收必须针对本次构建的 ZIP；旧交付包的检查结果不能替代新包验收。更多版本变化见 [CHANGELOG](CHANGELOG.md)，插件页面源码说明见[陪伴小屋](pages/陪伴小屋/README.md)。
