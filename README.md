面向 AstrBot 的角色陪伴插件。让角色有自己的生活，也记得与你共同经历的事。

状态、日程、记忆、关系、表达与主动联系围绕角色组织，在私聊和群聊中延续；普通对话沿用 AstrBot 的主回复链。

## 从 6.7.0 升级

7.0.0 继续使用原仓库和插件名 `astrbot_plugin_private_companion`。通过现有安装更新即可，不需要另装一份插件。

### 升级步骤

1. **先准备可验证的回退材料。** 保存插件配置文件和原数据目录；使用过独立记忆或其他伴侣拓展的，也备份它们的配置与数据。另从 7.0.0 发布页的「6.7.0 回退包」附件下载旧版代码包，并核对下方列出的 SHA-256。若发布页没有该附件或校验不符，先不要升级。
2. **更新原插件。** 发布后，在 AstrBot 插件管理中将现有插件更新至 7.0.0，再按宿主提示重载。离线更新时，先停止 AstrBot，再用本版本交付包替换原插件代码目录，保留独立的配置和数据目录。
3. **打开「陪伴小屋 → 开始使用」。** 查看识别出的旧版账号、人格、私聊对象和模型。只有一个匹配目标时会自动预选；有多个候选或无法确认归属时，需要选择对应关系。
4. **确认配置交接。** 按引导进入迁移页，查看可接续配置及差异后确认。已正确识别并接续的模型、回复、主动联系等设置无需重新填写；已有新版明确设置优先保留。
5. **核对并导入资料。** 在「资料与维护 → 旧版资料迁入」按类别确认资料范围、账号、角色和用户／群聊映射，再执行导入。配置交接完成与资料导入完成分别记录。
6. **重载后完成核对。** 按页面提示重载插件并完成「重启核对」，确认账号、角色、普通回复及需要使用的功能正常，再检查资料迁移结果中的剩余项。确认无遗漏前保留旧版备份。

交接时尤其注意：AstrBot 管理员、旧版主要用户与角色人格是不同的概念。请按真实账号和用户 ID 核对，不能仅凭显示名称判断归属。

### 哪些内容可以接续

| 内容 | 7.0.0 中的处理 |
| --- | --- |
| 账号、人格与聊天对象 | 根据旧配置和当前宿主信息确认对应关系；不明确的目标需要手动映射 |
| 回复、主动联系、模型与生活设置 | 按转换规则预览并接续；不等价、需补充或暂不支持的项单独说明 |
| 角色档案、世界知识、熟人资料与群关系 | 按角色及对应用户／群聊导入；旧版「世界知识」中的角色资料也参与档案迁移 |
| 记忆、经历与历史资料 | 核对来源身份、可见性和治理状态后导入；原始归档与可检索导入分别记录 |
| 已学习表达、表情、参考图、衣柜与日记 | 在迁移页按类别核对可用来源及结果；保留已有新版资料，避免重复导入 |
| 旧独立拓展配置 | 只接续有明确转换规则的参数；外部服务、设备权限及无法等价转换的项需另行确认 |

**归档成功不等于所有资料都已进入对话检索。** 无法确认身份、可见性不符或已被撤回、限制的记录，不会因迁移重新进入召回；具体原因以迁移结果为准。

迁移读取旧版来源，写入新版独立数据目录。覆盖升级时，新运行数据使用旧插件数据目录内的 `companion-7` 隔离子目录；此前试用安装已有的独立数据根继续沿用。旧任务和未确认的投递不会因迁移重新执行。

### 旧独立拓展如何交接

7.0.0 已内置内容创作、生图、识屏、现实触及、一起陪伴、游戏和直播能力，无需为这些能力另装七个伴侣插件。长期记忆也在插件内维护，旧记忆伴侣资料可通过迁移页导入。

配置交接与业务资料迁移有各自的范围：旧拓展的创作项目、房间／通话会话、媒体及设备观察数据，本轮仍有外部保留或暂缓迁移的部分。不要因某项配置已接续，就删除对应旧拓展的数据。

确认内置能力接管后，停用承担同一功能的旧独立拓展，避免重复注入、重复调度或重复发送。屏幕、麦克风、摄像头等设备访问需要按当前设备和权限重新确认，不会因迁移自动扩大授权。

### 需要回退时

7.0.0 没有一键降级。迁移结果不符合预期时，不要再次执行迁移或清理。先正常停止 AstrBot；若插件仍在运行但宿主可以响应，先停用插件并关闭 AstrBot。准备好 6.7.0 回退包后再恢复：

1. **封存 7.0.0 现场。** 将当前插件目录、AstrBot 配置目录和实际运行数据根复制到插件扫描目录之外。数据根可能是原插件数据目录下的 `companion-7`，也可能是配置的外部路径；如果两处都有数据，都先保留。现场副本用于后续取回 7.0.0 新资料，不能作为 6.7.0 数据直接启动。
2. **恢复旧版代码。** 从本节的 7.0.0 发布附件下载回退包，验证 SHA-256 后，将压缩包中的 `astrbot_plugin_private_companion` 目录完整恢复到原插件目录。不要把新旧代码合并，也不要从已替换为 7.0.0 的仓库分支取旧代码。
3. **恢复旧版插件配置。** 将 `astrbot_plugin_private_companion_config.json` 恢复为升级前版本；不要回滚整个 AstrBot 配置目录，以免撤销其他插件或宿主设置。若之前没有另存此文件，可检查 AstrBot 配置目录下 `.private-companion-upgrade/source.json`：根据其中的 SHA-256 找到同目录的归档 JSON，核对哈希后复制为 `astrbot_plugin_private_companion_config.json`。这份归档只包含被识别的升级前插件配置，不包含运行数据；若它不存在或校验失败，不要猜字段拼回旧配置。
4. **让 6.7.0 使用原数据。** 确认原 V1 数据目录和升级前使用的外部存储路径仍完整。正常覆盖升级会把新版运行数据隔离在 `companion-7` 或既有的 V2 独立数据根中；启动 6.7.0 时不要把这些路径配置为它的数据目录，也不要将其中数据库复制覆盖 V1。若无法确认 V1 数据位置，先不要启动旧版。
5. **启动并核验。** 启动 AstrBot，确认加载日志和插件信息显示 6.7.0，再检查原账号、人格、主要用户、记忆和回复。旧拓展若在交接时停用，按原备份恢复其配置与状态。确认回退有效前，继续保留 V1 原始数据和 7.0.0 现场副本。

V1 配置/资料迁移的来源按只读方式读取，正常覆盖安装的新运行数据与 V1 原数据分开保存；但升级后产生的新资料不会自动写回 6.7.0。回退只恢复旧版可读的旧配置和数据，7.0.0 新增内容留在封存副本中，需要时再从新版导出或人工整理，不能直接交给旧版数据库读取。

7.0.0 发布前置：将 `astrbot_plugin_private_companion-6.7.0-rollback.zip` 作为 7.0.0 发布附件提供，并确认用户可以下载。该包来自正式 `v6.7.0` 标签（提交 `f2f87183993a0667800056f73bcf12df298cdbcb`），SHA-256：`C8812D861942D0274E74D48A383EFD330537E7155C787D30D33220075A050CEA`；只含插件代码，不含配置、用户数据或运行数据库。

## 首次安装

1. 在 AstrBot 中准备可用的 `aiocqhttp` 平台、聊天模型和人格，再安装发布的 7.0.0 版本。
2. 打开插件扩展页「陪伴小屋」，进入「开始使用」，按引导确认账号、角色、管理员及聊天对象。
3. 在「模型与连接」选择后台任务所需模型，在「自我」补充角色资料。普通对话继续使用 AstrBot 当前会话的模型与回复设置。
4. 先确认普通对话、角色状态和资料保存正常，再按需开启主动联系、语音、生图及其他能力。需要外部服务的功能，须先配置服务参数和权限。

需要调整绑定时进入「账号与会话」；需要备份或恢复时进入「资料与维护 → 备份与还原」。

## 核心能力

| 方向 | 主要能力 |
| --- | --- |
| 对话陪伴 | 私聊、获准群聊、多账号与多人格；沿用 AstrBot 模型、历史、工具、流式输出和发送设置 |
| 角色生活 | 状态、睡眠与疲倦、日程、位置、天气、日记、成长和生活事件 |
| 关系与记忆 | 熟人卡、用户／群聊关系、世界知识、来源记忆、经历检索、反思与修订 |
| 主动联系 | 结合角色生活、近期对话和关系形成联系候选，检查时机、频率、权限及投递结果 |
| 表达与学习 | 回复风格、分段、TTS、表情，以及表达学习和群聊行为模仿 |
| 运行诊断 | Token 与缓存观测、缓存异常、近期回复效率、模型任务及发送记录 |

普通回复由 AstrBot 主链生成和发送，**不计入插件后台任务预算**。后台维护、主动联系及独立能力按对应模型与预算设置运行。插件预算与模型服务商的账户余额分别管理，诊断页面按实际观测展示。

以下七项能力随插件提供，在陪伴小屋首页的家具目录查看状态、进入配置并分别启停：

| 内置能力 | 用途 |
| --- | --- |
| 内容创作（Content） | 作品、创作任务与内容管理 |
| 生图（Image） | 文生图、改图及对应模型路线、参数和优先级 |
| 识屏（Screen） | 在授权范围内获取屏幕等设备上下文 |
| 现实触及（Reality） | 按配置接入摄像头及其他现实设备与服务 |
| 一起陪伴（Together） | 共同活动与实时陪伴相关能力 |
| 游戏（Game） | 游戏互动及相关角色体验 |
| 直播（Live） | 直播事件与相关互动能力 |

外部模型、设备及第三方服务仍需满足各自的连接和授权条件；安装插件本身不会让这些服务自动就绪。

## 聊天功能指令

私聊和群聊保留了常用的功能指令入口。命令经 AstrBot 普通回复主链处理，并在本轮授权工具可用时实际调用对应 V2 服务；普通回复仍使用 AstrBot 当前会话模型，不计入插件后台任务预算。

| 指令 | 用途 |
| --- | --- |
| `陪伴 帮助` | 查看当前可用的功能指令与管理入口 |
| `陪伴 状态` | 查看本轮可用的角色状态、睡眠与生活信息 |
| `陪伴 能力列表`、`陪伴 主动判定` | 查看本轮可用能力，或检查主动联系的当前证据 |
| `陪伴 日程`、`陪伴 查看日程` | 查询当前角色日历；可在指令后补充查询线索 |
| `生成日程`、`刷新日程`、`重新生成日程` | 生成或刷新今日自动计划；仅在已授权私聊中生效 |
| `陪伴 日记`、`陪伴 梦境` | 查询本轮工具可提供的角色历史摘要；工具不提供的旧正文不会被补写 |
| `陪伴 记忆 <线索>`、`陪伴 长期记忆 <线索>`、`陪伴 片段 <线索>` | 按线索查询当前角色可访问的记忆、旧版归档或共同经历 |
| `陪伴 画像` | 查询当前私聊对象在该角色下的熟人资料 |
| `陪伴 答疑 <问题>` | 使用当前可用的诊断说明与运行检查回答问题 |
| `陪伴画图 <描述>`、`陪伴合照 <修改要求>` | 使用当前会话授权的生图或改图工具；生成图片会按回执投递 |
| `陪伴群 状态`、`陪伴群 话题` | 根据当前群聊可见上下文作答 |
| `陪伴群 黑话 <词>`、`陪伴群 片段 <线索>` | 查询本群可访问的黑话释义或群聊记忆 |

普通工具操作受当前角色、用户／群聊授权和已配置能力影响；没有对应工具时会说明不可用。旧版的 HDSI、答疑确认/取消/设置、重要日期、未完话头删除、群 LLM 开关、撤回管理、衣柜、表达学习和主动路由语法会识别并给出 V7 对应入口；这些语法不代表旧数据副作用已原样兼容。涉及配置、授权、清空与重置的操作仍须在「陪伴小屋」对应页面完成。

## 配置与权限

### 先配置角色，再细调用户与群聊

- **安装与连接设置**维护账号、服务连接和运行条件，不随当前打开的聊天窗口变化。
- **角色默认设置**维护角色自己的状态、日程、资料和行为偏好，作为该角色的共同基础。
- **用户／群聊设置**只覆盖对应对象的回复、主动联系或其他可细调项目；在关系网中进入相应用户／群聊页调整。

持久化角色状态跟随角色，熟人卡在该角色下归属对应用户。角色自身的生活状态与用户事实分别记录，群聊也不会因此获得成员的私聊资料。

### 管理员隐私与共享

屏幕、麦克风、摄像头等隐私能力按管理员授权及当前设备权限生效。管理员可以通过配置共享指定能力，但角色默认设置、用户身份或旧版迁移记录本身都不代表共享授权。

真实外部动作仍需通过对应权限与发送检查。结果未知的投递不会自动重放；页面会区分未发送、已确认和结果未知。

## 排障

先查看 AstrBot 日志，再打开「陪伴小屋 → 治理与维护」。反馈问题时提供插件版本、发生时间、相关页面或功能、复现步骤及脱敏日志。

| 现象 | 优先检查 |
| --- | --- |
| 升级后设置或资料看起来缺失 | 「旧版资料迁入」中的配置交接、资料类别、目标映射及剩余项；两类完成状态需分别核对 |
| 更新或重载后配置不见了 | 「账号与会话」中的运行状态、保存结果、当前角色及实际数据根；先保留现场和日志 |
| 普通私聊或群聊没有回复 | AstrBot 核心消息日志、平台连接、角色绑定和对应用户／群聊权限 |
| 主动联系没有发出 | 「主动与联系」的开关、时段、免打扰、用户覆盖、候选拦截原因和投递结果 |
| TTS 或表情没有触发 | 「表达」中的输出设置、语音服务、可用素材、当前会话策略和发送记录 |
| 生图无法使用 | 对应功能的模型连接、路线顺序、参数、参考图，以及服务端返回的错误 |
| 后台维护提示预算不足 | 插件后台预算、实际任务路由和错误码；同时区分服务商余额或限流错误 |
| 回复变慢或缓存命中异常 | 「治理与维护」中的近期回复效率、Token／缓存诊断及同期 AstrBot 日志 |

近期回复效率展示单次回复总耗时和可观测阶段，便于区分准备、上下文与插件处理、模型生成及发送过程。Token、缓存和回执仅展示宿主或插件实际提供的数据；未提供的数据会保留未知状态。

## 开发者想说的话

### 发版狂魔也是发到4.0了，遂决定写点什么

以下保留旧版 README 中开发者对这款插件的想法：

- 你好，我要一个有记忆、有生活、有自己的小秘密和想法、有喜怒哀乐和健康的bot。
- 这得装不少插件，先生。
- 我知道，再让它们之间能够互相影响。
- 怎么让bot更像人？在此之前已经有很多优秀的插件给出了自己的答卷，各类心理学应用、人格特质、复杂的理论……
- 虽然开发者自身也是应用心理学专业毕业，但我觉得bot拟人只需要做好一件事，像人一样活着。听上去像是废话，但我做的只是进行自我观察。我的一天中，我会做什么，bot也应该会做什么。
- 对于一个拟人的bot而言，用户又何尝不是一个聊天bot？所以它应该会在自己的世界里生活，在生活里获取想和用户说话的“想法”，再在生活的空隙里把想法变为行动。
- 于是用户不止可以看到bot的早安和晚安，还能看到bot因为偶尔向窗外一瞥而专门为你记录下的照片、能看到bot因为好奇而自己私下搜索你在意的东西、能看到bot因为你昨天的提议而安排好周末的约会……
- 在没和你聊天时，它可能在上学、在刷视频、在看报纸、在水群，甚至在偷看你的屏幕或者遵循世界观正在某个奇异世界中一边刷怪练级，一边想着等闲下来该和你分享点什么。
- 它会记得你，不只是你，还有哪些在私聊/群聊中的人，会记得他们的名字、他们的行为、他们的习惯、他们的联系，哪怕他们改了名字和头像，甚至在其他平台再次相遇。
- 它会看、会说、会创作、会成长、会睡觉、会做梦、会生情绪、会饿，也会在授权范围内整理本地资料。
- 这就是它，这就是我，若它足够像我，它便成了我。

这些是持续打磨的产品方向。设备访问、跨平台身份关联与外部动作，仍以实际能力和授权范围为准。
